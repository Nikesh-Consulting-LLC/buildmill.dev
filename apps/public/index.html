What it is

A factory, not a free-for-all

AI coding agents are fast. Unsupervised, that speed is a liability: a wall of unreviewed diffs, changes nobody asked for, and no record of who decided what.

Build Mill puts the agents inside a factory. Work is typed and written down first — features get a PRD, stories get acceptance criteria. Plans are approved before code. Every change arrives as a pull request you review. Shipping is a release you sign off — never a side effect of a merge.

Your repo stays yours: GitHub remains the source of truth for code, and the factory records everything else — every run, every decision, every dollar.

The agent proposes.
The manager decides.

Work starts as words

A feature begins as a PRD you approve; stories carry acceptance criteria. The story is the single source of truth for the work.

Every gate is yours

Plan approval, PR review, release sign-off — three explicit decisions, each recorded. Rejections carry your comment into the retry.

Two systems of record

GitHub holds the code — branches, PRs, CI. The factory holds the work — items, runs, gates, costs — queryable, never reconstructed.

How it works

One story, start to shipped

Follow a single user story through the mill. Three of these steps are yours — they're the green ones.

1

You write the story

A user story with acceptance criteria — or a feature, which starts as a PRD and splits into stories once you approve it. Bugs and chores skip the ceremony.

2

An agent plans it

Dispatch is two-phase. First a plan run: the agent reads your repo and writes an implementation plan and a test plan. No code yet.

3

You approve the plan your gate

Before a line is written, you've seen how it will be written. Send it back and the retry carries your feedback — the next attempt is informed, not blind.

4

The agent builds it

It claims the work, checks out your repo, implements the approved plan, runs your project's gates, and pushes a branch. The factory opens the pull request.

5

You review and merge your gate

The diff and the original story sit side by side, gate results inline. Approve merges. Send back returns it with your comment attached to the next run.

6

A release is cut

Pinned to a commit and versioned by date. An agent writes the release notes from the real commit range and deploys that exact build to UAT — every release, no exceptions.

7

You sign off, and promote your gate

The release carries its test cases; a human runs them. Sign-off unlocks only when UAT deployed and every case passed — then promotion ships the same pinned build to production. Never a rebuild, never automatic.

Features

Everything between the idea and the deploy

The parts of shipping that usually live in someone's head, made explicit — and auditable.

Typed work items

Features, bugs, chores, stories. A feature gets a PRD before any engineering, splits into stories, and completes itself when the last one merges.

Plans before code

Every item is dispatched twice: a plan run you approve, then a code run that implements exactly that plan. Surprises get caught while they're still words.

Any agent can work

The autonomous runner grinds through the queue; your own IDE agent connects over MCP and claims the same work. First come, first served, under lease.

Releases that don't drift

A release pins a commit, goes to UAT first, and is immutable — if UAT fails, it's rejected and superseded. A version name means one build, forever.

Everything measured

Every run records its seconds, lines, tokens, and dollars — rolled up per agent, per item, per day. Every gate decision lands in an audit trail.

Your keys stay yours

Coding-agent credentials never leave your machine — the cloud can't touch your repo on its own. Cloud-side LLM keys are write-only; the UI sees four characters, ever.

And it's still just git

Build Mill isn't a walled garden. The factory exposes a real git remote — clone it with whatever you already use and work side by side with the agents, in the same repo, on the same queue. Push your branch and the factory opens the pull request itself.

  • Any client that speaks git. Terminal, VS Code, JetBrains — if it can clone and push, it can work the factory.
  • No GitHub credentials on your machine. Your factory token is the password; the org's real GitHub credential is attached server-side and never reaches you.
  • Your AI coding tools plug in too. Claude Code — or any agent that speaks MCP — connects to the factory, claims work from the same queue, and hands its branch back like any other worker.
  • The guardrails hold for humans too. The remote polices every push — your claimed branch, forward-only, no history rewrites — unless you've been explicitly granted more.
