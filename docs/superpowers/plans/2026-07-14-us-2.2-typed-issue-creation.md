# US-2.2 — Typed issue creation & triage — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give every issue a user-chosen type (`feature` | `bug` | `chore` | `story`) that drives type-appropriate create/edit fields, type-appropriate detail rendering, board/list filtering, distinct badge iconography, a `bug` default at GitHub import, and a `type-changed` event — with `type` locked server-side once the issue leaves `draft`.

**Architecture:** The `issues.type` column and the `TypeBadge` shell already exist from us-2.1; this story adds the *behavior* around them. Type-specific fields are not new columns — they are markdown sections composed into / parsed out of the existing `issues.body` by a pure module (`apps/web/src/lib/issue-body.ts`), so the schema stays flat and downstream artifact generators (us-2.3/us-2.5) read one field. All issue CRUD stays on the Supabase JS SDK under RLS ("build less API"); migration `032` adds a `guard_issue_type_change` trigger so the draft-only rule is enforced in Postgres rather than trusted from the browser; the only API change is the `bug` default in the GitHub issue pull (`apps/api/app/routers/github.py`), which is orchestration and already lives there.

**Tech Stack:** Next.js 16 (App Router, React 19), TypeScript strict, Tailwind v4, shadcn/ui on **Base UI** (not Radix), Supabase (Postgres + RLS + Realtime) project `wdudmfhhqxrqzoyhuzwx`, FastAPI (Python 3.12) + pytest, lucide-react icons, react-markdown.

**Format contract (round-trips):** each present, non-empty section is emitted as `## <heading>` then a blank line then the trimmed text; sections are joined by a blank line. Example for `bug`:
```
## Repro steps

1. Open /reports
2. Click Export

## Expected behavior

A CSV downloads.
```
`parseIssueBody` splits on `## <heading>` lines for the headings of the given type; any text before the first recognised heading is assigned to that type's **first** section (this is how a us-2.1-era untyped/unheaded `body`, and a GitHub-imported body, degrade gracefully rather than being lost).

```ts
import type { IssueType } from "@/components/type-badge";

export type IssueSectionKey = "description" | "story" | "repro" | "expected";

export const SECTION_HEADINGS: Record<IssueSectionKey, string> = {
  description: "Description",
  story: "Story",
  repro: "Repro steps",
  expected: "Expected behavior",
};

export const SECTION_PLACEHOLDERS: Record<IssueSectionKey, string> = {
  description: "The raw idea, in your own words. Markdown supported.",
  story: "As a user, I can… so that…\n\nMarkdown supported.",
  repro: "1. Go to…\n2. Click…\n3. See the error",
  expected: "What should have happened instead.",
};

export const SECTIONS_BY_TYPE: Record<IssueType, readonly IssueSectionKey[]> = {
  feature: ["description"],
  bug: ["repro", "expected"],
  chore: ["description"],
  story: ["story"],
};

export const REQUIRED_SECTIONS_BY_TYPE: Record<
  IssueType,
  readonly IssueSectionKey[]
> = {
  feature: [],
  bug: ["repro", "expected"],
  chore: [],
  story: [],
};

export const TYPES_WITH_CRITERIA: readonly IssueType[] = [
  "feature",
  "bug",
  "story",
];

export function showsCriteria(type: IssueType): boolean {
  return TYPES_WITH_CRITERIA.includes(type);
}

export type IssueSections = Partial<Record<IssueSectionKey, string>>;

export function composeIssueBody(
  type: IssueType,
  sections: IssueSections
): string {
  return SECTIONS_BY_TYPE[type]
    .map((key) => {
      const text = (sections[key] ?? "").trim();
      return text ? `## ${SECTION_HEADINGS[key]}\n\n${text}` : "";
    })
    .filter(Boolean)
    .join("\n\n");
}

export function parseIssueBody(
  type: IssueType,
  body: string | null
): IssueSections {
  const keys = SECTIONS_BY_TYPE[type];
  const text = (body ?? "").trim();
  if (!text) return {};

  // Index every recognised heading for this type, in the order it appears.
  const hits: { key: IssueSectionKey; start: number; end: number }[] = [];
  for (const key of keys) {
    const re = new RegExp(`^##[ \\t]+${escapeRegExp(SECTION_HEADINGS[key])}[ \\t]*$`, "m");
    const m = re.exec(text);
    if (m) hits.push({ key, start: m.index, end: m.index + m[0].length });
  }
  hits.sort((a, b) => a.start - b.start);

  const out: IssueSections = {};
  if (!hits.length || hits[0].start > 0) {
    // Legacy / imported body with no headings (or a preamble): everything up
    // to the first heading belongs to this type's first section.
    const preamble = text.slice(0, hits.length ? hits[0].start : text.length).trim();
    if (preamble) out[keys[0]] = preamble;
  }
  hits.forEach((hit, i) => {
    const stop = i + 1 < hits.length ? hits[i + 1].start : text.length;
    const value = text.slice(hit.end, stop).trim();
    if (value) out[hit.key] = out[hit.key] ? `${out[hit.key]}\n\n${value}` : value;
  });
  return out;
}

function escapeRegExp(s: string): string {
  return s.replace(/[.*+?^${}()|[\]\\]/g, "\\$&");
}
```

```sql
-- 032_issue_type_guard: an issue's type is the branching point of the whole
-- Phase-2 hierarchy (feature → PRD → stories; bug/chore → straight to plan),
-- so it may only be changed while the issue is still a draft (US-2.2).
-- Issue CRUD goes browser → PostgREST under RLS, so this rule has to live in
-- Postgres to actually be a rule.

create or replace function public.guard_issue_type_change()
returns trigger
language plpgsql
as $$
begin
  if new.type is distinct from old.type and old.status <> 'draft' then
    raise exception 'Issue type can only be changed while the issue is a draft.';
  end if;
  return new;
end;
$$;

create trigger issues_guard_type_change
  before update of type on public.issues
  for each row execute function public.guard_issue_type_change();

revoke execute on function public.guard_issue_type_change() from public, anon, authenticated;
```

```tsx
} from "@/lib/issue-body";

export type IssueFormData = {
  id: string;
  title: string;
  body: string | null;
  acceptance_criteria: string[];
  status: string;
  type: IssueType;
};

export function IssueDialog({
  orgId,
  projectId,
  issue,
}: {
  orgId: string;
  projectId: string;
  issue?: IssueFormData;
}) {
  const router = useRouter();
  const isEdit = !!issue;
  const initialType: IssueType = issue?.type ?? "feature";
  // Type is the branching point of the hierarchy — draft-only, and the DB
  // trigger from migration 032 enforces it regardless of what we render.
  const typeLocked = isEdit && issue.status !== "draft";

  const [open, setOpen] = useState(false);
  const [title, setTitle] = useState(issue?.title ?? "");
  const [type, setType] = useState<IssueType>(initialType);
  const [sections, setSections] = useState<IssueSections>(
    parseIssueBody(initialType, issue?.body ?? null)
  );
  const [criteria, setCriteria] = useState<string[]>(
    issue?.acceptance_criteria?.length ? issue.acceptance_criteria : [""]
  );
  const [saving, setSaving] = useState(false);
  const [error, setError] = useState<string | null>(null);

  function setSection(key: IssueSectionKey, value: string) {
    setSections((prev) => ({ ...prev, [key]: value }));
  }

  function changeType(next: IssueType) {
    // Re-parse the *current* text under the new type's headings so switching
    // feature → bug keeps what was typed instead of dropping it on the floor.
    const carried = composeIssueBody(type, sections);
    setType(next);
    setSections(parseIssueBody(next, carried));
  }

  function setCriterion(i: number, value: string) {
    setCriteria((prev) => prev.map((c, idx) => (idx === i ? value : c)));
  }

  function removeCriterion(i: number) {
    setCriteria((prev) =>
      prev.length > 1 ? prev.filter((_, idx) => idx !== i) : prev
    );
  }

  async function handleSave(e: React.FormEvent) {
    e.preventDefault();
    setError(null);

    const withCriteria = showsCriteria(type);
    const cleanCriteria = withCriteria
      ? criteria.map((c) => c.trim()).filter(Boolean)
      : [];

    if (!title.trim()) {
      setError("Title is required.");
      return;
    }
    for (const key of REQUIRED_SECTIONS_BY_TYPE[type]) {
      if (!(sections[key] ?? "").trim()) {
        setError(`${SECTION_HEADINGS[key]} is required for a ${type}.`);
        return;
      }
    }

    setSaving(true);
    const supabase = createClient();
    try {
      const values = {
        title: title.trim(),
        type,
        body: composeIssueBody(type, sections) || null,
        acceptance_criteria: cleanCriteria,
      };

      let issueId = issue?.id;
      if (isEdit) {
        const { error: dbError } = await supabase
          .from("issues")
          .update(values)
          .eq("id", issue.id);
        if (dbError) {
          setError(dbError.message);
          return;
        }
      } else {
        const { data, error: dbError } = await supabase
          .from("issues")
          .insert({ ...values, org_id: orgId, project_id: projectId })
          .select("id")
          .single();
        if (dbError) {
          setError(dbError.message);
          return;
        }
        issueId = data.id;
      }

      await supabase.from("issue_events").insert({
        org_id: orgId,
        issue_id: issueId!,
        type: isEdit ? "updated" : "created",
        payload: { title: values.title, issue_type: type },
      });

      if (isEdit && issue.type !== type) {
        await supabase.from("issue_events").insert({
          org_id: orgId,
          issue_id: issueId!,
          type: "type-changed",
          payload: { from: issue.type, to: type },
        });
      }

      setOpen(false);
      if (!isEdit) {
        setTitle("");
        setType("feature");
        setSections({});
        setCriteria([""]);
      }
      router.refresh();
    } finally {
      setSaving(false);
    }
  }

  return (
    <Dialog open={open} onOpenChange={setOpen}>
      <DialogTrigger
        render={isEdit ? <Button variant="outline" size="sm" /> : <Button />}
      >
        {isEdit ? (
          <>
            <Pencil className="size-4" />
            Edit
          </>
        ) : (
          <>
            <Plus className="size-4" />
            New issue
          </>
        )}
      </DialogTrigger>
      <DialogContent className="max-h-[85vh] overflow-y-auto sm:max-w-lg">
        <DialogHeader>
          <DialogTitle>{isEdit ? "Edit issue" : "New issue"}</DialogTitle>
          <DialogDescription>
            Pick a type — it decides what this issue needs and what the factory
            builds from it.
          </DialogDescription>
        </DialogHeader>
        <form onSubmit={handleSave} className="grid gap-4">
          <div className="grid gap-2">
            <Label htmlFor="issue-type">Type</Label>
            {typeLocked ? (
              <div className="flex items-center gap-2">
                <TypeBadge type={type} />
                <p className="text-xs text-muted-foreground">
                  Type is locked once the issue leaves draft.
                </p>
              </div>
            ) : (
              <Select
                items={ISSUE_TYPES.map((t) => ({
                  value: t,
                  label: ISSUE_TYPE_LABELS[t],
                }))}
                value={type}
                onValueChange={(v) => {
                  if (typeof v === "string") changeType(v as IssueType);
                }}
              >
                <SelectTrigger id="issue-type" className="w-full">
                  <SelectValue />
                </SelectTrigger>
                <SelectContent>
                  {ISSUE_TYPES.map((t) => (
                    <SelectItem key={t} value={t}>
                      {ISSUE_TYPE_LABELS[t]}
                    </SelectItem>
                  ))}
                </SelectContent>
              </Select>
            )}
          </div>

          <div className="grid gap-2">
            <Label htmlFor="issue-title">Title</Label>
            <Input
              id="issue-title"
              placeholder="Add CSV export to the report page"
              value={title}
              onChange={(e) => setTitle(e.target.value)}
            />
          </div>

          {SECTIONS_BY_TYPE[type].map((key) => (
            <div key={key} className="grid gap-2">
              <Label htmlFor={`issue-${key}`}>
                {SECTION_HEADINGS[key]}
                {REQUIRED_SECTIONS_BY_TYPE[type].includes(key) && (
                  <span className="text-destructive"> *</span>
                )}
              </Label>
              <Textarea
                id={`issue-${key}`}
                rows={key === "expected" ? 3 : 5}
                placeholder={SECTION_PLACEHOLDERS[key]}
                value={sections[key] ?? ""}
                onChange={(e) => setSection(key, e.target.value)}
              />
            </div>
          ))}

          {showsCriteria(type) && (
            <div className="grid gap-2">
              <Label>Acceptance criteria</Label>
              {criteria.map((c, i) => (
                <div key={i} className="flex items-center gap-2">
                  <Input
                    placeholder={`Criterion ${i + 1}`}
                    value={c}
                    onChange={(e) => setCriterion(i, e.target.value)}
                  />
                  <Button
                    type="button"
                    variant="ghost"
                    size="icon"
                    aria-label="Remove criterion"
                    onClick={() => removeCriterion(i)}
                    disabled={criteria.length === 1}
                  >
                    <X className="size-4" />
                  </Button>
                </div>
              ))}
              <Button
                type="button"
                variant="outline"
                size="sm"
                className="w-fit"
                onClick={() => setCriteria((prev) => [...prev, ""])}
              >
                <Plus className="size-4" />
                Add criterion
              </Button>
            </div>
          )}

          {error && (
            <p className="text-sm font-medium text-destructive">{error}</p>
          )}
          <DialogFooter>
            <Button type="submit" disabled={saving}>
              {saving && <Loader2 className="size-4 animate-spin" />}
              {isEdit ? "Save changes" : "Create issue"}
            </Button>
          </DialogFooter>
        </form>
      </DialogContent>
    </Dialog>
  );
}
```
      **Behavior note vs us-2.1:** acceptance criteria are no longer unconditionally required (a `chore` has none and a `feature`'s are optional per the story); the required fields are now title plus the type's required sections. This is the story's intent, not a regression.
