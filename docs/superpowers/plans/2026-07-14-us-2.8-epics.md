**Goal:** Ship epic CRUD, an Epics section on the project, an epic detail rollup view, and an optional epic selector on the issue form — all directly through the Supabase JS SDK under RLS, with `epic-assigned` / `epic-removed` events and a delete that un-assigns members instead of deleting them.

**Architecture:** The `epics` table and `issues.epic_id` already exist from [us-2.1](../../../stories/us-2.1-issues-replace-tasks.md), so this story is almost entirely `apps/web`: server components read epics + their member issues via the SSR Supabase client, client components mutate via the browser SDK exactly like `project-actions.tsx` and the guidelines sections do. ### Task 1: Migration 038 — epic delete un-assigns members

AC 5 ("Deleting an epic un-assigns its members (issues are never deleted with it)") is a **database** guarantee, not a UI one — it must hold even if the delete comes from psql. us-2.1 declares `issues.epic_id` only as "nullable → epics" and never states an on-delete action, so it inherits Postgres' default `no action`: deleting an epic with members raises a foreign-key violation instead of un-assigning them. us-2.1 also uses the composite `(id, org_id)` FK pattern from migration 020, which makes the fix subtle: a bare `on delete set null` would try to null `org_id` too, and `org_id` is `not null`. Postgres 15+ column-list syntax — `on delete set null (epic_id)` — nulls only the epic column. This migration replaces the constraint and adds the `epic_id` index us-2.1 omitted.

**Files:**
- Create: `infra/supabase/migrations/038_epic_unassign_on_delete.sql`
- Modify: `apps/web/src/lib/supabase/database.types.ts` (regenerated, not hand-edited)
- Modify: `stories/us-2.1-issues-replace-tasks.md` (correct the FK declaration at its source)
- Test: SQL assertions run via Supabase MCP `execute_sql` (no pytest — see Global Constraint 1)

**Interfaces:**
- Consumes: `public.epics (id, org_id)`, `public.issues (id, org_id, epic_id)` from us-2.1's migration `031`; `public.is_org_member(uuid)` from migration `014`.
- Produces:
  - Constraint `issues_epic_fk` on `public.issues`: `foreign key (epic_id, org_id) references public.epics (id, org_id) on delete set null (epic_id)` — i.e. `pg_constraint.confdeltype = 'n'`.
  - Index `issues_epic_idx` on `public.issues (epic_id) where epic_id is not null`.

  ```sql
  --
  -- Deleting an epic must un-assign its issues, never delete them. Migration
  -- 031 (US-2.1) created issues.epic_id with the composite (id, org_id) FK
  -- pattern from 020 but left the on-delete action at the default NO ACTION,
  -- so deleting an epic with members raises a FK violation instead.
  --
  -- The composite key is why this needs the Postgres 15+ column-list form:
  -- a bare ON DELETE SET NULL would null org_id too, and org_id is NOT NULL.
  -- ON DELETE SET NULL (epic_id) nulls only the epic column and leaves the
  -- org scoping — and therefore the RLS predicate — intact.

  alter table public.issues
    drop constraint if exists issues_epic_fk;

  alter table public.issues
    add constraint issues_epic_fk
    foreign key (epic_id, org_id)
    references public.epics (id, org_id)
    on delete set null (epic_id);

  -- issues by epic_id, and the FK's own delete-time lookup needs it too.
  create index if not exists issues_epic_idx
    on public.issues (epic_id)
    where epic_id is not null;
  ```

  ```ts
  import type { IssueStatus } from "@/components/status-badge";

  export type EpicStatus = "open" | "completed";

  export type EpicIssueType = "feature" | "bug" | "chore" | "story";

  export type EpicRow = {
    id: string;
    project_id: string;
    title: string;
    description: string | null;
    status: EpicStatus;
    created_at: string;
    updated_at: string;
  };

  export type EpicMemberIssue = {
    id: string;
    title: string;
    type: EpicIssueType;
    status: IssueStatus;
    parent_id: string | null;
    abandoned_at: string | null;
  };

  export type EpicRollup = {
    /** Non-abandoned members only — AC 4 ignores abandoned issues. */
    total: number;
    done: number;
    abandoned: number;
    byType: Record<EpicIssueType, number>;
    percent: number;
    readyToComplete: boolean;
  };

  export type EpicFeatureGroup = {
    feature: EpicMemberIssue;
    children: EpicMemberIssue[];
  };

  export type EpicGrouping = {
    features: EpicFeatureGroup[];
    others: EpicMemberIssue[];
  };

  /**
   * US-2.8 AC 4: an issue counts as done at `merged` or `done`. Abandoned
   * issues are not terminal — they are excluded from the rollup entirely by
   * rollupEpicIssues, so they neither block nor satisfy the nudge.
   */
  const TERMINAL_STATUSES: ReadonlySet<string> = new Set(["merged", "done"]);

  export function isIssueTerminal(issue: Pick<EpicMemberIssue, "status">): boolean {
    return TERMINAL_STATUSES.has(issue.status);
  }

  const EMPTY_TYPE_COUNTS = (): Record<EpicIssueType, number> => ({
    feature: 0,
    bug: 0,
    chore: 0,
    story: 0,
  });

  export function rollupEpicIssues(issues: EpicMemberIssue[]): EpicRollup {
    const counted = issues.filter((i) => !i.abandoned_at);
    const byType = EMPTY_TYPE_COUNTS();
    let done = 0;
    for (const issue of counted) {
      byType[issue.type] += 1;
      if (isIssueTerminal(issue)) done += 1;
    }
    const total = counted.length;
    return {
      total,
      done,
      abandoned: issues.length - counted.length,
      byType,
      percent: total === 0 ? 0 : Math.round((done / total) * 100),
      // An empty epic is never "ready to complete" — there is nothing to finish.
      readyToComplete: total > 0 && done === total,
    };
  }

  export function formatEpicProgress(rollup: EpicRollup): string {
    if (rollup.total === 0) return "No issues assigned";
    return `${rollup.done} of ${rollup.total} ${
      rollup.total === 1 ? "issue" : "issues"
    } done`;
  }

  const TYPE_LABELS: Record<EpicIssueType, [string, string]> = {
    feature: ["feature", "features"],
    bug: ["bug", "bugs"],
    chore: ["chore", "chores"],
    story: ["story", "stories"],
  };

  const TYPE_ORDER: EpicIssueType[] = ["feature", "story", "bug", "chore"];

  export function formatEpicTypeCounts(rollup: EpicRollup): string {
    const parts = TYPE_ORDER.filter((t) => rollup.byType[t] > 0).map((t) => {
      const n = rollup.byType[t];
      return `${n} ${TYPE_LABELS[t][n === 1 ? 0 : 1]}`;
    });
    return parts.join(" · ");
  }

  /**
   * AC 3: features carry their child stories nested underneath, then bugs and
   * chores. A story whose parent feature is not in this epic has no nest to
   * sit in, so it falls through to `others` rather than disappearing.
   */
  export function groupEpicIssues(issues: EpicMemberIssue[]): EpicGrouping {
    const features = issues
      .filter((i) => i.type === "feature")
      .map((feature) => ({
        feature,
        children: issues.filter(
          (i) => i.type === "story" && i.parent_id === feature.id
        ),
      }));

    const nestedIds = new Set(
      features.flatMap((g) => g.children.map((c) => c.id))
    );

    const others = issues.filter(
      (i) => i.type !== "feature" && !nestedIds.has(i.id)
    );

    const otherOrder: EpicIssueType[] = ["bug", "chore", "story"];
    others.sort((a, b) => otherOrder.indexOf(a.type) - otherOrder.indexOf(b.type));

    return { features, others };
  }
  ```

  ```tsx
  import { useState } from "react";
  import { useRouter } from "next/navigation";
  import { CheckCircle2, Loader2, RotateCcw, Trash2 } from "lucide-react";
  import { createClient } from "@/lib/supabase/client";
  import type { EpicStatus } from "@/lib/epics";
  import { Button } from "@/components/ui/button";
  import { ConfirmDialog } from "@/components/confirm-dialog";

  export function EpicActions({
    orgId,
    epicId,
    projectId,
    title,
    status,
    memberCount,
    redirectOnDelete = false,
  }: {
    orgId: string;
    epicId: string;
    projectId: string;
    title: string;
    status: EpicStatus;
    memberCount: number;
    redirectOnDelete?: boolean;
  }) {
    const router = useRouter();
    const [toggling, setToggling] = useState(false);
    const [error, setError] = useState<string | null>(null);

    // AC 4: completing an epic is always a manual action. The rollup only ever
    // nudges — it never flips the status on its own.
    async function toggleStatus() {
      setError(null);
      setToggling(true);
      const supabase = createClient();
      try {
        const { error: dbError } = await supabase
          .from("epics")
          .update({ status: status === "open" ? "completed" : "open" })
          .eq("id", epicId);
        if (dbError) {
          setError(dbError.message);
          return;
        }
        router.refresh();
      } finally {
        setToggling(false);
      }
    }

    // AC 5: the epic goes, its issues stay. The FK does the un-assigning
    // (migration 038: ON DELETE SET NULL (epic_id)); we capture the member ids
    // first so we can write one epic-removed event per issue afterwards. Events
    // are written after the delete succeeds so a failed delete leaves none.
    async function handleDelete() {
      const supabase = createClient();

      const { data: members, error: membersError } = await supabase
        .from("issues")
        .select("id")
        .eq("epic_id", epicId);
      if (membersError) throw new Error(membersError.message);

      const { error: deleteError } = await supabase
        .from("epics")
        .delete()
        .eq("id", epicId);
      if (deleteError) throw new Error(deleteError.message);

      if (members?.length) {
        const { error: eventsError } = await supabase.from("issue_events").insert(
          members.map((m) => ({
            org_id: orgId,
            issue_id: m.id,
            type: "epic-removed",
            payload: { epic_id: epicId, epic_title: title, reason: "epic-deleted" },
          }))
        );
        // The epic is already gone and the issues are already un-assigned —
        // a failed event write is a logging gap, not a failed delete, so it
        // must not surface as "delete failed".
        if (eventsError) console.error("epic-removed events failed", eventsError);
      }

      if (redirectOnDelete) {
        router.push(`/projects/${projectId}`);
      } else {
        router.refresh();
      }
    }

    return (
      <div className="flex flex-col items-end gap-2">
        <div className="flex shrink-0 items-center gap-2">
          <Button
            variant="outline"
            size="sm"
            onClick={toggleStatus}
            disabled={toggling}
          >
            {toggling ? (
              <Loader2 className="size-4 animate-spin" />
            ) : status === "open" ? (
              <CheckCircle2 className="size-4" />
            ) : (
              <RotateCcw className="size-4" />
            )}
            {status === "open" ? "Complete epic" : "Reopen epic"}
          </Button>
          <ConfirmDialog
            trigger={
              <Button variant="outline" size="sm">
                <Trash2 className="size-4" />
                Delete
              </Button>
            }
            title={`Delete "${title}"?`}
            description={
              memberCount === 0
                ? "This epic has no issues assigned. Deleting it can't be undone."
                : `${memberCount} ${
                    memberCount === 1 ? "issue" : "issues"
                  } will be un-assigned from this epic. The ${
                    memberCount === 1 ? "issue is" : "issues are"
                  } not deleted — only the epic is. This can't be undone.`
            }
            confirmLabel="Delete epic"
            onConfirm={handleDelete}
          />
        </div>
        {error && (
          <p className="text-sm font-medium text-destructive">{error}</p>
        )}
      </div>
    );
  }
  ```
