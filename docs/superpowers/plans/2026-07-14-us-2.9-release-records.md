# US-2.9 — Release records — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn each merged change into a durable, per-issue **release record** that tracks its journey after the merge — deployed to which environment when, QA signed off, approved for production — with the sign-off and promotion decisions landing in the [us-2.7](../../../stories/us-2.7-approval-log-audit.md) approval log.

**Architecture:** Migration `039` classifies deployments into the [us-1.16](../../../stories/completed/us-1.16-test-case-management.md) environment vocabulary (`deployments.environment`, nullable), adds `release_records` (one per merged code run, created by the [us-1.12](../../../stories/completed/us-1.12-approve-and-merge-pr.md) approve/merge flow in `apps/api/app/routers/reviews.py`) and the append-only `release_record_events`. When a deployment run succeeds on an environment-classified deployment, `apps/api/app/deploy.py` re-uses the [us-1.48](../../../stories/completed/us-1.48-task-deploy-traceability.md) commit-ancestry match (`github.compare_commits(merge_sha, payload_sha)`) to stamp a dated `deployed` event on every record the payload contains — strictly best-effort, after the run has already been marked succeeded and notified. QA sign-off and promotion approval are two SECURITY INVOKER Postgres functions that write an `approvals` row and a record event in one transaction, called from the browser via `supabase.rpc()`; everything else is plain SDK reads under RLS.

**Tech Stack:** Postgres 17.6 / Supabase project `Software-Factory` (`wdudmfhhqxrqzoyhuzwx`) with RLS + PL/pgSQL functions; FastAPI + psycopg (service-role pipeline writes) + httpx PostgREST client for the merge-time record; Next.js 16 App Router + Supabase JS SDK + Base UI (`@base-ui/react`) components; pytest (monkeypatched, no live DB) for the API contract.

Create `infra/supabase/migrations/039_release_records.sql`:

```sql
-- 039_release_records: the post-merge journey of a merged change (US-2.9).
--
-- A release record is created at merge time by the US-1.12 approve/merge
-- flow and then accumulates append-only events as its merge commit reaches
-- environments (deployed), passes UAT (qa-signoff) and is cleared for prod
-- (promotion-approved).
--
-- The record NEVER triggers a deploy. Deploys stay the manual US-1.32 flow;
-- the record only observes what happened and records what was decided.
--
-- deployments.environment classifies a deployment into the US-1.16
-- environment vocabulary. It is nullable on purpose: an unclassified
-- deployment simply never feeds release records.
--
-- Cross-org integrity uses the composite (id, org_id) FK pattern of
-- migrations 020/021 — a plain FK would let a row in one org reference
-- another org's ids, because FK validation bypasses RLS.

alter table public.deployments
  add column environment text
    check (environment in ('dev', 'uat', 'production'));

-- Composite-FK targets. us-2.1 (031) may already have added these; adding a
-- duplicate constraint is a hard error, so guard rather than assume.
do $$
begin
  if not exists (
    select 1 from pg_constraint where conname = 'issues_id_org_unique'
  ) then
    alter table public.issues
      add constraint issues_id_org_unique unique (id, org_id);
  end if;
  if not exists (
    select 1 from pg_constraint where conname = 'runs_id_org_unique'
  ) then
    alter table public.runs
      add constraint runs_id_org_unique unique (id, org_id);
  end if;
end $$;

create table public.release_records (
  id uuid primary key default gen_random_uuid(),
  org_id uuid not null references public.organizations(id) on delete cascade,
  issue_id uuid not null,
  run_id uuid not null,
  merge_commit_sha text not null,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  unique (id, org_id),
  -- One record per merged code run. A rejected-then-redispatched issue that
  -- merges a second run gets a second record on the same issue — which is
  -- correct: that is a second change with its own journey.
  unique (run_id),
  foreign key (issue_id, org_id)
    references public.issues (id, org_id) on delete cascade,
  foreign key (run_id, org_id)
    references public.runs (id, org_id) on delete cascade
);

create index release_records_org_idx on public.release_records (org_id);
create index release_records_issue_idx
  on public.release_records (issue_id, created_at desc);
create index release_records_sha_idx
  on public.release_records (merge_commit_sha);

alter table public.release_records enable row level security;

create policy "members manage their org release records"
  on public.release_records for all
  using (public.is_org_member(org_id))
  with check (public.is_org_member(org_id));

create trigger release_records_touch
  before update on public.release_records
  for each row execute function public.touch_updated_at();

-- Append-only (select + insert policies only, no update, no delete).
create table public.release_record_events (
  id bigint generated always as identity primary key,
  org_id uuid not null references public.organizations(id) on delete cascade,
  record_id uuid not null,
  environment text not null
    check (environment in ('dev', 'uat', 'production')),
  kind text not null
    check (kind in ('deployed', 'qa-signoff', 'promotion-approved')),
  deployment_run_id uuid,
  actor uuid references auth.users(id),
  actor_email text not null default '',
  comment text not null default '',
  created_at timestamptz not null default now(),
  constraint release_record_events_record_fkey
    foreign key (record_id, org_id)
      references public.release_records (id, org_id) on delete cascade,
  -- Deleting a deployment cascades to its runs (021). The record must keep
  -- the FACT that it was deployed; it only loses the run link. The PG15+
  -- column-list form nulls just the run id, leaving org_id intact.
  constraint release_record_events_run_fkey
    foreign key (deployment_run_id, org_id)
      references public.deployment_runs (id, org_id)
      on delete set null (deployment_run_id)
);

create index release_record_events_record_idx
  on public.release_record_events (record_id, created_at);
create index release_record_events_org_idx
  on public.release_record_events (org_id);

-- Idempotency for the best-effort matcher: re-running it for the same run
-- can never double-stamp a record.
create unique index release_record_events_deployed_unique
  on public.release_record_events (record_id, deployment_run_id)
  where kind = 'deployed';

alter table public.release_record_events enable row level security;

create policy "members read their org release record events"
  on public.release_record_events for select
  using (public.is_org_member(org_id));

create policy "members add their org release record events"
  on public.release_record_events for insert
  with check (public.is_org_member(org_id));

-- QA sign-off on one environment (US-2.9). One transaction writes both the
-- decision (approval log, US-2.7 renders it with no changes there) and the
-- record's timeline event. SECURITY INVOKER: authorization is RLS — a
-- non-member cannot see the record at all ("release record not found").
create or replace function public.release_qa_signoff(
  p_record uuid,
  p_environment text,
  p_comment text default ''
)
returns bigint
language plpgsql
security invoker
set search_path = public
as $$
declare
  v_org uuid;
  v_issue uuid;
  v_comment text := coalesce(nullif(btrim(p_comment), ''), '');
  v_event bigint;
begin
  if p_environment not in ('dev', 'uat', 'production') then
    raise exception 'unknown environment "%"', p_environment;
  end if;

  select org_id, issue_id into v_org, v_issue
  from public.release_records
  where id = p_record;

  if v_org is null then
    raise exception 'release record not found';
  end if;

  insert into public.approvals
    (org_id, issue_id, gate, subject_type, subject_id, decision, comment, actor)
  values
    (v_org, v_issue, 'qa-signoff', 'release_record', p_record, 'approved',
     v_comment, auth.uid());

  insert into public.release_record_events
    (org_id, record_id, environment, kind, actor, actor_email, comment)
  values
    (v_org, p_record, p_environment, 'qa-signoff', auth.uid(),
     coalesce(auth.jwt() ->> 'email', ''), v_comment)
  returning id into v_event;

  return v_event;
end;
$$;

revoke execute on function public.release_qa_signoff(uuid, text, text)
  from public, anon;
grant execute on function public.release_qa_signoff(uuid, text, text)
  to authenticated;

-- Approve for production (US-2.9). Records the decision ONLY — it does not
-- deploy anything. The subsequent prod `deployed` event arrives from the
-- manual deploy flow like any other.
create or replace function public.release_approve_promotion(
  p_record uuid,
  p_comment text default ''
)
returns bigint
language plpgsql
security invoker
set search_path = public
as $$
declare
  v_org uuid;
  v_issue uuid;
  v_comment text := coalesce(nullif(btrim(p_comment), ''), '');
  v_event bigint;
begin
  select org_id, issue_id into v_org, v_issue
  from public.release_records
  where id = p_record;

  if v_org is null then
    raise exception 'release record not found';
  end if;

  insert into public.approvals
    (org_id, issue_id, gate, subject_type, subject_id, decision, comment, actor)
  values
    (v_org, v_issue, 'promotion', 'release_record', p_record, 'approved',
     v_comment, auth.uid());

  insert into public.release_record_events
    (org_id, record_id, environment, kind, actor, actor_email, comment)
  values
    (v_org, p_record, 'production', 'promotion-approved', auth.uid(),
     coalesce(auth.jwt() ->> 'email', ''), v_comment)
  returning id into v_event;

  return v_event;
end;
$$;

revoke execute on function public.release_approve_promotion(uuid, text)
  from public, anon;
grant execute on function public.release_approve_promotion(uuid, text)
  to authenticated;
```

-- A release_records row whose org_id does not match its issue's org_id must
-- be impossible. Uses two real orgs if they exist; otherwise reports skip.
do $$
declare
  v_org_a uuid;
  v_org_b uuid;
  v_issue_a uuid;
  v_run_a uuid;
begin
  select id into v_org_a from public.organizations order by created_at limit 1;
  select id into v_org_b from public.organizations
    where id <> v_org_a order by created_at limit 1;
  select id, org_id into v_issue_a, v_org_a from public.issues limit 1;
  select id into v_run_a from public.runs where org_id = v_org_a limit 1;

  if v_org_b is null or v_issue_a is null or v_run_a is null then
    raise notice 'SKIP: need two orgs plus an issue and a run to prove this';

async def _create_release_record(
    settings: Settings,
    user_token: str,
    org_id: str,
    issue_id: str,
    run_id: str,
    merge_sha: str,
) -> bool:
    """US-2.9: the merge is what starts a release record.

    Best-effort by construction: the PR is already merged by the time this
    runs, so a bookkeeping failure must never turn a successful merge into
    an error response. Returns True when the row was inserted.
    """
    try:
        await postgrest_post(
            settings,
            user_token,
            "release_records",
            {
                "org_id": org_id,
                "issue_id": issue_id,
                "run_id": run_id,
                "merge_commit_sha": merge_sha,
            },
        )
        return True
    except Exception as e:  # noqa: BLE001 — the merge already succeeded
        logger.warning(
            "Could not create a release record for run %s: %s", run_id, e
        )
        return False

def list_release_record_candidates(
    settings: Settings, project_id: str, environment: str
) -> list[dict[str, Any]]:
    """US-2.9: this project's release records with no `deployed` event yet
    for this environment — the only records a run could newly stamp."""
    with _connect(settings) as conn:
        rows = conn.execute(
            """
            select rr.id, rr.org_id, rr.merge_commit_sha
            from public.release_records rr
            join public.issues i on i.id = rr.issue_id
            where i.project_id = %s
              and not exists (
                select 1 from public.release_record_events e
                where e.record_id = rr.id
                  and e.kind = 'deployed'
                  and e.environment = %s
              )
            order by rr.created_at
            """,
            (project_id, environment),
        ).fetchall()
    return [
        {
            "id": str(r["id"]),
            "org_id": str(r["org_id"]),
            "merge_commit_sha": r["merge_commit_sha"],
        }
        for r in rows
    ]


def insert_deployed_event(
    settings: Settings,
    org_id: str,
    record_id: str,
    environment: str,
    deployment_run_id: str,
) -> None:
    """US-2.9: stamp a dated `deployed` event on a release record. The
    partial unique index makes a repeat a no-op, not a duplicate."""
    with _connect(settings) as conn:
        conn.execute(
            """
            insert into public.release_record_events
              (org_id, record_id, environment, kind, deployment_run_id,
               actor_email)
            values (%s, %s, %s, 'deployed', %s, 'api (deployment run)')
            on conflict do nothing
            """,
            (org_id, record_id, environment, deployment_run_id),
        )
        conn.commit()


async def record_deployed_events(settings: Settings, ctx: dict[str, Any]) -> int:
    """US-2.9: a succeeded run on an environment-classified deployment stamps
    a `deployed` event on every release record whose merge commit the shipped
    payload contains — the US-1.48 ancestry match, inverted.

    BEST-EFFORT BY CONTRACT: this function never raises. A deploy that
    worked must never be failed, blocked, or delayed by bookkeeping. Every
    failure is logged and yields a lower count, never an exception.
    """
    try:
        deployment = ctx["deployment"]
        environment = deployment.get("environment")
        if not environment:
            return 0  # unclassified deployments never feed release records
        if ctx.get("source") == "zip":
            return 0  # a zip payload has no commit ancestry to match
        run = await asyncio.to_thread(get_run, settings, ctx["run_id"])
        commit_sha = (run or {}).get("commit_sha")
        if not commit_sha:
            return 0
        candidates = await asyncio.to_thread(
            list_release_record_candidates,
            settings,
            str(deployment["project_id"]),
            environment,
        )
        if not candidates:
            return 0

        owner, repo = (ctx.get("repo_full_name") or "/").split("/", 1)
        installation_id = await asyncio.to_thread(
            _org_installation_id, settings, ctx["org_id"]
        )
        token = await github.mint_installation_token(settings, installation_id)

        stamped = 0
        for record in candidates:
            try:
                cmp = await github.compare_commits(
                    token, owner, repo, record["merge_commit_sha"], str(commit_sha)
                )
            except Exception as e:  # noqa: BLE001 — one bad record, not the batch
                _log.warning(
                    "Release-record match skipped for record %s: %s",
                    record["id"],
                    e,
                )
                continue
            # The payload contains the merge commit when the merge commit is
            # the payload's commit or an ancestor of it.
            if cmp.get("status") not in ("identical", "ahead"):
                continue
            await asyncio.to_thread(
                insert_deployed_event,
                settings,
                record["org_id"],
                record["id"],
                environment,
                ctx["run_id"],
            )
            stamped += 1
        return stamped
    except Exception as e:  # noqa: BLE001 — a deploy that worked never fails here
        _log.warning(
            "Release-record matching failed for run %s: %s", ctx.get("run_id"), e
        )
        return 0

/** QA sign-off on one environment — writes approvals (gate 'qa-signoff')

  records,

  projectId: string;
  records: ReleaseRecordWithEvents[];

                          className="text-xs font-normal underline-offset-4 hover:underline"

                          deployment

                      {r.issues?.title ?? "Issue"}
                    </Link>
                  </TableCell>
                  <TableCell className="whitespace-nowrap text-xs text-muted-foreground">
                    <span className="font-mono">
                      {r.merge_commit_sha.slice(0, 7)}
                    </span>{" "}
                    · {formatDay(r.created_at)}
                  </TableCell>
                  {ENVIRONMENTS.map((env) => {
                    const deployed = r.release_record_events.find(
                      (e) => e.kind === "deployed" && e.environment === env
                    );
                    const signedOff = r.release_record_events.some(
                      (e) => e.kind === "qa-signoff" && e.environment === env
                    );
                    const promoted =
                      env === "production" &&
                      r.release_record_events.some(
                        (e) => e.kind === "promotion-approved"
                      );
                    return (
                      <TableCell key={env} className="whitespace-nowrap text-xs">
                        {deployed ? (
                          deployed.deployment_runs ? (
                            <Link
                              href={`/projects/${projectId}/deployments/${deployed.deployment_runs.deployment_id}`}
                              className="underline-offset-4 hover:underline"
                            >
                              {formatDay(deployed.created_at)}
                            </Link>
                          ) : (
                            formatDay(deployed.created_at)
                          )
                        ) : (
                          <span className="text-muted-foreground">—</span>
                        )}
                        <span className="ml-1.5 inline-flex items-center gap-1 align-middle">
                          {signedOff && (
                            <ShieldCheck
                              className="size-3.5 text-emerald-600"
                              aria-label={`QA signed off on ${env}`}
                            />
                          )}
                          {promoted && (
                            <Rocket
                              className="size-3.5 text-emerald-600"
                              aria-label="Approved for production"
                            />
                          )}
                        </span>
                      </TableCell>
                    );
                  })}
                </TableRow>
              ))}
            </TableBody>
          </Table>
        )}
      </CardContent>
    </Card>
  );
}
