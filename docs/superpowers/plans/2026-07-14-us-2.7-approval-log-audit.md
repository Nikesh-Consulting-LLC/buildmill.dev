# US-2.7 — Approval log timeline & audit view — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Surface the append-only `approvals` log as a chronological **Decisions** timeline on issue detail and a filterable project-level **Audit** table, both read directly from Postgres under RLS via the Supabase JS SDK.

**Architecture:** This is a surfacing story — a query, not a store. `approvals` already exists (created by [us-2.1](../../../stories/us-2.1-issues-replace-tasks.md)) and is already org-scoped with RLS on its own `org_id`, so **no migration and no FastAPI endpoint are added**. Both views are Next.js server components that `select` from `approvals` through the existing SSR Supabase client, hand plain row arrays to presentational components, and resolve `actor` UUIDs to display names through a shared helper. All gate-dependent rendering is derived from the row's own string (`humanizeToken`) or from the distinct gates present in the data — never from a hardcoded gate list — so `qa-signoff` and `promotion` render the day [us-2.9](../../../stories/us-2.9-release-records.md) starts writing them, with zero code changes.

**Tech Stack:** Next.js 16 App Router (server components), Supabase JS SDK under RLS, Base UI (shadcn) `Select`/`Table`/`Input`, Tailwind v4, TypeScript strict.

## Global Constraints

- **This plan assumes the [us-2.1](../../../stories/us-2.1-issues-replace-tasks.md) rename has already landed.** Every path here is post-rename: `apps/web/src/app/(app)/issues/[id]/page.tsx` (not `tasks/`), route `/issues/<id>`, `routers/issues.py`. Before starting Task 3, run `ls "apps/web/src/app/(app)/issues/[id]/page.tsx"` — if it does not exist, us-2.1 has not landed and this story is blocked.
- **No migration.** `approvals` (issue ref, `gate`, `subject_type`, `subject_id`, `decision`, `comment`, `actor`, `created_at`, `org_id`, select+insert policies only) ships with us-2.1's migration `031`. Do not write `037` or any migration. Do not regenerate `database.types.ts` — us-2.1 already did. If a migration ever *does* become necessary, stop and re-plan rather than improvising one.
- **No new API surface.** Per CLAUDE.md "Build less API": plain reads go through the Supabase JS SDK under RLS from `apps/web`. Do not add a router, endpoint, or RPC.
- **No hardcoded gate list in rendering (critical AC).** Gate labels come from `humanizeToken(row.gate)`; the Audit gate filter's options come from `new Set(rows.map(r => r.gate))`. A `switch` over `gate` anywhere is a bug. Task 5 proves this by inserting `qa-signoff` and `promotion` rows via SQL and confirming they render.
- **No test runner exists for `apps/web`.** `apps/web/package.json` has `dev`/`build`/`start`/`lint` only — no vitest, jest, or playwright. The only pytest suite is `apps/api` (`npm run test:api`), which cannot reach this frontend-only work and has no live DB. So steps here substitute **`npm run build` (includes the type check) + a scripted manual browser check** for the red/green test cycle, and verify DB behavior (RLS, forward-compat gates) with **direct SQL via the Supabase MCP `execute_sql`** against project `wdudmfhhqxrqzoyhuzwx`. This is the same substitution used by the us-1.24/us-1.25/us-1.26 plans in this folder. Do not scaffold a test framework this repo does not have.
- **shadcn here is Base UI, not Radix**: `render={<Button />}` not `asChild`; pass `items` to `Select.Root` so the trigger renders labels rather than raw values (verified against `node_modules/@base-ui/react/select/root/SelectRoot.d.ts`, which types `items?: ReadonlyArray<{ label: React.ReactNode; value: any }>`).
- **Use the shared UI primitives**: `StatusBadge` (`@/components/status-badge`) for decision pills and `EmptyState` (`@/components/empty-state`) for empty views. Do not invent a new badge or empty pattern.
- **`approvals.actor` cannot be PostgREST-embedded.** `actor` references `auth.users(id)` only. Per `infra/supabase/migrations/015_org_membership_visibility.sql`, PostgREST auto-embeds only across a *direct* FK between the two tables in the query, which is why `organization_members` needed a second FK to `public.profiles(id)`. `approvals` has no such FK, so `select("... , profiles(display_name)")` returns a PGRST200 relationship error. Resolve names with a **separate `profiles` query** (`.in("id", actorIds)`) — this needs no migration and works because 015's "org members can view teammates' profiles" policy already permits it.
- No comments in code unless explaining a genuinely non-obvious constraint.
- Do not mark the story `Completed` — only the user does that. Task 5 moves it to `Testing`.

```ts
import type { SupabaseClient } from "@supabase/supabase-js";

export type ApprovalRow = {
  id: string;
  gate: string;
  decision: string;
  subject_type: string | null;
  subject_id: string | null;
  comment: string | null;
  actor: string | null;
  created_at: string;
};

const ACRONYMS = new Set(["prd", "qa", "llm", "pr", "ci"]);

// Gate and decision labels are derived from the row's own string, never from a
// lookup of known gates: `qa-signoff` and `promotion` (US-2.9) must render with
// no code change the first time they appear.
export function humanizeToken(token: string): string {
  const words = token.split("-").filter(Boolean);
  if (words.length === 0) return token;
  const rendered = words.map((w) =>
    ACRONYMS.has(w.toLowerCase()) ? w.toUpperCase() : w.toLowerCase()
  );
  if (!ACRONYMS.has(words[0].toLowerCase())) {
    rendered[0] = rendered[0].charAt(0).toUpperCase() + rendered[0].slice(1);
  }
  return rendered.join(" ");
}

export function subjectHref(
  subjectType: string | null,
  subjectId: string | null,
  issueId: string
): string | null {
  if (!subjectType || !subjectId) return null;
  switch (subjectType) {
    case "run":
      return `/review/${issueId}`;
    case "artifact":
      return `/issues/${issueId}#artifact-${subjectId}`;
    default:
      return null;
  }
}

export function subjectLabel(
  subjectType: string | null,
  subjectId: string | null
): string | null {
  if (!subjectType || !subjectId) return null;
  return `${humanizeToken(subjectType)} ${subjectId.slice(0, 8)}`;
}

export function formatWhen(iso: string): string {
  return new Date(iso).toLocaleString(undefined, {
    month: "short",
    day: "numeric",
    hour: "2-digit",
    minute: "2-digit",
  });
}

// approvals.actor references auth.users(id) only, so PostgREST cannot embed
// profiles across it (see migration 015). A separate keyed read is the
// no-migration path, and 015's teammate-visibility policy already allows it.
export async function fetchActorNames(
  supabase: SupabaseClient,
  actorIds: (string | null)[]
): Promise<Record<string, string>> {
  const ids = Array.from(
    new Set(actorIds.filter((id): id is string => Boolean(id)))
  );
  if (ids.length === 0) return {};

  const { data } = await supabase
    .from("profiles")
    .select("id, email, display_name")
    .in("id", ids);

  const names: Record<string, string> = {};
  for (const p of data ?? []) {
    names[p.id] = p.display_name || p.email || p.id;
  }
  return names;
}
```

`subjectType === "release"` deliberately falls to `default` and returns `null`: release records do not exist until [us-2.9](../../../stories/us-2.9-release-records.md), so a `promotion` row renders its subject as plain text rather than a dead link — and starts linking only when us-2.9 adds the route and one `case`. The `#artifact-<id>` anchor is inert until [us-2.3](../../../stories/us-2.3-feature-prd.md) renders artifacts; the link still lands correctly on the issue page today.

```tsx
      ...Array.from(new Set(rows.map((r) => r.gate)))
        .sort()
        .map((g) => ({ label: humanizeToken(g), value: g })),
    ],
    [rows]
  );

  const decisionItems = useMemo<Option[]>(
    () => [
      { label: "All decisions", value: ANY },
      ...Array.from(new Set(rows.map((r) => r.decision)))
        .sort()
        .map((d) => ({ label: humanizeToken(d), value: d })),
    ],
    [rows]
  );

  const actorItems = useMemo<Option[]>(
    () => [
      { label: "All actors", value: ANY },
      ...Array.from(
        new Set(rows.map((r) => r.actor).filter((a): a is string => Boolean(a)))
      )
        .map((a) => ({ label: actorNames[a] ?? a, value: a }))
        .sort((x, y) => x.label.localeCompare(y.label)),
    ],
    [rows, actorNames]
  );

  const filtered = useMemo(() => {
    const fromMs = from ? new Date(`${from}T00:00:00`).getTime() : null;
    const toMs = to ? new Date(`${to}T23:59:59.999`).getTime() : null;
    return rows.filter((r) => {
      if (gate !== ANY && r.gate !== gate) return false;
      if (decision !== ANY && r.decision !== decision) return false;
      if (actor !== ANY && r.actor !== actor) return false;
      const ts = new Date(r.created_at).getTime();
      if (fromMs !== null && ts < fromMs) return false;
      if (toMs !== null && ts > toMs) return false;
      return true;
    });
  }, [rows, gate, decision, actor, from, to]);

  const isFiltered =
    gate !== ANY || decision !== ANY || actor !== ANY || from !== "" || to !== "";

  function clearFilters() {
    setGate(ANY);
    setDecision(ANY);
    setActor(ANY);
    setFrom("");
    setTo("");
  }

  return (
    <Card>
      <CardHeader>
        <CardTitle className="text-base">Audit</CardTitle>
        <CardDescription>
          Every gate decision across this project&apos;s issues — append-only, so
          &quot;why did we ship this&quot; stays answerable.
        </CardDescription>
      </CardHeader>
      <CardContent className="flex flex-col gap-4">
        <div className="flex flex-wrap items-end gap-3">
          <div className="grid gap-1.5">
            <Label className="text-xs text-muted-foreground">Gate</Label>
            <Select
              items={gateItems}
              value={gate}
              onValueChange={(v) => setGate(v)}
            >
              <SelectTrigger size="sm" className="w-40">
                <SelectValue />
              </SelectTrigger>
              <SelectContent>
                {gateItems.map((i) => (
                  <SelectItem key={i.value} value={i.value}>
                    {i.label}
                  </SelectItem>
                ))}
              </SelectContent>
            </Select>
          </div>

          <div className="grid gap-1.5">
            <Label className="text-xs text-muted-foreground">Decision</Label>
            <Select
              items={decisionItems}
              value={decision}
              onValueChange={(v) => setDecision(v)}
            >
              <SelectTrigger size="sm" className="w-40">
                <SelectValue />
              </SelectTrigger>
              <SelectContent>
                {decisionItems.map((i) => (
                  <SelectItem key={i.value} value={i.value}>
                    {i.label}
                  </SelectItem>
                ))}
              </SelectContent>
            </Select>
          </div>

          <div className="grid gap-1.5">
            <Label className="text-xs text-muted-foreground">Actor</Label>
            <Select
              items={actorItems}
              value={actor}
              onValueChange={(v) => setActor(v)}
            >
              <SelectTrigger size="sm" className="w-48">
                <SelectValue />
              </SelectTrigger>
              <SelectContent>
                {actorItems.map((i) => (
                  <SelectItem key={i.value} value={i.value}>
                    {i.label}
                  </SelectItem>
                ))}
              </SelectContent>
            </Select>
          </div>

          <div className="grid gap-1.5">
            <Label className="text-xs text-muted-foreground" htmlFor="audit-from">
              From
            </Label>
            <Input
              id="audit-from"
              type="date"
              value={from}
              onChange={(e) => setFrom(e.target.value)}
              className="w-36"
            />
          </div>

          <div className="grid gap-1.5">
            <Label className="text-xs text-muted-foreground" htmlFor="audit-to">
              To
            </Label>
            <Input
              id="audit-to"
              type="date"
              value={to}
              onChange={(e) => setTo(e.target.value)}
              className="w-36"
            />
          </div>

          {isFiltered && (
            <Button variant="ghost" size="sm" onClick={clearFilters}>
              Clear
            </Button>
          )}
        </div>

        {rows.length === 0 ? (
          <EmptyState
            icon={ScrollText}
            title="No decisions logged yet"
            description="Approvals, rejections, and overrides across this project's issues will show up here."
          />
        ) : filtered.length === 0 ? (
          <EmptyState
            icon={ScrollText}
            title="No matching decisions"
            description="No decisions match these filters. Try widening the gate, actor, or date range."
          />
        ) : (
          <>
            <Table>
              <TableHeader>
                <TableRow>
                  <TableHead>When</TableHead>
                  <TableHead>Issue</TableHead>
                  <TableHead>Gate</TableHead>
                  <TableHead>Decision</TableHead>
                  <TableHead>Actor</TableHead>
                  <TableHead className="whitespace-normal">Comment</TableHead>
                </TableRow>
              </TableHeader>
              <TableBody>
                {filtered.map((r) => (
                  <TableRow key={r.id}>
                    <TableCell className="text-muted-foreground">
                      {formatWhen(r.created_at)}
                    </TableCell>
                    <TableCell>
                      <Link
                        href={`/issues/${r.issue_id}`}
                        className="underline-offset-4 hover:underline"
                      >
                        {r.issue_title}
                      </Link>
                    </TableCell>
                    <TableCell>{humanizeToken(r.gate)}</TableCell>
                    <TableCell>
                      <StatusBadge status={r.decision as TaskStatus} />
                    </TableCell>
                    <TableCell>
                      {r.actor ? (actorNames[r.actor] ?? r.actor) : "—"}
                    </TableCell>
                    <TableCell className="max-w-sm truncate whitespace-normal text-muted-foreground">
                      {r.comment || "—"}
                    </TableCell>
                  </TableRow>
                ))}
              </TableBody>
            </Table>
            <p className="text-xs text-muted-foreground">
              {filtered.length} of {rows.length} decision
              {rows.length === 1 ? "" : "s"}
            </p>
          </>
        )}
      </CardContent>
    </Card>
  );
}
```
