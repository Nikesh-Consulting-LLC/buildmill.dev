# US-86.2 — In the factory shows the build, not its cargo

**Status:** Testing
**Phase:** 86 — Routing, simplified
**Depends on:** us-86.1 (the feature is the routing unit), migrations 138/139 (feature-owned code run, run_items), us-24.2 (factory-tab nesting)

## Story

As the manager, when a feature is in the factory as one coding unit, the
**In the factory** tab shows me the build: the feature's header row carries
the run's truth — a "Building" stage, the agent that claimed it, elapsed,
and heard — and the stories beneath it read as its cargo ("in this build"),
not as eleven independent "Running" rows with no agent, no elapsed, and no
heartbeat behind them (observed live on FEAT-2.8, 2026-08-13: eleven
Running pills with em-dashes while the actual run — one row, on the
feature, claimed by the interactive agent — was invisible).

## Acceptance criteria

- **AC1 — the header carries the run.** When a live run's issue is the
  feature heading a nested group, the header row shows a stage pill
  (Building / Queued), the claiming agent's name (linked to its profile
  when it has one), elapsed, and heard — sourced from the same liveness
  lookup the story rows already use, keyed by the feature's issue id.
- **AC2 — stories read as cargo.** Story rows nested under a feature whose
  run is live show "in this build" in the Stage column instead of a
  status pill, and no fake dashes pretending to be per-story telemetry.
- **AC3 — nothing else changes.** Features without a live feature-owned
  run render exactly as before; the tab count is untouched (presentation
  only); a story with its own run (story-mode projects) keeps its own
  stage, agent, elapsed, and heard.

## Out of scope

- The Queue details page (factory-queue) — same disease, separate surface;
  follow-up if the manager wants it there too.
- Per-story progress inside a feature build (run_items carry no per-story
  status today).
