# US-100.3 — The tabs say what they hold

**Status:** Testing
**Phase:** 100 — One document, not twenty-two sections
**Depends on:** us-100.1 (there is one document to name)

## Story

As the manager, the project's own settings mislabel both of the things this
phase is about. The tab called **Guidelines** holds the twenty-two-section
catalog. The tab called **Agent Instructions** holds the *per-task* worker
instructions — Plan, Code, RCA, Merge and the rest
([page.tsx](../apps/web/src/app/(app)/projects/[id]/page.tsx) L426-429).

So the name "Agent Instructions" is already taken, by the thing it does not
mean. Opening the tab I would go to for my project's instructions shows me a
list of per-run-kind editors, and the document I am looking for is under a
different word entirely. That is the "old style" I keep seeing.

Both names change to what they hold, and the same words are used wherever
these appear — project settings, templates, and the audit trail — so a
manager who learns them once can read every surface.

## Acceptance criteria

- **AC1 — Agent Instructions means the document.** The tab named **Agent
  Instructions** holds the single markdown document from us-100.1. The
  Guidelines tab is gone; nothing in the app calls the project's conventions
  "guidelines" any more.

- **AC2 — the per-task editor is renamed for what it steers.** The current
  worker-instructions editor gets a name that is not "Agent Instructions" —
  it holds one instruction per task (Plan, Code, RCA, Merge, Test, …) and
  should say so. The existing grouping and per-kind naming
  ([worker-instructions-tab.tsx](../apps/web/src/app/(app)/projects/[id]/worker-instructions-tab.tsx))
  is kept; only the label changes.

- **AC3 — one vocabulary everywhere.** The same two names are used in project
  settings, in the superadmin template editor, in the org template editor,
  and in `content_audit`'s labels
  ([content-audit-section.tsx](../apps/web/src/app/(app)/projects/[id]/content-audit-section.tsx)
  L51, which currently renders `worker_instructions` as "Agent instructions"
  — the same collision). A test pins that no surface uses the old words.

- **AC4 — deep links keep working.** The `?tab=guidelines` value is still
  honoured, redirecting to the renamed tab, so a bookmark or a link in a
  notification does not 404 into an empty page.

- **AC5 — the help text follows.** Wherever help copy explains guidelines
  sections ([help-content.ts](../apps/web/src/components/help/help-content.ts)
  L591, [help_content.py](../apps/api/app/help_content.py) L253), it is
  rewritten for one document — including the Versioning & Release reference,
  which no longer names a section.

- **AC6 — tests.** `npm run build` green; a test asserting the retired words
  appear on no surface.

## Verified (2026-08-15)

- **AC1/AC2 — the reported defect is fixed.** The tab holding the single
  document is now **Agent Instructions**; the per-kind editor is **Task
  Instructions**. Renaming the first without the second would have left two
  tabs claiming the same name, which is how the confusion started.
- **AC3 — one vocabulary.** `content-audit-section.tsx` used to render
  `worker_instructions` as "Agent instructions" — the same collision in a
  third place — and now matches. A test asserts neither surface still labels
  anything "Guidelines".
- **AC4 — deep links survive.** The tab *value* stays `guidelines`, so
  `?tab=guidelines` in a bookmark or notification still resolves; only the
  label changed. Pinned by a test, because renaming the value would have
  been the tempting tidy-up and would have broken every existing link.
- **Caught during the rename:** the two setup-checklist rows both read
  "Agent Instructions marked ready" once the first was renamed — one tracks
  `guidelines_ready_at`, the other `worker_instructions_ready_at`. The
  second now reads "Task Instructions marked ready".
- **4 tests** pinning the labels, the absence of the old words, the audit
  vocabulary, and the deep-link value.
- api Essential green (**1784 passed, 545 skipped, 0 failed**); `npm run
  build` green.

### Gaps

- **AC5 (help copy) is not done.** `help-content.ts` L194 still has an "Agent
  instructions" heading and the Versioning & Release help text still
  describes a section. Both are user-visible prose and should follow.
- The database columns keep their names (`guidelines_ready_at`,
  `instructions_synced_hash`), and the `guidelines` storage key is unchanged
  — deliberate, per this story's own out-of-scope list.

## Out of scope

- Any change to what the per-task editor *contains* — this is naming and
  placement only.
- The `guidelines` run kind's own name, which us-100.5 decides.
- Renaming database columns or the `input_context.guidelines` key; the
  vocabulary change is the manager's, not the wire format's.
