# US-91.19 — The workdesk is one page

**Status:** Completed
**Phase:** 91 — Usability: the dashboard reads like the job
**Depends on:** [us-91.1](us-91.1-the-tab-is-named-for-what-you-do-there.md), [us-91.2](us-91.2-dispatch-opens-with-what-is-already-running.md), [us-92.1](us-92.1-the-tabs-fit-the-phone.md) (the tab control this removes)

## Story

As the manager, Things to Do has four tabs and three of them are somewhere
else in the app:

| Tab | Already lives at |
|---|---|
| In the factory | `/factory-queue` — the queue in worker-pull order, reorderable and pausable |
| Completed | `/activity` — every finished run, with who ran it and what it cost |
| Releases | `/releases` — every build cut, and where each one got to |

So the page that should answer *"what needs me, and what is happening"*
spends three quarters of its surface restating pages that do the same job
better. The tabs themselves cost a control, a decision and — on a phone —
555px of bar (us-92.1). Removing them removes all of that.

What is left is what only this page does: **what an agent is holding right
now**, **what merged work is waiting on a release**, and **what needs a
decision from me**. One page, no facets.

And the name should say so. "Things to Do" describes a list; **Workdesk**
describes the place you work from, which is what it becomes once it stops
being a set of tabs.

## The one thing that must not be lost

"In the factory" was not purely duplicative: it showed **queued and held**
work — the 38 items nobody has claimed, and the ones no worker *can* claim.
In Progress deliberately shows only claimed runs (us-91.2 AC2), so deleting
the tab would make unclaimable work invisible on the page a manager opens to
find out why nothing is moving.

That is a condition, not a list, and it gets one line rather than a tab.

## Acceptance criteria

- **AC1 — one page, no tabs.** The tab control (bar and the us-92.1 phone
  select) is gone. The page renders, in order: the alerts strip, **In
  Progress**, the release suggestions (us-91.18), then the action list.
- **AC2 — the queue keeps a voice, and gets its own door.** Beneath In
  Progress, one line states what the factory holds but nobody is working:
  *"38 queued · 4 waiting on something"*, linking to `/factory-queue`. It
  renders only when there is something to say.
  **Extended after the manager's note:** Factory Queue also becomes a nav
  entry directly under Work Items, and the two facts the retired tab had
  that the queue page lacked move onto it — **elapsed** on a running row,
  and the **requeue** button when a worker has gone quiet. The queue page
  already carried the rest (state, hold reason, worker, activity, last
  heard, feature nesting, project grouping, reorder and pause), so pasting
  the tab's table there would have been the very duplication this story
  removes.
- **AC3 — nothing is orphaned.** Completed work is reachable from the page
  via a link to Activity, and releases via Release — the two nav entries
  already exist, so this is a sentence, not a section.
- **AC4 — the nav entry reads Workdesk**, and the page header with it. The
  route stays `/dashboard`: renaming it would break every link, bookmark and
  agent instruction for no gain.
- **AC5 — the page gets cheaper, not just shorter.** The queries that fed
  only the deleted tabs — the finished-run feed, the releases list and the
  in-flight deploy list — come out of the dashboard load. Deleting a tab
  while still paying for its data would be the worst of both (us-87.1).
- **AC6 — the tab URL degrades quietly.** A saved `/dashboard?tab=factory`
  link opens the workdesk rather than erroring; the parameter is ignored.
- **AC7 — the removed tables' code goes with them.** `FactoryTable`,
  `CompletedTable` and `ReleasesTable` are deleted rather than left unused —
  dead code that still compiles is the kind that gets edited by mistake.

## UAT feedback round (2026-08-14, the manager's notes)

Three amendments from using the page:

- **AC2 amended — the queue is a list, not a line.** The one-line summary
  hid the queue. The section now shows the first **five** queued items
  (type, id, title, project; a held row wears an amber "held" chip with
  US-39.4's reason on hover) and a button — "All N in Factory Queue" /
  "Open Factory Queue" — to the page that stays the authority on
  worker-pull order.
- **In Progress gains a working gear.** Each live row carries a small
  muted gear turning once every five seconds — a hum, not a siren. It
  stops turning when the worker has gone silent (the section already
  refuses to call silence work), and stands still entirely under
  `prefers-reduced-motion`.
- **AC4 overridden — the name is Workbench, route included.** AC4 kept
  `/dashboard` to protect links; the manager chose the clean rename. The
  route is now `/workbench`, the nav entry and header read **Workbench**,
  every internal reference moved (34 files), `?from=dashboard` still
  resolves for stale tabs, and `next.config` 301s `/dashboard` →
  `/workbench` with the query string intact — so what AC4 protected is
  protected by the redirect instead.

## Out of scope

- Changing `/factory-queue`, `/activity` or `/releases`. They keep every row
  they show today; this page stops copying them.
- The shell badge and its count, which already means "things waiting on you".
- Merging any of those pages into each other.

## Verified (2026-08-14, localhost)

- The nav reads **Workdesk · Work Items · Factory Queue · Testing · Release ·
  Activity · Bug Reports**; the page's `h1` is **Workdesk** and the route is
  still `/dashboard`.
- **Zero tab elements render.** The page is: alerts strip → In Progress →
  the queue line → release suggestions → the action list → the two links out.
- The queue line reads **"38 queued in the factory, unclaimed."** and opens
  Factory Queue, whose own back-link now says Workdesk.
- `FactoryTable`, `CompletedTable` and `ReleasesTable` are deleted, and with
  them the finished-run, releases and in-flight-deploy queries that fed only
  those tabs (AC5).
