# US-99.2 — AGENTS.md is the index, and Build Mill owns it whole

**Status:** New
**Phase:** 99 — The instructions live in the repo
**Depends on:** us-99.1 (the kind-to-file map exists)

## Story

As the manager, `AGENTS.md` today is a shared file: Build Mill owns a fenced
region inside it and `merge_block`
([repo_docs.py](../apps/api/app/repo_docs.py) L450) is careful to "never
touch a byte outside them". That shared ownership made sense when the block
held only assembled guidelines and a docs-tree pointer. It stops making
sense the moment `AGENTS.md` becomes the entry point to a set of files Build
Mill maintains — because then half a file being authoritative and half being
somebody else's notes is a question every agent has to answer for itself.

So Build Mill owns `AGENTS.md` outright. It is written whole on each publish:
the project's single instruction markdown, followed by a reference to every
`.buildmill/` file that exists and one line on which work each steers.
`CLAUDE.md` becomes, permanently, the `@AGENTS.md` pointer — the skeleton it
was always meant to be.

**This destroys hand-written `AGENTS.md` content on first publish.** That is
the accepted consequence of single ownership, and it is recorded here rather
than discovered by a customer. The mitigation is that the destruction is
visible: it happens inside a commit, on a branch with history, at a moment
the manager chose (us-99.4) rather than silently at dispatch.

## Acceptance criteria

- **AC1 — the instruction files are written.** Publishing writes
  `.buildmill/<File>.md` for every kind in the us-99.1 map whose resolved
  content is non-blank, each file being that kind's content and nothing else
  — no fences, no factory markers, no preamble. A kind whose content is
  blank writes no file, and an existing file for a kind that becomes blank is
  **deleted**, so the repository never carries an instruction the factory no
  longer believes in.

- **AC2 — `AGENTS.md` is the index, written whole.** `AGENTS.md` is
  generated in full from: the project's single instruction markdown, then a
  reference section listing every `.buildmill/` file that was written, each
  with the one-line "who receives this" the instruction editor already
  carries in `KIND_META`, then the docs-tree pointer when the tree is
  enabled. `BLOCK_START`/`BLOCK_END` and `merge_block` are retired for
  `AGENTS.md`; nothing outside is preserved, because there is no outside.

- **AC3 — a legacy file converts cleanly.** A repository whose `AGENTS.md`
  still carries the old fenced block — or the pre-22.6 legacy region
  `_strip_legacy_block` handles — converts to the new whole-file form on
  first publish without leaving markers, duplicated headings, or an orphaned
  block behind. Pinned by tests over real fixtures of both old shapes.

- **AC4 — `CLAUDE.md` is the pointer, always.** `CLAUDE.md` is written as
  `@AGENTS.md` unconditionally. The `_is_pointer_only`
  ([repo_docs.py](../apps/api/app/repo_docs.py) L463) preservation branch is
  retired along with it — a `CLAUDE.md` carrying other content is replaced,
  not merged.

- **AC5 — one writer.** Every path that writes instruction files goes
  through one function, the way `build_instruction_file_contents`
  ([repo_docs.py](../apps/api/app/repo_docs.py) L506) is today's single
  door — so a publish from the editor and a publish from project creation
  produce byte-identical files. The content assembly is **pure** and tested
  without GitHub, as `instruction_files` already is.

- **AC6 — the destruction is stated where a manager will see it.** The
  publish surface (us-99.4) says plainly that Build Mill owns `AGENTS.md`
  and `CLAUDE.md` and rewrites them whole. Not a warning dialog — a standing
  line of copy, because it is true every time.

- **AC7 — tests.** Essential, faked GitHub: the AC1 write and delete paths;
  AC2's index shape; AC3's two conversion fixtures; AC4's unconditional
  pointer; and AC5's identical-output assertion across both entry points.

## Out of scope

- **Asking before overwriting a foreign `AGENTS.md`.** Considered and
  declined: ownership is unconditional. AC6 makes it known instead.
- When a publish happens, and the uncommitted-changes warning — us-99.4.
- Where the project's conventions come from — us-99.3.
- The `docs/factory/` tree written by `sync_tree`
  ([repo_docs.py](../apps/api/app/repo_docs.py) L610). It keeps its current
  behavior and its own pointer in the index.
- Changing any instruction's text.
