# US-92.4 — A test case row says what it is

**Status:** New
**Phase:** 92 — The app on a phone
**Depends on:** [us-91.6](us-91.6-the-test-library-is-a-table-you-can-page.md) (the table this makes readable on a phone)

## Story

As the manager, the test library on a phone shows three usable columns —
**Test case, Source, Execution** — because Type & environment and Work item
are `lg:table-cell` and drop out below that. What is left cannot answer the
question the library is for: *which* case is this, and where does it apply.

The facts do survive, but crammed into the title cell's sub-line, so a row
reads:

> `A zero-byte file is rejected` `integration · api · negative · dev · File
> upload with drag-and-drop and per-file progress` `agent` `manual`

Four different kinds of fact — type, surface, sentiment, environment, and the
work item — run together in one grey sentence with nothing distinguishing
them, then `agent` and `manual` repeat in their own columns.

us-91.6 made this a table so the library could be scanned. On a phone a table
is the wrong instrument; the same information wants a card.

## Acceptance criteria

- **AC1 — one card per case below `md`.** Title first and unclipped over two
  lines if it needs them — the title is the identity of a test case and must
  never be the thing that truncates.
- **AC2 — the facts are separated, not concatenated.** Type and environment
  as the badges they already are (wrapping), execution as its badge with the
  suite name for an automated case, source as its icon. A reader must be able
  to tell at a glance which badge means what.
- **AC3 — the work item is named and links.** "Covers: US-2.1.1 File upload…"
  as its own line, linking to the item. It is the single most useful fact for
  deciding whether a case matters, and today it is buried mid-sentence.
- **AC4 — steps stay one tap away**, as the disclosure they became in
  us-91.6, and the expanded prose is readable at 375px rather than
  horizontally scrolling in its `<pre>`.
- **AC5 — the row's actions are reachable**: edit and abandon/restore at
  ≥40px, not `icon-sm` buttons at the edge of the screen.
- **AC6 — the filters follow us-92.2's shape.** Eight filter pills sit above
  this list too; below `md` they collapse into one **Filters** button with an
  active count, opening a sheet. The two pages should not solve the same
  problem two ways.
- **AC7 — paging survives.** The pager, the `N–M of T` count and the
  page-scoped selection behave exactly as on desktop; the mobile list pages
  ten at a time like the table.

## Out of scope

- The test **run** pages and their checklists.
- Bulk select and the Automate flow on mobile — they stay desktop
  affordances, and the bar simply does not render below `md`.
- Changing what a test case is, or which filters exist.
