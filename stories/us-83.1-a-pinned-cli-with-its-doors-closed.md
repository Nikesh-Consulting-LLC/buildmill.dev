# US-83.1 — A pinned CLI with its config doors closed

**Status:** Testing
**Phase:** 83 — Interactive agent stability
**Dependencies:** none (build first: every later story's probe measures the CLI this one pins)

## Story

As the operator of a pool fleet, I want the interactive agent's CLI version
pinned and its self-modifying defaults turned off, so that what a run measures
today is still true tomorrow and no workspace repo can silently reconfigure
the agent.

## Context

Measured against the real CLI (grok 1.0.0, `3cd0d0cbce`) and its documentation
(docs.x.ai/build/settings/reference), three defaults are wrong for a fleet:

1. **`[cli] auto_update` defaults ON**, and nothing disables it — not the slot
   env, not the config `write_model_config` writes, not the provisioner. The
   CLI can self-update in the background of any run. This project has been
   burned by CLI generation drift twice already (`grok.py`'s own docstring:
   1.0.0 → 1.1.7 removed flags and a subcommand mid-story). The docs provide
   `GROK_DISABLE_AUTOUPDATER` explicitly for CI/containers.
2. **`[compat.claude]` / `[compat.cursor]` default ON** — the CLI scans
   Claude/Cursor directories for skills, rules, agents, MCP servers and
   *hooks*. Factory workspaces are arbitrary project checkouts; a repo
   carrying `.claude/` or `.cursor/` config injects behavior the factory
   never granted, bypassing the tool-grant model (US-34.2). The factory's own
   repos carry `CLAUDE.md`/`.claude`, so this fires today.
3. **The install is unpinned** — `INTERACTIVE_CLI_INSTALL_CMD`
   (apps/api/app/agent_provision.py) curl-pipes `install.sh`, taking whatever
   is latest. `grok update --version <V>` exists for pinning.

Also carried here because it lives in the same config write: the custom model
block has no `context_window`, and the docs say auto-compact timing depends on
it — a BYOK entry without it cannot compact reliably on long runs. The
handshake confirms catalog models carry `totalContextTokens`; custom entries
only know what the config tells them.

## Acceptance criteria

1. The slot env file (US-78.1) for interactive agents carries
   `GROK_DISABLE_AUTOUPDATER=1`.
2. `write_model_config` (apps/runner/supervisor/modules/interactive.py) always
   writes the config file — `[cli] auto_update = false` plus `[compat.claude]`
   and `[compat.cursor]` with all scanning keys off — and includes the
   `[model.<id>]` block only when a model resolved. The delete-on-no-model
   behavior is replaced by this (a config without a model block kills stale
   model state the same way); the stale-model regression test is updated to
   assert the new shape, not deleted.
3. The provisioner pins the CLI: after the install script, run
   `<cli> update --version <PIN>` where `<PIN>` is a named constant beside
   `INTERACTIVE_CLI_INSTALL_CMD`; the provision verify step compares
   `buildmill-agent-cli version` output to the pin and fails loudly on
   mismatch (never "unknown-but-green").
4. When the gateway env includes the model's context window (server sends it
   alongside the mint for models it knows), the model block gains
   `context_window = <N>`. Absent knowledge writes nothing — never a guess.
5. Runner tests pin the config sections (auto_update off, compat off, model
   block presence rules, context_window passthrough).

## Out of scope

- Sandbox profiles (`GROK_SANDBOX`), web-fetch/memory/subagent toggles —
  policy decisions, separate story if wanted.
- Forking `xai-org/grok-build` (recorded Phase 78 known gap; unchanged here).
- Automatic version *upgrades* — re-pinning is a deliberate manual change to
  the constant.

## Verification (2026-08-12, built)

**Verified:** runner tests pin the hardening sections ([cli] auto_update off,
both [compat.*] fully off, in every write), the no-model overwrite path, and
the context-window rules (numeric env lands, absent/garbage writes nothing;
grok-4.5 → 500000 in both env builders). API tests pin
`GROK_DISABLE_AUTOUPDATER=1` in the slot env, the version in the install
command, and the provision gate (pin passes; mismatch and "unknown" both
raise). Full suites green: runner 286 passed, api Essential 1590 passed.

**Not verified (UAT):** a live provision on a pool machine — run Update on a
host and confirm the probe logs `grok 1.0.0` and the gate holds; `inspect`
on-machine showing compat scanning off.
