# US-103.4 — The Workbench shows the release in flight

**Status:** Testing
**Phase:** 103 — A release cannot get stuck
**Depends on:** us-103.3 (Stop), us-103.1 (the reaper), US-91.18 (`ReleaseSuggestions`), US-6.3/US-13.6 (run liveness on the Workbench), US-35.5 (stalled-queue reasoning)

## Story

As the manager, when a release is being prepared I want the Workbench — the
page I actually sit on — to show me the same truth it shows me about story
runs: who is doing it, how long they have been at it, whether they are still
breathing, and a way to stop them. On 2026-08-16 the Workbench told me
2026.08.16.3 was "being prepared" for two and a half hours after its
supervisor had ceased to exist.

That sentence was not a bug. It is the literal design: `FLIGHT_WORDS` maps
`releases.status` to prose
([release-suggestions.tsx:31](../apps/web/src/app/(app)/workbench/release-suggestions.tsx:31)),
and status was — correctly — `running`. What the card has no access to is
liveness. The Workbench's liveness pass reads `runs`
([data.ts:1240](../apps/web/src/app/(app)/workbench/data.ts:1240)) and computes
running minutes, silent minutes and a lapsed lease for every claim. Release
prep is not a `runs` row, so it gets none of that — the one job in the factory
that can hang unobserved is the one job with no observation.

## Design

### The same reading, from the other table

`release_prep_runs` carries `worker_id`, `claimed_at` and `claim_expires_at` —
everything the run liveness pass needs, under different table cover. So the
Workbench's release card gains the same four facts, computed the same way and
worded the same way, from the prep row for the in-flight release:

| fact | source |
|---|---|
| who holds it | `workers.name` via `worker_id`, linked to the agent's console |
| how long | `now() - claimed_at`, in minutes |
| silence | `now() - claim_expires_at + lease`, the same derivation the run pass uses when there is no `last_heartbeat_at` column |
| lapsed | `claim_expires_at < now()` |

`release_prep_runs` has no `last_heartbeat_at` — `heartbeat_release_prep`
pushes `claim_expires_at` forward instead. **Corrected during implementation:**
this story assumed that made silence merely approximable and planned to hedge
the wording. It does not. Every beat sets `claim_expires_at = now() + 2 hours`
with nothing else ever writing that column, so the last beat landed at exactly
`claim_expires_at - 2h` and silence is arithmetic, not a guess. The card
therefore states minutes, and `last_heartbeat_at` is not needed — no migration.

The runner beats every 20 seconds (`HEARTBEAT_SECONDS`), so twenty minutes of
silence is sixty missed beats: the same threshold the run liveness pass uses
for an autonomous worker, for the same reason.

### What the card says when it is wrong

A lapsed lease is the state that mattered on 2026-08-16 and the card says so
plainly — the release is not being prepared, it is abandoned, and here is
Stop. The three readings, in the card's own words:

- **working** — "prepared by <agent>, 12 min" — the ordinary case;
- **silent** — heard from over two hours ago, lease still valid — amber, "may
  have stopped";
- **abandoned** — lease lapsed — the same red the stalled-queue badge uses,
  naming that us-103.1's sweep will fail it, with **Stop** offered now.

Stop is us-103.3's endpoint, called from here, because this is where the
manager is standing when they find out.

### One card, not a new section

`ReleaseSuggestions` already renders the in-flight release with its version,
status, project and snapshotted items (the 2026-08-14 UAT amendment). This
story extends that card rather than adding furniture — the Workbench's own
rule from US-91.18, that a card never becomes wallpaper, is why the release
appears there only while something is true about it.

## Acceptance criteria

- **AC1 — the card carries liveness.** While a release is in flight, its
  Workbench card names the agent holding the prep (linked to that agent's
  console), how long it has been held, and one of the three readings above.
  A release at `queued` (no prep claimed yet) says it is waiting for an agent
  and how long it has waited.
- **AC2 — abandoned is unmistakable.** A lapsed lease renders in the
  established alarm treatment, states that the agent stopped reporting, and
  says what happens next (the sweep fails it) — not a spinner, not "being
  prepared".
- **AC3 — silence is derived, not guessed.** Silence is computed as
  `now - (claim_expires_at - lease)`, which is exact because the heartbeat is
  the only writer of that column. The derivation is a pure function with the
  lease and the silence threshold as named constants, and its boundaries are
  pinned by tests. No migration and no new column.
- **AC3b — an in-flight release is shown even when nothing new has merged.**
  The card's `if (!mine.length) continue` fired before the in-flight check, and
  2026.08.16.3 carried zero items — so the Workbench showed nothing at all for
  the very release that was stuck. The in-flight release is the card whether or
  not merged work sits behind it. The read also covers `notes-ready`,
  `deploying` and `uat-deploy-failed`, which were missing from the status
  filter entirely.
- **AC4 — Stop is on the card.** us-103.3's Stop is offered from the Workbench
  card for every state it accepts, with the same confirmation, and the card
  reflects the new state on refresh.
- **AC5 — the other in-flight states read true.** `deploying`, `uat-deployed`,
  `uat-signed-off` and `promoting` keep their existing plain-words line and
  gain no fake liveness — there is no agent holding those, and the card must
  not imply one. `uat-deploy-failed` says the deploy failed and offers Retry.
- **AC6 — the reads are org-scoped and cheap.** The prep/worker read is
  filtered by `org_id` (the US-9.7 lesson: RLS alone permits every org the
  manager belongs to) and adds at most one round trip to the Workbench load,
  inside us-87.10's page budget.
- **AC7 — tests.** Web: the liveness derivation is a pure function with a
  `.test.ts` covering working / silent / abandoned / queued-unclaimed, pinned
  against the boundary values. The card renders each reading.

## Out of scope

- The release freeze on dispatch and its explanation — us-103.5.
- Streaming the release agent's transcript into the Workbench (the console
  link is the route to it).
- Rebuilding release prep as a `runs` row to inherit the existing liveness
  pass. US-63.3 split it deliberately; this story borrows the reading, not the
  table.
- Liveness for deployment runs.
- Any change to what the card says about *unreleased merged work* (US-91.18's
  original purpose) — that half is untouched.

## Built (2026-08-16)

`release-liveness.ts` derives the four readings from `release_prep_runs`, with
`PREP_LEASE_MINUTES` and `PREP_SILENT_MINUTES` as named constants. `data.ts`
reads the prep rows org-scoped with a hinted embed
(`workers!release_prep_runs_worker_id_fkey`), and `release-suggestions.tsx`
renders the line, the agent linked to its console, and Stop.

Two bugs surfaced while building, both fixed here: the card's
`if (!mine.length) continue` fired **before** the in-flight check, so a
release carrying zero items - which 2026.08.16.3 did - produced no card at
all; and the status filter omitted `notes-ready`, `deploying` and
`uat-deploy-failed` entirely. AC3 was also corrected: silence is exactly
recoverable from the lease, not coarse, so no migration was needed.

**Verified.** `npm run test:web`: 197 passed, including ten new tests pinning
every reading and both boundaries - among them the 2026-08-16 numbers
themselves (claimed 13:36, lease expired 15:46, read 16:12 -> held 156 min,
silent 146 min, `abandoned`). `npm run build` compiles clean.

**Not verified - this is the story's main gap.** Nothing was rendered. No
browser, no screenshot, no page dump: without `apps/web/.env.local` the dev
server cannot authenticate against Supabase. The derivation is proven; the
card is not. Colours, layout, the console link resolving, the Stop button's
behaviour from the card, and the whole of AC1/AC2/AC4/AC5 as *visible things*
need the manager's eyes. AC6's page-load cost was reasoned (one added query,
org-filtered) but not measured.
