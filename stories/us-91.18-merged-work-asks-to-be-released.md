# US-91.18 — Merged work asks to be released

**Status:** New
**Phase:** 91 — Usability: the dashboard reads like the job
**Depends on:** [us-91.1](us-91.1-the-tab-is-named-for-what-you-do-there.md) (the tab it sits on)

## Story

As the manager, work that has merged is finished as far as the factory is
concerned — and invisible from then until I remember to cut a release. There
is no prompt. The Dispatch tab shows what needs a decision and what is
running; nothing says *"five things are built and sitting in the default
branch, unreleased since 2026.08.13.1."*

So merged work waits on me remembering, and the gap between "merged" and
"live" is the one stretch of the pipeline the dashboard says nothing about.

Cutting a release is one click from a page I am already on. It should be
offered where the work is, not looked up.

## What "eligible" means here

A release snapshots the items whose merge commit falls in the range since the
**last released** version — and `previous_release` is deliberately the last
one that actually *shipped*: a rejected or rolled-back release leaves its
commits unreleased, and they must be included again.

The card must not re-derive that. `GET /projects/{id}/releases/preview`
already computes it — pinned commit, proposed version, the item list and the
**blockers** (no UAT deployment designated, a release still in flight, no
repo, nothing merged). It answers from GitHub's compare API, so it is a
per-project network call and must not run on every dashboard load.

The card therefore makes a cheaper, weaker claim from the database alone —
items merged since the last shipped release — and the preview stays the
authority for what a cut would actually contain.

## Acceptance criteria

- **AC1 — one card per project with unreleased merged work**, at the top of
  the Dispatch tab, beneath In Progress. It names the project, the count, and
  the version it is measuring from: *"5 work items merged since 2026.08.13.1"*
  (or "since the project's first commit" when nothing has shipped yet).
- **AC2 — it names the items, not just a number.** Up to three rows — type
  badge, display id, title, each linking to the item — then "+ N more". A
  bare count cannot be checked, and the manager is being asked to ship these.
- **AC3 — one shortcut: Cut release.** It opens the existing cut dialog for
  that project, which runs the real preview and shows the proposed version,
  the pinned commit and the true item list. The card never cuts anything
  itself, and never proposes a version — the factory computes it.
- **AC4 — the card is a suggestion, and the dialog is the authority.** If the
  preview's item list differs from the card's count (a merge outside the
  range, a hand-merged commit with no run behind it), the dialog is right.
  Say so in the card's tooltip rather than letting two numbers argue.
- **AC5 — a project that cannot cut does not get asked.** No card while a
  release is in flight for that project, or when no UAT deployment is
  designated. Instead, when merged work exists and a **blocker** is the only
  thing stopping it, show the blocker once — *"5 items are waiting on a
  release; 2026.08.14.1 is still in UAT"* — with no button. An invitation
  that fails on click is worse than none.
- **AC6 — no card when there is nothing to release.** Zero merged-since rows,
  no card. It never becomes furniture.
- **AC7 — it costs one query.** Merged items per project since the last
  shipped release, resolved in the existing dashboard load — no GitHub call,
  no `preview` request per project, nothing that grows with release history
  (us-87.1, us-87.10).
- **AC8 — it obeys the tab's grouping.** Under project grouping (us-91.4) the
  card sits inside its project's group; ungrouped, it sits above the action
  rows.

## Out of scope

- Cutting automatically, or on a schedule. Releases stay manager-triggered
  (Versioning & Release), and this only makes the trigger easy to find.
- Changing the release lifecycle, the version scheme, or the blockers.
- Recommending a promotion to production, or a sign-off — the same argument
  applies to those gates and each deserves its own story once this one has
  proved the shape.
- Notifying outside the app about unreleased work.
