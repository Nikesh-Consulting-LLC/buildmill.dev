# US-100.2 — AGENTS.md is the Agent Instructions

**Status:** Completed
**Phase:** 100 — One document, not twenty-two sections
**Depends on:** us-100.1 (the document exists)

## Story

As the manager, `AGENTS.md` is currently a file Build Mill generates *about*
my instructions — an ownership notice, a pointer to `.buildmill/Guidelines.md`,
and a table of the per-task files. Everything I actually wrote lives one hop
away.

That indirection was right when the conventions were twenty-two assembled
sections. Once they are one document (us-100.1), it is just a redirect: the
file every agent and every repository-reading tool opens first says "the real
thing is over there".

So `AGENTS.md` **is** the Agent Instructions. My document is its body; the
generated references to the per-task files follow underneath.
`.buildmill/Guidelines.md` retires — shipped 2026-08-15 in us-99.3 and
superseded here, which is worth saying plainly rather than quietly deleting.

## Acceptance criteria

- **AC1 — the document is the body.** `build_agents_index` becomes: the
  project's Agent Instructions verbatim, then the ownership line, then the
  generated table of `.buildmill/*.md` references. A project that has written
  no Agent Instructions gets the ownership line and the table alone, and says
  so rather than emitting a stray heading.

- **AC2 — `Guidelines.md` retires, and is deleted from repositories that
  have it.** The path joins the publisher's delete set for one release, so a
  project that published under us-99.3 does not keep a stale conventions file
  that now disagrees with `AGENTS.md`. `CONVENTIONS_FILE` and its map entry
  go; `test_conventions_do_not_collide_with_any_kind` is rewritten rather
  than deleted, because the collision it guards is why
  `Guidelines_Refresh.md` has its name.

- **AC3 — one writer, still.** Both publish paths keep going through
  `instruction_file_plan`, and the test asserting they produce byte-identical
  files and delete sets keeps passing.

- **AC4 — the hash notices the move.** `publish_hash` already covers
  deletions, so the retirement of `Guidelines.md` registers as a change and
  the next publish actually removes it. Pinned by a test, because a deletion
  the hash cannot see is exactly the bug us-99.2's hash was introduced for.

- **AC5 — tests.** Essential, faked GitHub: AC1's body-then-references shape;
  the empty-document case; AC2's delete appearing in the plan; AC3's
  identical-writers assertion.

## Verified (2026-08-15)

- **AC1 — the document is the body.** `build_agents_index` now takes the
  conventions text (not a boolean) and emits it first, followed by a `---`
  rule, the ownership line, and the generated table of `.buildmill/*.md`
  references. Pinned: with a document, `AGENTS.md` starts with it; with none,
  the file opens on the ownership line rather than a horizontal rule over
  nothing — a real defect caught by smoke-testing the empty case.
- **AC2 — `Guidelines.md` retires and is deleted.** The path is added to the
  publisher's delete set **unconditionally**, so a project that published
  under us-99.3 loses the stale conventions file rather than keeping one that
  disagrees with `AGENTS.md`. `CONVENTIONS_FILE` is deliberately kept in the
  map — it is still the name of a path the factory *owns and removes*.
- **AC3 — one writer, still.** The Save button and the dispatch-time sync
  both go through `instruction_file_plan`; the identical-writers test
  (files **and** delete sets) still passes.
- **AC4 — the hash notices.** `publish_hash` already covers deletions, so the
  retirement registers as a change and the next publish actually performs it.
- **Three tests updated to the new contract rather than deleted**, each
  asserting the retirement positively: `Guidelines.md` is absent from the
  write set *and* present in the delete set, and the conventions text now
  appears in `AGENTS.md`. This reverses us-99.3 one story after it shipped,
  and the tests say so where a reader will find it.
- api Essential green (**1780 passed, 545 skipped, 0 failed**).

### Gaps

- **Nothing has been published to a real repository**, so no `Guidelines.md`
  has actually been deleted anywhere yet. The retirement is proven in the
  plan, not in a repo.
- AC2's rewrite of `test_conventions_do_not_collide_with_any_kind` was not
  needed — the assertion still holds, because `Guidelines.md` remains a
  reserved name that no kind may claim.

## Out of scope

- Changing the per-task `.buildmill/*.md` files or their map — they keep the
  shape us-99.1 gave them.
- Whether a publish happens automatically. It stays the manager's action, as
  us-99.4 decided.
- Reconciling an `AGENTS.md` edited directly in the repository. Build Mill
  owns it whole and overwrites it; that decision stands.
