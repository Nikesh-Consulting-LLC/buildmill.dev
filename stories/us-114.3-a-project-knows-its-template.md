# US-114.3 — A project knows its template, and can change it

**Status:** Testing
**Phase:** 114 — A template travels as a zip
**Depends on:** US-114.2 (the project's Instructions tab in the templates'
shape), US-114.1 (`TemplateZipButtons` and the import plan), US-67.1
(`projects.org_template_id`, written once at creation), migration 266
(`seed_worker_instructions`: a kind the template leaves empty seeds from
`default_worker_instruction`), US-99.4 (publish to repo)

## Story

As a manager, I want a project to say which template it was created from,
show me which files I have changed since, let me put a file back, and let me
switch the whole project to a different template — so that a project's
instructions are traceable to a template instead of being seventeen files
that once, silently, came from somewhere.

## Design

### Provenance is a line on the Overview today

`projects.org_template_id` is written by the create dialog and never again;
the only place it surfaces is *Created from template: X* on the Overview tab
(us-67.1). There is no drift signal, no way to reset a file to what the
template says, and no way to re-apply or change the template — the seed
trigger runs once, on insert.

### A template banner on the Instructions tab

Above the tree/editor (us-114.2), one bar:

- **Template · `<name>` `<key>`** — the org template the project came from
  (or *No template* for a project created before templates or with none
  chosen).
- **N files differ from template** — computed at load by comparing each of
  the project's seventeen files with the template's: the document against
  `org_project_templates.agent_instructions`, a task file against its
  `worker_instruction` section. A kind the template holds no file for is
  not compared (the seed gave it the factory default; there is nothing of
  the template's to differ from) and the editor says so.
- The **Export / Import** buttons from us-114.1, wired to the project's
  files with the same plan → confirm → write flow (`<slug>-instructions.zip`;
  import overwrites project files, an empty file in the zip blanks the
  project's copy).
- **Change template**.

### Per-file drift and Reset

The editor header for a file that differs from the template says *Differs
from template* with **Reset to template**, which writes the template's text
for that file (after the usual confirm). For a kind the template has no file
for, the button is the existing **Reset to factory default**
(`default_worker_instruction`). For the document there is no factory
default: a template with an empty document offers no reset.

### Change template replaces every file

The dialog lists the org's available, unarchived templates (current one
marked, not selectable) with their filled-file counts. Choosing one shows the
plan against the project's current files — **overwritten / cleared /
unchanged**, using the seed's own rule for a kind the template leaves empty
(factory default) — and a warning that local edits are lost and that a
publish is needed afterwards. Confirm writes every file (document from the
template's document; each task file from its section or the factory
default), then re-links `projects.org_template_id` to the chosen template so
the banner and drift now refer to it. Cancel writes nothing.

## Acceptance criteria

1. The Instructions tab shows a banner naming the project's template (name and
   key), or *No template*; the Overview line stays.
2. The banner counts files that differ from the template; a file whose text
   equals the template's is not counted, and a kind the template holds no
   file for is neither counted nor marked.
3. The editor for a differing file shows *Differs from template* and **Reset
   to template**; confirming it writes the template's text and the file no
   longer differs. For a kind the template has no file for, the editor
   offers **Reset to factory default** and says the template has no file.
4. **Export** downloads `<slug>-instructions.zip` in the us-114.1 layout with
   the project's filled files; **Import** shows the same plan/confirm as the
   template pages and overwrites the project's files, and the drift count
   updates.
5. **Change template** lists the org's available templates (current marked,
   not selectable) with a plan of overwritten / cleared / unchanged; confirming
   replaces every file's content — a kind the template has no file for gets
   the factory default, the document gets the template's document — and the
   banner then names the new template with 0 files differing.
6. Cancelling Change template or Reset writes nothing; a viewer without
   `manage_project` sees the banner and drift but no Reset / Import / Change
   controls.

## Out of scope

- **A "template updated — apply changes?" offer.** Drift is compared to the
  template *now*; telling the manager the template moved since creation is a
  separate story (the `db.py` template-offers-an-update query exists for
  agents; the UI does not).
- **A migration.** Nothing new is stored: drift is computed, Change template
  reuses the existing columns and rows.
- **Changing the superadmin catalog from a project.** The banner links only
  to the org's copy.

## Verification (2026-08-17)

the Demo project's Instructions tab (dev server, parsed from the stream)
shows the banner with **"6 files differ from template"** against the org's
Default template, *Differs from template* on the selected `AGENTS.md`, and the
Export / Import / Change template / Reset to template buttons (AC1/AC2/AC3
rendering). Drift is `driftedKeys()` in `instructions-tab.tsx`, comparing each
file with the template's document/section and skipping kinds the template has
no file for.

and the tab's own `writeFile`, and resolves a missing kind through
`default_worker_instruction` exactly as `seed_worker_instructions` does.
