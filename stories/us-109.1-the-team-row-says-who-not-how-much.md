# US-109.1 — The Team row says who, not how much

**Status:** Testing
**Phase:** 109 — The Team page answers at a glance
**Depends on:** US-53.3 (the member page folded into the row's expand panel), US-91.12 (the effort line this trims), us-107.3 (the capability icons that share the name line), US-32.1 (the agent settings page this moves Remove to)

## Story

As the manager, I want the Team roster row to carry only what I scan, so that I
can see who is here, what they can do, and whether they are working — without
reading past a module name, a join date and five accounting figures to get
there.

The row had accreted every fact anyone ever wanted about a member. On a
three-agent roster that is three lines per row, of which one is the question
being asked:

```
Programmer  AGENT 📋 </> 🐛 🚀  Buildmill Interactive Agent  ● online
1 token · Joined Aug 11, 2026 · Pod-001 slot 9
4h 52m worked · 6 completed · +7553 −621 lines · 6.5M tokens · $6.83
```

Nothing there is wrong. It is all *reference* — read once, when a specific
question is being asked — sitting in the place reserved for *scanning*.

And the button cluster had grown to six, of which one deletes the member
irreversibly, wearing the same outline button as Suspend and sitting next to
it.

## Design

### Three facts leave the row; the expand panel already existed to hold them

US-53.3 folded the standalone member page into the row's expand panel. That
panel is where a manager goes when they have a question about one member — so
it is where the answers belong.

| moved off the row | now in | why |
|---|---|---|
| the module pill (`Buildmill Interactive Agent`) | **About → Agent type** | fixed at creation (US-66.2), never changes, and the longest thing on the name line |
| `1 token · Joined Aug 11, 2026` | **About → Tokens, Joined** | looked up, not scanned |
| `+7553 −621 lines · 6.5M tokens · $6.83` | **Output (last 30 days)** | output totals; the org's are on the KPI row now (us-109.2) |

The row keeps the seat (`Pod-001 slot 9` / `self-hosted`) — US-32.2 made two
agents deliberately able to share a name, so the seat is the only thing
distinguishing them, and it is not a lookup. It keeps `4h 52m worked · 6
completed`, which is the one thing on that line that answers *is this agent
earning its seat*.

The subline is now built from parts and rendered only if non-empty: an agent
with no email and no seat gets no empty line under its name.

### Remove leaves the row entirely

It was the one irreversible action in a cluster of reversible ones, one button
from Suspend. It now lives where the manager is already deliberately looking at
one member:

- **An agent** — a bordered section at the bottom of its settings page
  (`/team/{id}/settings`), deliberately *outside* the per-worker config card,
  since an agent with no runner at all is exactly the one being deleted.
- **A person** — inside their expand panel, under **Remove from this org**.
  People have no settings page, and this is their only home. Not repeated for
  agents, so there is exactly one place to remove any given member.

Both render one `RemoveMember` component, so the confirm wording and the delete
cannot drift apart. The settings page resolves `manage_members` client-side
(`loadOrgCapabilities`, the same rows RLS reads) to decide whether to offer it;
the database re-checks on the write regardless.

### The runner console button goes, the console does not

Every agent row carried a second door to `/team/{id}/runner`. The console is
still a page, still reachable from the Console tab on the settings page. One
door is enough.

## Acceptance criteria

- **AC1 — the name line is identity and state only.** Name, `AGENT` pill, the
  four capability icons, online/health, suspended. No module name.
- **AC2 — the subline is identity and place only.** Email (people) and the seat
  or `self-hosted` (agents). No token count, no join date, and no empty line
  when a member has neither.
- **AC3 — the effort line is two figures.** `4h 52m worked · 6 completed` and
  nothing else. People still show no effort line at all.
- **AC4 — the moved facts are one click away.** Expanding a member shows
  **About** (agent type, active tokens, joined) and, for an agent with effort in
  the window, **Output (last 30 days)** with worked/completed, lines added and
  removed, tokens and cost.
- **AC5 — an agent is removed from its settings page.** `/team/{id}/settings`
  offers **Remove agent** with a destructive confirm, and lands back on `/team`
  with the agent gone. Offered only to a manager with `manage_members`.
- **AC6 — a person is removed from their expand panel.** **Remove from this
  org** appears there for a manager, with the same confirm, and the list
  refreshes without them.
- **AC7 — the row's button cluster shrinks by two.** No Remove, no runner
  console. Suspend/reactivate, reset password (people), agent settings, CLI
  window and Claude Terminal are unchanged, as is the chevron.

## Out of scope

- Anything server-side. No migration, no API change, no new query — every fact
  that moved was already being loaded for the row that showed it.
- The `/team/{id}/runner` console page itself, which is untouched and still
  linked from the settings page's Console tab.
- Removing a member from anywhere else (the fleet page, the machine page).
  Those never offered it.
- Suspend. It stays on the row: it is reversible, it is the thing a manager
  actually reaches for, and moving both would have left the row unable to stop
  a misbehaving agent.

## Built (2026-08-16)

Web only.

- `team/remove-member.tsx` **(new)** — `RemoveMember`, the one confirm+delete
  both surfaces render.
- `team/team-view.tsx` — module pill, token/joined subline, the three output
  figures, the Remove button and the runner-console button all removed;
  `subline` derived; `formatWhen` exported; the moved facts passed into
  `MemberDetail`.
- `team/[principalId]/member-detail.tsx` — **About** and **Output** sections,
  and a person's **Remove from this org**.
- `team/[principalId]/settings/page.tsx` — the **Remove this agent** section
  and its `manage_members` check.
- `team/[principalId]/agent-runner-data.ts` — `orgId` exposed from
  `useAgentRunner` (it was already resolved in `reload`, just not returned).

**Verified.** `npm run build` compiles and type-checks; `npm run lint` is clean
of new problems; `npm run test:web` 236 passing.

**Not verified.** Nothing was rendered. There is no `apps/web/.env.local` in
this checkout, so no page was loaded and **no row has been seen** — the same
gap us-107.3 recorded. Every acceptance criterion here is visual, and AC5/AC6
in particular are destructive paths that have not been exercised against a real
row: the delete is the same statement the roster ran before, but the two
callers of it are new.
