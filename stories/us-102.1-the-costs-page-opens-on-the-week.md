# US-102.1 — The Costs page opens on the week, and stops explaining itself

**Status:** Testing
**Phase:** 102 — Costs leads with the numbers
**Depends on:** us-95.4 (the window and the filters already live in the URL)

## Story

As the manager, `/costs` opens on thirty days and on a paragraph. Neither is
what I come here for.

Thirty days is the wrong default because the question I actually ask at this
page is "what has this week cost me" — a month flattens the week I am asking
about into a bar four pixels wide, and the window-over-window line compares
me against a month I have already stopped thinking about. Seven days is the
grain the work happens at; thirty is one click away and stays there.

The paragraph
([costs-view.tsx](../apps/web/src/app/(app)/costs/costs-view.tsx) L229-236) is
five lines of essay about gateway metering, rate-at-time-of-call pricing and
where rates are configured. It was written for the first visit and is read on
none of the others; it pushes the numbers below the fold on a laptop and off
the first screen entirely on a phone. What it says is true and worth keeping
somewhere — it belongs in the help topic, not above the data.

## Acceptance criteria

- **AC1 — the default window is 7 days.** A bare `/costs` shows the last
  seven days: the curve, the table and the totals. `DEFAULT_DAYS` in
  [costs-url.ts](../apps/web/src/app/(app)/costs/costs-url.ts) is the only
  place the number lives, so the parse, the URL round-trip and the view agree
  by construction.

- **AC2 — the URL still says what it means.** Because defaults are omitted
  from the query string, a bare `/costs` is now seven days and `?days=30`
  appears in the URL when thirty is chosen. Every window value already in a
  bookmark (`?days=1`, `?days=7`, `?days=30`, `?days=90`) parses to exactly
  what it did before — the change is which one is implied, never what an
  explicit one means.

- **AC3 — the paragraph is gone from the page.** The heading stays; the
  five-line description is removed. Nothing that was only stated there is
  silently lost: the two facts a manager can act on — cost uses the rate in
  force when the call was made, and rates live in Settings → LLM Providers —
  move onto the Total cost card's own hint, which is where somebody asking
  "what does this number mean" actually looks.

  *Amended during build:* the criterion first said "the help topic for this
  page". There is no Costs topic in `HELP_TOPICS` — the section has never had
  one — and minting a topic means a new body renderer plus its mirror in
  `help_content.py`, which is a change of its own and not this one. The facts
  land on the card instead; a Costs help topic stays available to write.

- **AC4 — tests.** `costs-url.test.ts` pins the new default and that the
  explicit values are unchanged; `npm run build` green.

## Verified (2026-08-15)

- **AC1** — `DEFAULT_DAYS` is `7` in
  [costs-url.ts](../apps/web/src/app/(app)/costs/costs-url.ts); it is the only
  literal, read by both the parse and the round-trip.
- **AC2** — two new tests: every window in the vocabulary (`1 / 7 / 30 / 90`)
  parses to itself, and `days=30` now appears in the query string while `7`
  is the omitted default. The point of the first is that a bookmark written
  before this change means exactly what it meant.
- **AC3** — the paragraph is gone; the rate-at-time-of-call fact and the
  Settings → LLM Providers pointer are the Total cost card's hint (amended,
  above).
- **AC4** — `npm run test:web` green (**181 passed, 0 failed**); `npm run
  build` green.

### Not verified here

- **The rendered page.** This checkout has no `apps/web/.env.local`, so the
  dev server cannot create a Supabase client and every route — including
  `/costs` — answers 404 from `proxy.ts` before any component runs. The
  default window has not been seen in a browser; it is pinned by test only.

## Out of scope

- The window vocabulary itself (`Today / 7 / 30 / 90` stays as it is).
- Any change to what the curve or the table compute.
- Per-manager remembered windows — the URL is the memory, and a preference
  store for one number is not worth a table.
- A Costs help topic. Worth writing; not this story.
