# US-118.5 — The built-in covers depict the work

**Status:** Testing
**Phase:** 118 — A template shows its face
**Depends on:** US-118.1 (built-in covers: `image_path = builtin/<name>` →
`apps/web/public/template-covers/<name>.svg`, the `BUILTIN_COVERS` list in
`lib/template-cover.ts`, the picker strip in `TemplateDetailsDialog`)

## Story

As the platform admin (or an org manager) filling in a template's face, I
want the built-in cover picker to offer a cover for each kind of project the
factory actually builds — not just six generic ones — so that a template
for a Power BI dashboard, a Salesforce integration or a Yardi report has a
picture that says so, without anyone having to draw and upload one.

## Design

Nine covers join the six from US-118.1, drawn in the same palette and
geometry (320×160, 2:1, soft ground, ink and one accent, no text but a
mark) so the fifteen read as one set:

| name | label | what it depicts |
|---|---|---|
| `python-react` | Python + React app | a dark terminal panel beside a React atom |
| `database` | Database project | a cylinder with bands and a small table grid |
| `report-conversion` | Report conversion | a text document, an arrow, a document with a chart |
| `power-bi` | Power BI dashboards | a four-tile dashboard: bars, line, donut, KPI |
| `corporate-website` | Corporate website | a browser window: nav, hero headline, three columns |
| `conversational-agents` | Conversational agents | two chat bubbles and a typing indicator |
| `sharepoint` | SharePoint project | a document library: folder, list rows, a share mark |
| `salesforce` | Salesforce integration | a cloud, a two-way arrow, a system box |
| `yardi-reports` | Yardi reports | a building with a window grid beside a report sheet |

Nothing else changes shape: `BUILTIN_COVERS` gains nine entries (order is
display order — the six general ones first, then these), the CHECK already
accepts any `builtin/[a-z0-9-]{1,40}`, the API accepts the shape, and the
picker strip wraps. With fifteen thumbnails the strip gains a one-line label
under each (the `title` tooltip stays), because a wall of unlabeled 68px
pictures is a guessing game past six.

## Acceptance criteria

1. `apps/web/public/template-covers/` holds the nine new SVGs, each 320×160,
   served at `/template-covers/<name>.svg` (200, `image/svg+xml`).
2. `BUILTIN_COVERS` lists fifteen entries; every name is a legal
   `image_path` and has its file on disk — pinned by `template-cover.test.ts`.
3. In **Template details** (admin and org scope) the built-in strip shows
   all fifteen with a short label under each; picking any of the nine sets
   `image_path = builtin/<name>` on Save, and the card, header thumb and
   list thumb render it.
4. `npm run test:web`, `npm run build` clean.

## Out of scope

- Custom uploads (already there), an icon library or a colour picker.
- Renaming or redrawing the six existing covers.
- Per-org built-in sets — the fifteen are the factory's.
