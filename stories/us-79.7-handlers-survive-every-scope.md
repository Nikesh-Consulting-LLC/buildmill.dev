# US-79.7 — Error handlers survive every scope they serve

**Status:** Completed
**Phase:** 79 — Production error truth
**Dependencies:** none
**Fixes:** the remainder of prod BUG-8 (`AttributeError: 'WebSocket' object has no attribute 'method'`, issue `f0fc7113-5c31-468f-83d1-2ef49d2e3e1a`)

## Story

As the superadmin, I want every registered exception handler to survive being
invoked for a websocket, so that the inbox reports the failure that happened —
never an `AttributeError` raised by the reporting machinery itself, six copies
deep, masking the cause.

## Context

BUG-8 was three defects; commit `8c0f4af` fixed two (the console's
`run_trace.created_at` column, and `request.method` in the two handlers'
**report context** dicts) and is already live on prod. But the sweep stopped
one line short — these still dereference `request.method` unguarded and will
raise the identical mask the moment their handler runs for a socket scope:

- `main.py` `answer_postgrest_refusal` — the `logger.error` line (~379)
- `main.py` `report_unhandled_exception` — the `logger.exception` line (~416)
- `main.py` `report_operational_http_exception` — the `logger.warning` line
  (~333); Starlette routes an `HTTPException` raised inside a websocket route
  to this same handler, handing it the `WebSocket` as `request`
- `errors.py` `report_http_exception` — the context dict (~64), reached from
  the handler above

## Acceptance criteria

1. No handler registered on the app (nor any helper a handler calls)
   dereferences an HTTP-only attribute without a guard; on socket scopes the
   method renders as `WEBSOCKET` in both the report context and the log line —
   the same convention `8c0f4af` established.
2. Regression tests raise, from inside a websocket route: a `PostgrestError`,
   an `HTTPException`, and a plain `Exception` — asserting no `AttributeError`
   anywhere, the socket closing cleanly, and (where the US-76.1 policy says
   report) an `app_issues` row whose context reads `method: "WEBSOCKET"` and
   whose title names the **original** error.
3. A sweep test in the spirit of `test_console_columns.py`: every registered
   exception handler is invoked once with a minimal websocket-scoped
   connection object and must not raise — so the *next* handler someone adds
   cannot reintroduce the mask.

## Out of scope

- The accept-race hang-up itself (us-79.6).
- Any change to which errors are reported (the US-76.1 policy stands).
- The already-shipped `8c0f4af` fixes — verified live, not re-done.

## Proof required to reach Testing

The three regression tests plus the sweep test green, and the sweep test shown
failing when a deliberately broken handler is added locally.

## Outcome

Built 2026-08-11 on `phase-79-production-error-truth` (commit `8f028b1`).
`scope_method()` in errors.py answers `WEBSOCKET` on socket scopes; every
handler and `report_http_exception` resolve the method through it — the four
unguarded sites (both logger lines in main.py, the HTTPException handler's
log, the errors.py context dict) are gone.

**Verified:** `test_handler_scopes.py` — a PostgREST refusal, a 500, and a
plain crash raised from real websocket routes each report the *original*
error with `method: "WEBSOCKET"` and zero AttributeErrors; the sweep invokes
every registered handler (incl. us-79.5's new one) with a websocket
connection. Stashing the fix makes 3 of the 4 tests fail (AC-required proof);
restoring it passes 4/4. Full api suite green.

**Not verified:** nothing — this story is fully covered by automated tests.
