# US-93.1 — The front door tells the story

**Status:** New
**Phase:** 93 — The public site
**Depends on:** nothing

## Story

As the manager, buildmill.dev is the address I give people. Today it hands
them a login form — the one page on the whole property that assumes you
already know what Build Mill is. The public site that should catch that
visit (`apps/public`) exists, but it is one fold and a three-card "how it
works": a placeholder wearing the brand, not a story.

A visitor arriving at the root domain should leave two minutes later able
to repeat the pitch: Build Mill is an AI software factory with a human at
every gate. A story goes in; an agent plans it, and the plan is approved
before a line is written; the agent codes it and opens a pull request; the
manager reviews with the diff and the story side by side; releases are cut,
tried on UAT, signed off, and promoted — the same pinned build, never a
rebuild. The agent proposes, the manager decides. That is the story, and
the front door is the one surface that never tells it.

One page, simple but immersive — the story told top to bottom, not a
brochure of tabs.

## Acceptance criteria

- **AC1 — the root domain lands on the story, not a login.** `buildmill.dev`
  serves the public site; **Log in** and **Sign up** (→ `app.buildmill.dev`)
  are buttons in the corner, not the destination. If the Cloudflare hostname
  mapping is what sends visitors to the app today, fixing that mapping is
  part of this story, not a separate ticket.
- **AC2 — one page answers four questions, in order:** what Build Mill *is*
  (one sentence a visitor can repeat), what it *does* (the pipeline from
  story to shipped release), what its *features* are, and *who it is for*.
  A slim anchor nav jumps between them; there are no other pages.
- **AC3 — the "what it does" section is a journey, not a grid.** It follows
  one user story through the mill — written, planned, plan approved, coded,
  PR opened, reviewed, merged, released to UAT, signed off, promoted — as a
  narrative sequence a visitor scrolls through. The three-card version this
  replaces is the anti-goal.
- **AC4 — every claim on the page is true of the shipped product.** The
  gates named are gates that exist (plan approved before code, review before
  merge, sign-off before promote); the boundaries named are real (coding
  credentials stay on the operator's machine, GitHub stays the source of
  truth for code); releases described as pinned and immutable. No invented
  logos, testimonials, pricing, or feature the app does not have.
- **AC5 — simple stays simple.** Still `apps/public`: one static
  `index.html`, zero dependencies, no build step, no external requests
  (fonts, scripts, trackers — nothing leaves the origin). Motion is subtle
  scroll-reveal at most and is disabled under `prefers-reduced-motion`;
  light and dark both follow the system preference, as the current page
  already does.
- **AC6 — it reads in a hand.** At 375px the page is a single column with
  no horizontal scroll; the journey and feature sections stack; nav
  collapses to the brand plus the two buttons.
- **AC7 — the exits are Sign up and Log in.** Both appear in the nav and in
  a closing call-to-action; Sign up is the primary. No other outbound links
  except the app.
- **AC8 — the page carries its metadata.** Title, description, Open Graph
  tags, and the icon survive the redesign; the description matches the
  one-sentence answer from AC2.
- **AC9 — the git story is showcased, not buried.** A visitor must learn
  that the factory is plain git underneath: it exposes a real git remote
  (`api.buildmill.dev/git/<org>/<project>`), so any traditional client —
  terminal, VS Code, JetBrains — clones and pushes side by side with the
  agents, the factory opens the PR from the pushed branch, no GitHub
  credential ever sits on the worker's machine, and the push rails
  (claimed branch, forward-only, no rewrites without a grant) hold for
  humans exactly as for agents. This gets its own visual treatment (e.g.
  a terminal vignette), not a line in a feature card.

## Out of scope

- Pricing, docs, blog, changelog, or any second page — this is one page.
- Screenshots or live embeds of the app (they need curated demo data to not
  leak; a later story if wanted).
- Analytics, cookie banners, or any tracking.
- Changes to the app's own login/signup pages, or to `server.js` beyond
  what AC1 needs.
