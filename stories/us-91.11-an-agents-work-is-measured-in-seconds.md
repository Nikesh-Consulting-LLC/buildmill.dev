# US-91.11 — An agent's work is measured in seconds

**Status:** Testing
**Phase:** 91 — Usability: the dashboard reads like the job
**Depends on:** nothing (us-91.12 renders what this records)

## Story

As the manager, I cannot answer "how much work have my agents actually
done". Everything needed to answer it is already recorded, and nothing adds
it up:

| Fact | Where it already lives |
|---|---|
| Lines added / removed / files changed | `runs.lines_added`, `lines_removed`, `files_changed` (parsed by `apps/api/app/metrics.py`) |
| Tokens and dollars | `runs.tokens_in`, `tokens_out`, `cost_usd`; per call in `llm_usage` (with `worker_id`) |
| Who did it | `runs.worker_id` → `workers.principal_id` |
| Which work item | `runs.issue_id`, and `run_items` for a batch run |
| Commits | `run_item_commits` |

What is genuinely missing is **time**. A run's wall clock exists as
`started_at`/`finished_at`, but nothing durable says how long an agent
*worked* — and a wall clock is not the same thing: a run can sit paused,
and a run whose lease expires never gets a `finished_at` at all, so
subtracting timestamps on read silently reports either zero or forever.

So: record the seconds when the run ends, and roll the whole set up per
agent per day, so the Team page reads a small table instead of aggregating
every run in the workspace on every load (the mistake Phase 87 spent itself
undoing).

Seconds are the unit stored. Hours are a rendering.

## Acceptance criteria

- **AC1 — a run records the seconds it worked.** A new integer column
  `runs.work_seconds`, written once when the run reaches any terminal state
  (finished, failed, cancelled, abandoned, lease-expired). It measures time
  the agent held the run and was working:
  - from `claimed_at` (not `created_at` — queued time is not work),
  - to `finished_at`, or for a run that died holding its claim, to
    `last_heartbeat_at` (the last moment the agent was demonstrably alive),
  - **minus** any paused span (`paused_at` … resume) — **amended during
    implementation: not possible.** Nothing records a pause *interval*;
    `paused_at` is the current parked marker and is cleared on resume. The
    column comment states the gap; closing it needs a pause ledger.
  Never recomputed on read, and never null on a terminal run — a run whose
  time cannot be established writes `0` and records why in `error`/an event,
  because a silent null becomes a silent zero in every sum downstream.
- **AC2 — a daily rollup per agent.** A new table `agent_effort_daily`
  (org-scoped, RLS via `public.is_org_member`), keyed
  `(org_id, worker_id, day)` and carrying: `work_seconds`, `runs_finished`,
  `issues_completed`, `lines_added`, `lines_removed`, `files_changed`,
  `tokens_in`, `tokens_out`, `cost_usd`. Incremented as each run reaches a
  terminal state — one upsert, in the same transaction that closes the run,
  so the rollup can never drift from the runs it summarises.
- **AC3 — "completed" is counted once, and only when it merged.** A work
  item counts toward `issues_completed` for the agent whose **code run**
  produced the merge, at merge time — not per run, not per attempt, and not
  for a plan run. An item merged after three attempts counts once, for the
  agent that finished it. Pin this in the migration's comment and in a test:
  it is the number a person will quote in a review.
- **AC4 — dollars have one source.** `llm_usage` stays the per-call ledger;
  `runs.cost_usd` stays the run's rollup; `agent_effort_daily.cost_usd` sums
  the runs. Document which of the three any surface must read, and make the
  three reconcile on a seeded fixture in a test. Two different dollar figures
  for the same week is worse than none.
- **AC5 — history is backfilled.** The migration populates
  `runs.work_seconds` and `agent_effort_daily` from existing runs, using the
  same rules (including the heartbeat fallback), so the Team page does not
  open on an empty chart with months of real work behind it. The backfill
  reports how many runs it could not time, rather than quietly zeroing them.
- **AC6 — a human's time is not an agent's time.** `user_activity_sessions`
  (`active_ms`) already records people. This story does not touch it, does
  not merge it into the same table, and does not present the two as the same
  measure — an agent's held-lease seconds and a human's active-UI
  milliseconds are different things with the same unit.
- **AC7 — the migration is applied to both projects.** Per the repo rule:
  written in `infra/supabase/migrations/`, applied to prod **and** dev,
  `database.types.ts` regenerated, and `test_embed_ambiguity.py` swept — a
  new table holding two FKs is exactly the shape that breaks unrelated
  embeds (BUG-1.1).
- **AC8 — SQL tests cover the rules.** A `*_sql.py` test (Full QA) covers:
  paused time excluded, lease-expired run timed to its last heartbeat, a
  re-run item counted once, the rollup equalling the sum of its runs, and
  cross-org isolation on `agent_effort_daily`.

## Out of scope

- Any UI. The Team KPIs, the per-agent columns and the work-item effort line
  are [us-91.12](us-91.12-the-team-page-opens-with-three-numbers.md).
- Re-deriving lines of code, tokens or cost — those already exist and are
  already written; this story sums them, it does not recompute them.
- Billing, invoicing, or per-agent cost budgets and alerts.
- Per-tool or per-token-type timing breakdowns (`run_activity` and
  `mcp_tool_calls` hold that grain if it is ever wanted).
- Retention of the new table — it inherits whatever us-87.8 decides.

## Verified (2026-08-14)

- Migration `252_agent_effort_ledger.sql` applied to **both** Supabase projects;
  `database.types.ts` regenerated; `test_embed_ambiguity.py` swept clean.
- Prod backfill: **35 agent-day rows, 181 of 185 runs timed** (the other four
  are still in flight), **16.2 hours**, 16 completed items, 19 items carrying a
  cost.
- Rollups are maintained by trigger, in the same transaction that closes the
  run — chosen over application code because several paths close a run (the
  worker reporting, the reaper, a cancel, an abandon) and the rollup must not
  depend on which one wins.
- `test_agent_effort_sql.py` (Full QA) covers: timing from the claim, the
  heartbeat fallback, never-null on terminal, rollup = sum of runs, an item
  counted once for the agent that merged it, a plan run never completing an
  item, cost including failed attempts, and org scoping.

**AC1 amended — paused spans are NOT subtracted.** Nothing in this schema
records a pause *interval*: `runs.paused_at` is the current parked marker and
is cleared on resume, so there is no history to subtract. A run paused for
three hours and resumed counts those hours. This is stated in the column
comment rather than left for a reader to discover, and closing it needs a pause
ledger — its own change.

**Not run here**: the SQL suite. This machine has no `DATABASE_URL`, so Full QA
skips it (see CLAUDE.md → Testing). It runs on a machine with the credential.
