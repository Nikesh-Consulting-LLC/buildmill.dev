# US-96.9 — A stop is an answer, not a breakdown

**Status:** Testing
**Phase:** 96 — The type shapes the path
**Depends on:** nothing (sits beside us-85.3's fault-class work — that story
labels a broken bench; this one labels a deliberate stop)

## Story

As the manager, I stopped a run and the runner treated my decision as a
malfunction to repair. Run `22b807a5` (2026-08-14, the five-story batch code
run): I stopped it at 17:33 to re-dispatch per story. The module knew —
[interactive.py](../apps/runner/supervisor/modules/interactive.py) emitted
"the manager stopped this session" — but that knowledge died on the way out.
The failed result went through the repair ladder
([repair.py](../apps/runner/supervisor/repair.py)), whose keyword
classifier read the cancellation as transient: a 60-second wait, then a
**reclone** that invalidated the workspace's source record (forcing the next
run to refetch the whole tree), then a fresh CLI boot at 17:35 — on a claim
that no longer existed. That zombie session came up with a revoked worker
token and no factory MCP tools, spent two and a half minutes probing
endpoints with curl, went heartbeat-stale (a spurious
`agent_failures` row), and the run finally closed at 17:37 as
`runner-fault: "no enabled module can do 'code' work"` — a second spurious
failure record, five minutes after I had already made the decision it was
"diagnosing".

Every consumer of failure data now reads a lie: the failure log shows an
agent that broke twice on a day it broke zero times, the effort rollup
counts a 42-minute failure, and the error names modules when the truth is
"the manager stopped it".

## Acceptance criteria

- **AC1 — stopped is a fact on the result, not a phrase in the text.** A
  session ended by a manager stop returns a `ModuleResult` that says so in a
  field. `classify()` and `classify_fault()`
  ([repair.py](../apps/runner/supervisor/repair.py)) check that field
  before any keyword loop — the way `usage_cap_hit` already short-circuits —
  and a stopped result is terminal: no wait, no reinstall, no reclone, no
  retry. Pinned by a test proving the text "the session was cancelled"
  alone never selects a repair action.
- **AC2 — the run closes as stopped.** The runner reports a stopped session
  so the run row records the stop (the existing cancel/stop fields), with
  `fault_class` left null — neither runner-fault nor work-fault, because
  neither the box nor the story failed. The terminal error never says
  "no enabled module": the words the manager sees are "stopped by the
  manager".
- **AC3 — no failure rows for a decision.** A manager stop writes no
  `agent_failures` row — not `run-failed`, and no `heartbeat-stale` from its
  own shutdown window — and the daily effort rollup
  (`agent_effort_daily`) does not count it as a failure.
- **AC4 — no boot without a live claim.** Before invoking the CLI — first
  attempt or after any repair action — the workloop
  ([workloop.py](../apps/runner/supervisor/workloop.py)) confirms it still
  holds the claim. A lost, expired, or stop-requested claim aborts the
  invocation with one trace line naming why, and releases quietly. The
  2026-08-14 zombie — a booted agent holding a revoked token, probing the
  factory for a way in — becomes structurally impossible.
- **AC5 — a stop never costs the workspace.** No repair action runs in
  response to a stop, so the workspace's source record survives and the next
  run on the bench reuses the tree instead of refetching it.
- **AC6 — tests.** Runner tests for AC1/AC4/AC5 (classification pins, the
  no-claim guard, the untouched workspace record); an api Essential test if
  the stop-report path changes any route contract.

## Verified (2026-08-15)

- **AC1**: `ModuleResult.stopped` is the field; `LiveSession.cancel()`
  records the run in `STOPPED_RUNS` and the interactive module's
  `execute()` stamps the result. `classify()` short-circuits on it before
  any keyword loop (terminal — no wait, no reinstall, no reclone, no
  retry), pinned by a test whose result carries exactly "the session was
  cancelled" as text.
- **AC2**: the stop becomes a fact on the RUN ROW at stop time —
  `run_console.py`'s cancel relay now calls the new
  `db.set_run_stopped_reason(run_id, "stopped by the manager")` — and
  US-33.2's existing submit mapping (`stopped_reason` ⇒ outcome
  `stopped`, `error_text = stopped_reason`) lands it with those exact
  words. No Submit contract change was needed, so no new route test
  either (the AC6 clause was conditional on one). `fault_class` stays
  null: the runner's payload omits it entirely for stopped results.
- **AC3**: `complete_run` records an attempt and an `agent_failures` row
  for **failed only** now — a stop consumes nothing and writes no
  failure record. The effort ledger keys on run status, and `stopped` is
  not `failed`. The spurious heartbeat-stale row dies with AC4 (no
  zombie session exists to go stale). Beyond the AC: a stopped run's
  issue returns to `prev_issue_status` (migration 120's field) instead
  of `failed`, so "stop to re-dispatch per story" is one step and the
  item never wears a defect it doesn't have.
- **AC4**: `WorkerClient.claim_alive` probes the heartbeat endpoint
  (409/404 = the server says the claim is gone; a network blip answers
  live — a healthy run must not die over a dropped packet), and
  `execute_with_repair` runs a `preflight` before the FIRST boot and
  before every post-repair boot. A dead claim raises `ClaimLost`:
  `run_claimed` writes one trace line, releases quietly, submits
  nothing. Pinned by a test (dead claim ⇒ no submit, release note names
  it).
- **AC5**: no repair action runs for a stopped result (AC1's
  short-circuit), so nothing recloned touches the workspace source
  record — pinned by the same classification test.
- **AC6**: three runner tests added (`test_workloop.py`, 15 in file;
  full runner suite green), plus the existing suite's stub client taught
  the new probe. api Essential 1676 passed.
- **Not verified here, for UAT**: a live stop on a real interactive run
  (stop from the console → run row reads "stopped by the manager", item
  back at its pre-dispatch status, zero rows in Agent failures).

## Out of scope

- us-85.3's machine-fault relabeling — a broken bench is its own story;
  this one is only about deliberate stops.
- Changing how a stop is *requested* or delivered (the US-78.8 machinery) —
  only how the runner answers one.
- Requeue-on-stop policy — what I dispatch after stopping remains my call;
  nothing here auto-requeues.
- The repair ladder's behavior on genuine failures — wait/reinstall/reclone
  stay exactly as they are for results that are not stops.
