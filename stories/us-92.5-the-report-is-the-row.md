# US-92.5 — On Bug Reports, the report is the row

**Status:** Completed
**Phase:** 92 — The app on a phone
**Depends on:** [us-91.7](us-91.7-reports-are-bug-reports-and-live-under-activity.md) (the page this fixes, under its new name)

## Story

As the manager, Bug Reports is a `table-fixed` with seven columns, five of
them a fixed width: the chevron `w-8` (32px), Last seen `w-[7.5rem]` (120),
Count `w-16` (64), Status `w-24` (96) and Actions `w-20` (80). That is
**392px of fixed columns inside a 341px content box at 375px** — over-
constrained before the **Report** column, the only one carrying what was
actually reported, is given anything at all. The browser resolves it by
crushing everything, and the crash message — the reason the page exists —
comes out as a few characters and an ellipsis.

The Project column is already `hidden md:table-cell`, so on a phone the page
has quietly dropped which app is broken while keeping a 64px column for a
number.

Triage is a phone task. It happens when a notification lands, away from the
desk. The row has to lead with what broke.

## Acceptance criteria

- **AC1 — one card per report below `md`**, and the report's own words lead:
  the title/message over up to two lines, with its kind icon (crash, user
  report, wiring check) beside it.
- **AC2 — the project comes back.** Which deployed app reported this is
  essential on a phone, not less important than on a desktop. Project and
  deployment ride the card's meta line with the existing project colour dot.
- **AC3 — the meta line carries the rest**: last seen, and the occurrence
  count as words (`seen 14×`) rather than a column that costs 64px to say
  "14".
- **AC4 — status is a badge on the card, and the actions are buttons on
  it** — Promote / Ignore at ≥40px, matching what desktop offers for the same
  report state. Today they are an 80px column at the far edge.
- **AC5 — expanding still shows the detail** (stack, payload, deployment
  context) as it does now, readable at 375px without horizontal scrolling
  inside the `<pre>`.
- **AC6 — a wiring check still reads as a confirmation, not a crash**
  (us-79.1) — neutral icon, neutral treatment, no destructive colouring, in
  the card layout as in the table.
- **AC7 — the table stays at `md`+**, unchanged, including the `table-fixed`
  sizing that works there.

## Out of scope

- Changing triage semantics, the promote flow, or which statuses exist.
- The superadmin system-issues console, which has its own console layout.
- Reporting new things, or changing what a deployment sends.

## Verified (2026-08-14, localhost)

- Builds and type-checks; the table stays at `md`+ and the cards render below
  it.
- The expanded detail was **extracted into one `detailFor(report)` helper**
  used by both the table row and the card — two copies of the substance of a
  report would have drifted.

**Not verified with data**: no workspace reachable from this machine has any
`app_issues` rows, so the card could not be seen populated. The layout is
built to the measurements in the story (the seven columns' fixed widths total
~392px inside a 341px box) but a populated pass belongs in the manager's UAT.
