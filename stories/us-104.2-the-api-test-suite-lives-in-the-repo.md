# US-104.2 — The API test suite lives in the repo

**Status:** Testing
**Phase:** 104 — The tree can be trusted
**Depends on:** US-80.1 (the Essential/Full QA split), US-3.15 (credential redaction), US-31.3 (the fail-closed pool gate)

## Story

As the manager, I want the Playwright API suite that already exists on my
machine to be in the repository, so that it survives the laptop, runs for
anyone, and shows up in a diff when someone changes an endpoint it covers.

`scripts/testing/` has been sitting untracked since 2026-08-15: 22 spec files,
a generated catalog of the whole service, a summarizing runner, and a README
that explains its three layers. It has its own `.gitignore` excluding
`node_modules/`, `.env`, `.auth/` and results — so it was plainly written to
be committed, and simply never was. Nothing in git knows it exists.

That is the same failure mode Phase 104's other half is about. The migration
numbering fix lived on an unpushed branch for three days, went stale, and was
deleted; this suite has lived nowhere but a working directory for a day. Work
that only exists in one place is work that is one `rm -rf` from gone.

## Design

### What it actually is

Three layers, in decreasing order of how safely they point at a live
deployment — the README is the authority, this is the shape:

1. **The auth boundary, generated, always runs.** One test per operation
   asserting that no credential is refused *and* that a **forged credential of
   the right shape** is refused too. The second half is the one that earns its
   keep: a guard that merely checks a header is present, or trusts an
   unverified JWT, passes the first and fails this one. Safe anywhere — every
   request is refused before the handler runs, so nothing is dispatched,
   deployed, merged or deleted.
2. **Contract and refusal tests, hand-written, always run.** An unknown id, a
   rejected body, a path-traversal attempt: each must answer a legible 4xx
   with a renderable `detail`, never a 500. `security.spec.ts` adds the
   cross-cutting rules — a 422 that never echoes the input it rejected
   (a request body can carry a pasted PAT or an SSH key), CORS as an
   allow-list, and a sweep asserting no operation answers 2xx anonymously.
3. **Reads and mutations, opt-in.** Reads need a credential; mutations stay
   off behind `ALLOW_MUTATIONS=1`, because this API creates and deletes orgs,
   dispatches runs, merges PRs and deploys over SSH. A missing credential
   **skips** rather than fails, and the runner prints what was skipped and
   which variable would enable it — so a green run with skips is never
   mistaken for coverage.

### It is a fourth suite, not a fifth of an existing one

CLAUDE.md documents three suites (web, api, runner) and says there is no
single command that runs them all. This makes four, and the README keeps that
honest: it needs a *running service* to point at, so it cannot join the api
pytest run, which is deliberately network-free (US-80.1's autouse guard makes
outbound resolution fail instantly). It belongs where it is — beside the
service, run against a deployment.

### No secrets, checked rather than assumed

Every apparent credential in the tree is a marker or a deliberate fake:
`FORGED_JWT` is documented as signed by nobody (its signature segment decodes
to "not-a-real-signature"), `servers.spec.ts` holds a `SECRET_MARKERS` list of
strings that responses must **not** contain, and the PAT in `github.spec.ts`
is invalid by construction. `env.example` ships with every value blank. The
inner `.gitignore` keeps `.env`, `.auth/` and results out.

## Acceptance criteria

- **AC1 — it is in git.** `scripts/testing/` is committed: the 22 specs,
  `lib/`, `tools/generate-catalog.py`, `run-all.mjs`, `endpoints.json`,
  `playwright.config.ts`, `tsconfig.json`, `package.json`,
  `package-lock.json`, `env.example`, `README.md` and its `.gitignore`.
- **AC2 — nothing secret rides along.** `node_modules/`, `.env`, `.auth/`,
  `results/`, `playwright-report/` and `test-results/` stay excluded, and the
  committed files are scanned for credential shapes before the commit, not
  after.
- **AC3 — the suites are documented as four.** CLAUDE.md's Testing section
  names this one, says what it needs (a running service, `npm install` in that
  directory) and why it is not part of the api pytest run.
- **AC4 — the catalog's staleness is stated.** `endpoints.json` was generated
  on 2026-08-15 and does not include endpoints added since — Phase 103's
  `GET /worker/release-prep/held` among them. The README says how to
  regenerate it (`tools/generate-catalog.py` against a running app) and that
  the auth-boundary layer covers only what the catalog knows.

## Out of scope

- Regenerating `endpoints.json` — it needs a running service, which the
  machine committing this does not have. Recorded in AC4 instead of faked.
- Running the suite as part of any existing command, or gating anything on it.
- CI. There is no test workflow in `.github/workflows/` today and this story
  does not add one.
- Extending coverage to Phase 103's new endpoints — a follow-up once the
  catalog is regenerated.
- Any change to the suite's own code. It goes in as written.

## Built (2026-08-16)

`scripts/testing/` committed as written — 36 files: 22 specs, `lib/`,
`tools/generate-catalog.py`, `run-all.mjs`, `endpoints.json`, config and
README. CLAUDE.md's Testing section now says **four** suites and describes
this one, including why it cannot join the api pytest run (it needs a running
service; Essential makes outbound network fail by design).

**Verified.** The tree was scanned for credential shapes before committing
(`sk-ant-`, `sbp_`, `ghp_`, `sfw_`, PEM headers, JWT prefixes). Every hit was
inspected in context and every one is deliberate: `FORGED_JWT` in `suite.ts`
is documented as signed by nobody — its signature segment decodes to
"not-a-real-signature"; `servers.spec.ts` holds a `SECRET_MARKERS` list of
strings responses must **not** contain; `github.spec.ts` uses a PAT invalid by
construction; `llm.spec.ts` uses provider prefixes in must-not-appear
assertions. `env.example` ships every value blank, and the inner `.gitignore`
excludes `node_modules/`, `.env`, `.auth/` and results.

**Not verified — the suite was never run.** It needs a live service and
credentials this machine does not have, so nothing here proves the specs pass,
or even that they execute. It goes in as found. `endpoints.json` is also
stale: generated 2026-08-15, so Phase 103's `GET /worker/release-prep/held`
is absent and untested by the auth-boundary layer. The README now carries that
warning and the regeneration command at the top.
