# US-92.3 — A release is a card, with its buttons showing

**Status:** New
**Phase:** 92 — The app on a phone
**Depends on:** nothing

## Story

As the manager, Releases is the page where I *act* — sign off, promote,
cancel, retry. On a phone it is the page where I can act least.

Measured at 375px: two tables of **nine columns each** — Version, Project,
Status, UAT, Production, Commit, Items, Cut, Actions — inside a 314px box.
Nothing overflows because every cell is crushed instead, and the result reads
as one run-on string:

> `8c5d3e3 · 1 items · 7/29/2026Queued——8c5d3e317/29/2026Cancel`

That is the "titles are mixed up" complaint exactly: the headers no longer sit
over the values they name. And **Actions is the ninth column**, so the button
that is the whole reason for the visit is squeezed into the last few pixels.

A release is not a row of nine facts. It is one build, in one state, with one
or two things you can do to it next.

## Acceptance criteria

- **AC1 — one card per release below `md`.** Version as the heading (mono,
  tabular), status badge beside it, project underneath. The table stays at
  `md`+.
- **AC2 — the two environments read as a journey, not two columns.** A
  compact line showing UAT → Production with each stage's state (waiting,
  deployed, signed off, promoted, failed) and when — the question the page
  exists to answer is "how far has this build got".
- **AC3 — the actions are the last thing on the card and impossible to
  miss**: full-width buttons at ≥40px, in the same order the desktop offers
  them, showing exactly the same set for the same release state. Nothing is
  demoted to an overflow menu on the surface where acting is the point.
- **AC4 — the secondary facts earn their space or go.** Commit, item count
  and cut date collapse into one muted meta line (`8c5d3e3 · 1 item · cut
  29 Jul`), with the commit no longer competing with the version for the
  reader's attention.
- **AC5 — the two sections keep their headings.** "In flight" and "Finished"
  still separate the list, and each still says what it means; a card list
  without them is a pile.
- **AC6 — Cut release is reachable without scrolling past the list.** On a
  phone the primary action of the page sits at the top, not after every
  finished release.
- **AC7 — no horizontal scroll at 375px**, and no cell whose text is clipped
  to unreadability. This is the acceptance test for the whole story: if any
  part of a card needs a sideways gesture, it has not been solved.

## Out of scope

- Changing the release lifecycle, the gates, or which actions exist in which
  state.
- The release detail page (`/projects/{id}/releases/{releaseId}`) — a
  separate surface with its own layout problem.
- Adding a mobile-only action that desktop lacks.
