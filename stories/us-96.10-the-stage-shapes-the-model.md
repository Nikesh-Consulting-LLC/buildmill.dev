# US-96.10 — The stage shapes the model

**Status:** Testing
**Phase:** 96 — The type shapes the path
**Depends on:** — (nothing in this phase; it touches routing, not lifecycles)

## Story

As the manager, my model lineup froze a generation ago. The Anthropic picker
still suggests `claude-opus-4-8`; Claude Opus 5 shipped at the same price
($5/$25 per MTok) with a real capability step and its own separate rate-limit
pool, and nothing in the factory offers it. Meanwhile every stage rides
whatever single model the org default names, though the stages' economics
differ by an order of magnitude: a plan run that misfires burns a manager gate
*and* the code run that faithfully implements the bad plan, while a TLDR is
pure restatement that Haiku does at a fifth of Sonnet's price.

The lineup catches up, and each stage runs on the model its leverage deserves:

| Stage | Model | Effort |
|---|---|---|
| PRD draft (`prd_draft`) | `claude-opus-5` | `high` |
| Elaboration runs | `claude-sonnet-5` | `high` |
| Plan runs | `claude-opus-5` | `xhigh` |
| Code runs | `claude-opus-5`, fallback `claude-sonnet-5` | `xhigh` |
| `story_breakdown` | `claude-opus-5` | — |
| `content_tldr`, `work_item_tldr` | `claude-haiku-4-5` | — |
| `test_case_elaborate`, `learnings_merge` | `claude-sonnet-5` | — |

Thin routed functions carry no effort knob (effort belongs to presets / run
settings), hence the dashes. `xhigh` is already a legal preset effort
(`presets.EFFORTS`). Pricing note for the cost room: Sonnet 5's introductory
$2/$10 rate ends 2026-08-31, then $3/$15 — and its tokenizer counts ~30% more
tokens than the 4.6 generation for the same text, so per-token comparisons
against old baselines mislead.

## Acceptance criteria

- **AC1 — the picker offers the current generation.** In
  [providers-section.tsx](../apps/web/src/app/(app)/settings/llm-providers/providers-section.tsx)
  `MODEL_SUGGESTIONS.anthropic` becomes
  `["claude-opus-5", "claude-sonnet-5", "claude-haiku-4-5"]` —
  `claude-opus-5` in, `claude-opus-4-8` out. Suggestions only: existing org
  provider rows are data and stay untouched.
- **AC2 — the routing is applied, not just written.** The operating org's
  Anthropic provider row lists `claude-opus-5`, and the table above is applied
  through the surfaces the factory already has — `llm_function_routes` for the
  thin calls, presets / run settings for the worker runs (plan, code,
  elaboration, PRD draft). No new plumbing, no schema change, no migration.
- **AC3 — proof from the ledger.** After routing, one call or run of each
  stage lands in `llm_usage` naming the expected model — a TLDR row on
  `claude-haiku-4-5`, a plan run on `claude-opus-5`, an elaboration on
  `claude-sonnet-5` — recorded in this file before the story reaches Testing.
- **AC4 — the defaults stay sane.** The gateway's model fallthrough stays
  `claude-sonnet-5` ([llm_gateway.py:245](../apps/api/app/routers/llm_gateway.py)),
  and no code path hard-codes `claude-opus-4-8` as a suggestion or default
  afterwards (fixtures that use it as an arbitrary string are exempt — see out
  of scope).

  carries `claude-opus-4-8` anymore (the runner fixture and vendored
  litellm are exempt per out-of-scope).
- **AC2 partially in place already, remainder blocked from this session**:
  on the operating org (prod), the Anthropic provider row already lists
  `claude-opus-5` (and sonnet-5/haiku-4.5), and the run presets already
  carry the table's models — PRD/Plan/Code on `claude-opus-5`, Code
  falling back to `claude-sonnet-5`, PRD at effort `high`. What differs
  from the table: Plan and Code sit at effort `high` (table says `xhigh`),
  and every `llm_function_routes` row currently points at `grok-4.6` —
  the org's live routing choice. **This session's attempt to apply the
  table was blocked by the permission classifier** (a live rewrite of
  prod's operational routing is a manager decision, and honestly it should
  be). The exact change, ready to run at UAT (or click through Settings →
  LLM providers → routing):

  ```sql
  update public.agent_presets
  set settings = settings || '{"effort": "xhigh"}'::jsonb
  where org_id = '654d7ff1-ab30-4812-a1ff-c9588d91ad50' and name in ('Plan', 'Code');

  update public.llm_function_routes
  set provider_id = '85148548-10ac-488d-8805-d2f4c69e2835',
      model = case function_key
        when 'content_tldr' then 'claude-haiku-4-5'
        when 'work_item_tldr' then 'claude-haiku-4-5'
        when 'story_breakdown' then 'claude-opus-5'
        when 'test_case_elaborate' then 'claude-sonnet-5'
        when 'learnings_merge' then 'claude-sonnet-5'
        when 'prd_draft' then 'claude-opus-5'
      end
  where org_id = '654d7ff1-ab30-4812-a1ff-c9588d91ad50'
    and function_key in ('content_tldr','work_item_tldr','story_breakdown',
                         'test_case_elaborate','learnings_merge','prd_draft');
  ```

  Routes the table does **not** name (deploy_script_generate,
  plan_complexity_score, story_complexity_score) are deliberately left on
  the org's current choice. Elaboration runs carry no dedicated preset;
  they resolve to the provider default, which is already
  `claude-sonnet-5`.
- **AC3 for UAT**: the ledger proof needs real calls, which follow the
  routing being applied — after running the SQL above, one TLDR, one plan
  run and one elaboration should land in `llm_usage` naming
  haiku-4-5/opus-5/sonnet-5 respectively; record them here.

## Out of scope

- **`claude-fable-5` anywhere in the pipeline.** It costs 2× Opus 5, its
  safety classifiers can refuse a request mid-run (`stop_reason: "refusal"`)
  and the gateway has no refusal-fallback handling, and it requires 30-day
  data retention. Hand-escalating a single hard item to it stays possible;
  the factory never defaults to it.
- Per-stage routing *plumbing* — new tables, schema, or defaults machinery.
  The existing routes and presets carry the whole table.
- Preset templates: they deliberately carry no model id (only a `model_hint`
  advice string). Reviewing hint text that names the 4.x generation is
  superadmin data-entry, prompted at UAT, not code.
- Runner test fixtures that use old model ids as arbitrary strings
  ([test_progress_stream.py:28](../apps/runner/tests/test_progress_stream.py)).
- Non-Anthropic suggestion rows (OpenAI, Gemini, Groq, xAI, Ollama) — a
  separate sweep if ever requested.
