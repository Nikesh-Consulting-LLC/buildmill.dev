# US-83.2 — One session engine, two owners

**Status:** Testing
**Phase:** 83 — Interactive agent stability
**Dependencies:** none (us-83.1 first is build order, not a dependency)

## Story

As a manager opening a CLI-window session, I want the session to start with
real credentials through the exact machinery a run uses, so that the
conversation works the first time — and so that a fix to one path can never
again silently miss the other.

## Context

The runner has two copies of "open an ACP session":
`interactive._run_cli` (runs) and `session_host._open` (CLI-window sessions,
US-78.10). They have already drifted — the run path gained the handshake
trace line and the hard refusal when factory tools cannot be expressed; the
session path has neither, and its per-line `emit` *awaits* a control-socket
send inside the ACP notification handler, so a slow socket back-pressures the
agent's own read loop (the run path buffers through a sync sink).

Worse, the session path's credentials are a stub that has never worked:
`db.session_model_env` returns `{"model": "<id>"}` while `session_host._open`
expects the full gateway env (`GROK_MODELS_BASE_URL`, `GROK_XAI_API_BASE_URL`,
`BUILDMILL_GATEWAY_KEY`, `GROK_DEFAULT_MODEL`). No key is ever minted for a
session, the CLI would start credential-less, and the no-model refusal cannot
fire because it keys on `GROK_MODELS_BASE_URL`, which the stub never sets.
The docstring's claim — "same shape a run gets, minted the same way" — is
aspiration, not implementation. (Runs are correct: `env_provider` mints a
scoped key and `workloop.model_env(module="interactive")` builds the env,
refusing to start when the mint fails.)

This also owns the recorded Phase 78 gap: `llm_usage.session_id` has a column
and no writer, because no session-scoped credential exists to key usage on.

## Acceptance criteria

1. One shared open-session routine (spawn → `initialize` → handshake trace
   line → MCP translation → tools-refusal rule → `session/load`-or-`new` →
   LIVE registration) lives in one place and both `interactive._run_cli` and
   `session_host._open` call it. Tests pin parity: the handshake line and the
   inexpressible-tools refusal fire on BOTH paths.
2. `session.open` carries a real gateway env: the server mints a
   session-scoped key and sends the same env shape a run gets. The
   `session_model_env` stub is deleted. No credential, no session — the
   refusal wording matches the run path's "the agent was NOT started" rule.
3. Gateway calls made under a session key are metered with
   `llm_usage.session_id` set (closes Phase 78 known gap AC5).
4. Session narration cannot stall the agent: trace lines enqueue to a bounded
   buffer flushed by a separate task; overflow drops narration, never
   protocol traffic.
5. `python -m pytest` (runner) and api Essential both pass; the api-side
   session-open tests fake the mint the way run tests do, and pin the RPC and
   env-shape names so a stub cannot satisfy them again.

## Out of scope

- Promoting a session's work into a run/PR (us-78.10 AC4 deferral stands).
- Session liveness (crash watchdog, idle sweep) — us-83.3.
- Any web UI change.
