# US-98.1 — The factory learns a merge run

**Status:** New
**Phase:** 98 — Many branches, one landing
**Depends on:** nothing (Phase 96's instruction family is extended, not changed)

## Story

As the manager, work accumulates on branches faster than it lands. Several
work items finish, each on its own branch, and folding them into the default
branch is a job with real judgement in it — two agents touched the same file
and only a reader who understands both changes can say what the merged file
should be. That is agent work, and the factory has no kind for it.

This story adds the kind and nothing else: `merge` becomes a run the factory
can dispatch, route to a model, hand to a worker, and steer with its own
instruction text. The branches it operates on (us-98.2), the reading
(us-98.3), the hand-back (us-98.4) and the review (us-98.6) each land in
their own story. Splitting it this way is deliberate: adding a run kind has
a specific, repeatedly-fatal failure mode — a kind the database accepts but
the runner has never heard of leaves every such run sitting `queued` forever.
That has shipped three times, which is why
[test_runner_kind_coverage.py](../apps/api/tests/test_runner_kind_coverage.py)
exists. This story is the one that must not be half-done.

A merge run is dispatched on a **chore**. The chore keeps its single-shot
shape — there is no plan phase for a merge, exactly as there is none for a
chore's build.

## Acceptance criteria

- **AC1 — the run kind exists.** A migration widens `runs_kind_check` with
  `merge` (pattern:
  [185_draw_a_story.sql](../infra/supabase/migrations/185_draw_a_story.sql)
  L33-37), taking the set from ten kinds to eleven.

- **AC2 — the instruction kind exists, with default text.**
  `worker_instructions_run_kind_check` widens with `merge` (pattern:
  [257_every_kind_of_work_gets_its_own_words.sql](../infra/supabase/migrations/257_every_kind_of_work_gets_its_own_words.sql)
  L23-30), `baked_worker_instruction` gains a `merge` arm by **surgical
  append with a hash guard** — the 256/257 pattern that proves no existing
  kind's text moved — and `seed_worker_instructions` gains the value, with
  every existing project on both databases backfilled. The default text
  says what a merge run is for: read both sides of every conflict, decide
  from the code rather than from a rule about which side wins, and never
  drop a change you did not understand.

- **AC3 — `instruction_kind_for` passes it through.** `merge` is not in
  `('plan','code')`, so
  [257](../infra/supabase/migrations/257_every_kind_of_work_gets_its_own_words.sql)
  L132-155 already returns it unchanged and needs **no new arm**. That is
  an easy thing to break later, so it is pinned by a test rather than left
  to the reader.

- **AC4 — the runner can shape the hand-back.** `HANDBACK_SHAPE`
  ([cli_base.py](../apps/runner/supervisor/modules/cli_base.py) L62-73)
  gains a `merge` row, and `ROUTE_KINDS`
  ([runner_socket.py](../apps/api/app/routers/runner_socket.py) L771) gains
  `merge` so it can be model-routed. `test_runner_kind_coverage.py` — which
  pins `HANDBACK_SHAPE` against the database's own `runs_kind_check` — passes
  without being weakened.

- **AC5 — the web side stops lying about the kind set.**
  [run-kinds.ts](../apps/web/src/lib/run-kinds.ts) L17 currently lists
  **seven** kinds while the database allows ten — `guidelines`, `elaborate`
  and `wireframe` have been missing. It gains all four (the three stale ones
  and `merge`), and its `RUN_KIND_LABELS` and the separate
  `RUN_KIND_LABELS` in
  [instruction-preview.tsx](../apps/web/src/components/instruction-preview.tsx)
  L52 stop disagreeing — one export, one contents.

- **AC6 — the instruction editor names it.** `KIND_META`
  ([worker-instructions-tab.tsx](../apps/web/src/app/(app)/projects/[id]/worker-instructions-tab.tsx)
  L30-100) gains `merge` with a human name and a one-line "who receives
  this", and it is placed in a `SECTIONS` group rather than falling into the
  synthetic "Other" bucket. Reset-to-default rides the existing
  `default_worker_instruction` RPC unchanged.

- **AC7 — both projects, types, sweep, tests.** Migration applied to prod
  and dev, `database.types.ts` regenerated, embed sweep run. SQL tests pin
  the widened constraints, the new default's presence, and the
  `instruction_kind_for` passthrough. `npm run build` green; api Essential
  green; runner suite green.

## Out of scope

- The branch list, the dispatcher, and the refusals — us-98.2.
- Anything the agent reads or submits — us-98.3, us-98.4, us-98.5.
- The review surface and the merge method — us-98.6.
- Giving `merge` a `.buildmill/Merge.md` file — us-99.1 does that for every
  kind at once. Until then `merge` lives in `worker_instructions` like the
  other seventeen.
- Any new work-item **type**. A merge is dispatched on a chore; the type set
  stays `feature | bug | chore | story` as it has since
  [031_issues.sql](../infra/supabase/migrations/031_issues.sql) L49-50.
