# US-81.3 — UAT deployment triggers the suites

**Status:** Testing
**Phase:** 81 — Automated release testing
**Dependencies:** us-81.2

## Story

As a manager, I want every `run_on_uat` suite to run automatically the moment
a release lands on UAT — pinned to the release commit, against the release's
UAT deployment — so automated verification starts without anyone remembering
to start it.

## Acceptance criteria

1. When a release flips to `uat-deployed` (the success branch of
   `deploy.py`'s settle step), the factory fire-and-forgets a suite run for
   every active `run_on_uat` suite of the project: `commit_sha` =
   `releases.commit_sha`, `base_url` = the release UAT deployment's
   `website_url`, `release_id` set, `trigger='uat-deploy'`. No scheduler, no
   watcher — the hook is the settle function itself, the same precedent as
   release-prep firing the UAT deploy directly on submit.
2. The release page gains a **Suites** panel: one row per suite showing the
   latest run for this release — status, pass/fail totals, duration, a link
   to the live run view.
3. Per-suite re-run: `POST /api/v1/releases/{release_id}/suites/{suite_id}/rerun`,
   single-flight like any other run, available while the release is in
   `uat-deployed`.
4. A project with no declared suites behaves exactly as today — the panel
   simply doesn't render, and nothing else changes.
5. Suite runs never change the release status. They run *within*
   `uat-deployed`; what they mean for sign-off is us-81.4's business.

## Out of scope

- Gate/blocker changes and result-to-case mapping (us-81.4).
- Prod smoke (us-82.1).
- Re-running suites automatically when UAT is redeployed.

## Outcome

Built 2026-08-11. Both deploy pipelines' success branches call
`_launch_release_suites_if_any` right after `_settle_release_deploy` — a no-op
for ordinary runs, status-guarded (`uat-deployed` only) so a stray late
callback can't start suites on a cancelled release, exceptions swallowed so
the deploy's own outcome stands. The release page gained the **Automated
suites** panel (per-suite latest run, totals, link, advisory/gates badge) and
per-suite re-run (`POST /releases/{id}/suites/{suite_id}/rerun`, 409 while
in flight, refused off `uat-deployed`).

**Verified:** rerun endpoint tests (pins the release commit, refuses off-UAT);
build clean. **Not verified:** the trigger firing on a real release — rides
the next release's UAT deploy.
