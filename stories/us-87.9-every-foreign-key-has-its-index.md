# US-87.9 — Every foreign key has its index

**Status:** New
**Phase:** 87 — The app gets fast
**Depends on:** nothing

## Story

As the operator, Supabase's performance advisor returns **169 findings**
against prod, and they are the cheap, mechanical kind that compound quietly
as the workspace grows:

- **117 unindexed foreign keys** — worst on `documents` (5), `app_issues`
  (4), `clarifications` (4), `guideline_refreshes` (4), `issue_comments`
  (4), `runs` (4), `test_cases` (4). Each one turns a cascading delete or a
  parent-scoped filter into a sequential scan.
- **27 unused indexes** — write amplification with no read to pay for it.
- **1 duplicate index** — `projects_id_org_key` and `projects_id_org_unique`
  are identical.
- **3 `auth_rls_initplan` warnings** — `issue_comments`,
  `client_perf_events`, `user_activity_sessions` re-evaluate `auth.uid()`
  **per row** instead of once per query. A direct query over `pg_policies`
  finds 12 unwrapped `auth.*()` calls across 135 policies.
- **20 multiple-permissive-policies** — `app_issues` (10),
  `organization_members` (5), `profiles` (5). Postgres evaluates *every*
  permissive policy on every row.

None of this hurts at 63 work items. All of it hurts at 5,000.

## Acceptance criteria

- **AC1 — foreign keys are indexed where reads justify it.** Every one of
  the 117 is triaged: indexed, or explicitly declined with the reason (a
  tiny lookup table needs no index). The story carries the table, not a
  bare count. Indexes are created `CONCURRENTLY` so no migration takes a
  long lock on prod.
- **AC2 — dead indexes go.** The 27 unused indexes are dropped, except any
  that back a constraint or serve a query that has simply not run in the
  stats window — each exception named. The duplicate on `projects` is
  resolved to one.
- **AC3 — RLS evaluates once.** The 12 unwrapped `auth.uid()` /
  `auth.jwt()` calls are wrapped as `(select auth.uid())` so Postgres hoists
  them to an init-plan. Policy *semantics* are unchanged — a test proves
  cross-org isolation still holds on each touched table.
- **AC4 — overlapping policies are merged.** `app_issues`,
  `organization_members` and `profiles` each end with one permissive policy
  per role/action where the old set was a union of equivalents. Merging must
  not widen access; the story shows the before/after predicate for each.
- **AC5 — the advisor is re-run.** `get_advisors(type: performance)` after
  the change, with the remaining findings listed and justified. "169 → N,
  and here is why the N are fine."
- **AC6 — applied to both projects.** All migrations land in
  `infra/supabase/migrations/`, applied to **prod and dev**, with
  `database.types.ts` regenerated and `test_embed_ambiguity.py` swept.
- **AC7 — cross-org isolation re-verified.** The `*_sql.py` RLS tests run
  against a real database (`DATABASE_URL` set) for every table whose
  policies changed. This story edits policies; Essential alone does not
  cover it.

## Out of scope

- The composite index for the work-item hub's ordering — that ships with
  us-87.3, where the query it serves is defined.
- Security advisor findings — a separate concern with a separate story.
