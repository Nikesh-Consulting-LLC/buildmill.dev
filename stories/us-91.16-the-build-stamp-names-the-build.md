# US-91.16 — The build stamp names the build

**Status:** Completed
**Phase:** 91 — Usability: the dashboard reads like the job
**Depends on:** nothing

## Story

As the manager, the footer reads `Build: 2026.07.29.1 +463` and I cannot
tell from it whether I am looking at this morning's deploy or one from two
weeks ago. Every word of it is technically true and none of it answers the
question I asked.

`appVersion()` renders `git describe --tags --match "20*" --always`, stamped
into the gitignored `apps/web/VERSION` by the deploy workflows. So the string
means *"the newest version tag reachable from this commit, plus how many
commits of drift"* — a fact about **tags**, not about **this build**. Three
ways that misleads:

- **It goes stale without looking stale.** The string only changes when a
  new tag is reachable. Four deploys off the same tag produce four builds
  with an identical footer; the running build could be any of them.
- **It is now about to say nothing at all.** The repository was re-created on
  2026-08-13 and carries **zero tags**, so `--match "20*"` finds nothing and
  `--always` falls back to a bare SHA. `formatVersion` passes that through
  untouched, so the footer will read `Build: 0230b43` — unlabelled, and
  indistinguishable from a version to anyone reading it.
- **It has no time in it.** "When was this deployed" is the actual question
  behind every glance at that footer, and no part of the stamp answers it.

Stamp the facts that are always true — **the commit, and when it was
built** — and let the version name ride along when a tag exists to supply
one.

## Acceptance criteria

- **AC1 — the stamp carries commit and build time, always.** `apps/web/VERSION`
  becomes a small structured stamp (one JSON object, or newline-delimited
  `key=value`) with at minimum: `commit` (full SHA), `built_at` (ISO-8601
  UTC), `ref` (the branch deployed), and `version` (the `git describe`
  result, or empty when no tag matches). Commit and time come from the
  checkout and the clock, so they can never be missing.
- **AC2 — all three workflows stamp it identically.**
  [deploy-prod.yml](../.github/workflows/deploy-prod.yml),
  [deploy-uat.yml](../.github/workflows/deploy-uat.yml) and
  [uat-release.yml](../.github/workflows/uat-release.yml) write the same
  stamp the same way — one shared step, not three copies that drift.
  `uat-release.yml`'s release notes read from it rather than re-running
  `git describe`.
- **AC3 — the footer reads as a build, not a riddle.** Tagged:
  `Build: 2026.08.14.1 · 14 Aug 09:12`. Untagged: **`Build: 14 Aug 09:12`** —
  the time alone. **Amended after UAT:** the first cut printed
  `commit 0230b43 · …`, and a bare sha is noise to whoever reads a footer —
  it identifies the build only for someone already holding a list of shas,
  while the timestamp answers "is this today's" for everyone. The sha is not
  lost: it stays in the hover detail (AC4), which is where the person who
  needs it will look. Local: `dev`, as today.
- **AC4 — the full detail is one hover away.** A `title` (or a small
  popover) gives the full SHA, the branch, the exact UTC timestamp, and the
  drift count when there is a tag to drift from. The compact line stays
  compact.
- **AC5 — an untagged build never claims a version.** With no matching tag,
  no version-shaped string appears anywhere in the footer. This is the case
  the repository is in **right now**, so it is the case to build against —
  not the edge case.
- **AC6 — the API can be asked the same question.** The `api` service
  reports its own commit and build time on an existing unauthenticated
  endpoint (its health/docs surface), so "are web and api the same build"
  is answerable without SSH. Same stamp, same fields.
- **AC7 — the parser is tested.** Extend
  [app-version.test.ts](../apps/web/src/lib/app-version.test.ts) to cover:
  tagged with drift, tagged exactly, untagged (SHA only), missing stamp
  (`dev`), and a malformed stamp — which must degrade to `dev` rather than
  render a broken string. The existing `formatVersion` cases keep passing or
  are consciously replaced.
- **AC8 — the stamp stays out of git.** `apps/web/VERSION` remains
  gitignored and written only at deploy time. Nothing in the repo hard-codes
  a version.

## Out of scope

- Creating the missing `prod` branch or a baseline version tag — a
  repository operation, not a code change, and the manager's call to make.
- Changing the release version **scheme** (`YYYY.MM.DD.N`) or the cut →
  UAT → sign-off → promote lifecycle.
- Making Build Mill release *itself* through its own release pipeline
  (today's releases are for other projects; its own app ships by a
  `main → prod` merge).
- Surfacing build info anywhere beyond the footer and the API endpoint — no
  admin build page.

## Verified (2026-08-14, localhost against build-mill-dev)

- With no stamp present, the footer reads **`Build: dev`** — the local case,
  degrading rather than inventing a version.
- Eleven unit tests in `app-version.test.ts` cover the stamp: tagged with
  drift, tagged exactly, **untagged (time only, never version-shaped, sha
  still in the hover)**, missing, malformed, and the legacy bare-`git
  describe` string older builds carry.
- All three workflows write the same `key=value` stamp; `uat-release.yml` no
  longer re-derives its own.
- `/api/v1/health` reports `build_version`, `build_commit`, `build_ref` and
  `built_at` from the same file.

**Confirmed by the first deploy (2026-08-14):** the workflow stamped
`version=ba22e89 / commit=ba22e897… / ref=prod / built_at=2026-08-14T11:18:33Z`,
`/api/v1/health` reports the same, and — with the UAT amendment above — the
footer reads **`Build: Aug 14, 11:18 AM`**. The repository has no tags, so
this is the untagged path AC5 was written for, live.

**Second UAT note (2026-08-14, later):** the minute is noise too. The
footer now shows the build **date only** — `© 2026 Nikesh Consulting LLC.
(Build: Aug 14, 2026)` — pinned to en-US so the server render is the same
everywhere; the commit, branch and exact UTC timestamp remain one hover
away in the tooltip. Test amended to refuse a time of day in the compact
line.
