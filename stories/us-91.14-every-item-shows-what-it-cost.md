# US-91.14 — Every item shows what it cost

**Status:** Testing
**Phase:** 91 — Usability: the dashboard reads like the job
**Depends on:** [us-91.11](us-91.11-an-agents-work-is-measured-in-seconds.md) — for the per-item rollup only; the Completed column below needs nothing

## Story

As the manager, money spent by agents is visible in exactly two places I
never look while working: `/settings/spend` and the superadmin analytics.
On the surfaces where I actually make decisions — what the factory finished
this morning, and the list of work items I am about to dispatch more of —
the cost is invisible.

That is the wrong way round. A $0.30 story and a $14 story that both read
"Code submitted" are not the same event, and I should not have to open a run
page to tell them apart.

Two places, two different numbers, and the difference matters:

- **Things to Do → Completed** is a list of finished **runs**. Its number is
  what *that run* cost — `runs.cost_usd`, already recorded.
- **Work Items** is a list of **items**. Its number is what the item has
  cost so far: every run against it, added up.

## Acceptance criteria

- **AC1 — the Completed table gains a cost column.** In
  [dashboard-tabs.tsx](../apps/web/src/app/(app)/dashboard/dashboard-tabs.tsx),
  each row shows its run's `cost_usd`, carried through `CompletedItem` in
  [data.ts](../apps/web/src/app/(app)/dashboard/data.ts) — one more field on
  a query that already runs, no extra round trip.
- **AC2 — it follows the table's responsive rules.** The column hides below
  `lg` like Duration and Finished, and joins the existing subline at those
  widths (`3m 12s · 2h · $0.31`) so the fact survives where the column
  cannot fit (us-35.6).
- **AC3 — each work item shows its running total.** In the Work Items hub,
  every row shows what that item has cost across all of its runs — in the
  table lens as a column, in the outline lens on the item's meta line.
- **AC4 — the item's total is a stored rollup, not a per-row query.** A new
  `issues.cost_usd`, written in the same run-terminal transaction that
  us-91.11 establishes, and backfilled from existing runs by the same
  migration. The hub loads 200 items at a time; summing runs per row would
  be 200 queries or one that grows forever (us-87.1, us-87.10).
- **AC5 — a failed attempt still cost money.** The item total includes every
  run against it — failed, cancelled, abandoned, superseded by a retry — not
  only the run that merged. A story that took four attempts cost what four
  attempts cost, and hiding that is the one thing this number must not do.
  State it in the column's tooltip so nobody reads it as "the price of the
  merge".
- **AC6 — one formatter, and honest zeroes.** Use the shared `money()` from
  [budget.ts](../apps/web/src/lib/budget.ts), which already gives sub-dollar
  figures four decimals. **Null renders as `—`** (nothing has run yet), and
  a real zero renders as `$0.00` — those are different facts and must look
  different.
- **AC7 — the numbers agree with Spend.** For a given project and window,
  the sum of item costs reconciles with `/settings/spend` and with
  `llm_usage`. A fourth disagreeing dollar figure is worse than no figure
  (this is us-91.11 AC4's rule, applied at the item grain).
- **AC8 — the migration goes to both projects.** Written in
  `infra/supabase/migrations/`, applied to prod and dev, types regenerated,
  embed sweep run.

## Out of scope

- The board lens's cards, which are deliberately compact — table and outline
  only.
- Sorting or filtering by cost, and any cost-based alert or threshold.
- Converging the three local `money()` copies (`admin/analytics/runs`,
  `admin/usage`, `settings/spend`) onto the shared helper — worth doing,
  not here.
- Hours or tokens on these two surfaces; this story is dollars.
  (us-91.12 puts time and money together on the work-item page itself.)
- Per-role gating of cost visibility — cost is already visible to any member
  via `/settings/spend`, and this story does not change who may see it.

## Verified (2026-08-14, localhost against build-mill-dev)

- **Completed** gained a Cost column: `$11.07`, `$14.42`, and `—` where the run
  recorded no cost. The tablet-width sub-line carries it too.
- **Work Items** shows the item's running total: `$25.49` on US-2.1.1, matching
  the stored rollup (25.4892) — which is the sum of *three* runs against it,
  including the ones that did not merge.
- The rollup column and its backfill ride migration 252 (us-91.11).

**Found and fixed while verifying**: `toViewIssue` in `issue-view-types.ts`
rebuilds each row field by field, so adding the column to the select was not
enough — the mapper silently dropped it and the hub rendered no cost at all.
The column read correctly only after the mapper carried it.
