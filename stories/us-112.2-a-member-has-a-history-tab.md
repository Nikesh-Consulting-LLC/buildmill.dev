# US-112.2 — A member has a History tab

**Status:** Testing
**Phase:** 112 — The Team roster is a table
**Depends on:** us-112.1 (the roster table and its expand row), US-53.3 (the
expand panel), US-35.1 (hand-backs and voluntary releases), US-62.2 (the
per-agent read of us-62.1's run analytics)

## Story

As the manager, I want a member's history on its own tab, so that "what has
this agent been doing, and how well" is one question in one place rather than
two sections at the bottom of the longest tab.

## Design

**Recently done** and **Performance (last 30 days)** both lived at the foot of
Details, under About, Machine and Project access. They answer the same
question, and it was the last thing on the page. They move to a third tab,
**History**, beside Connect.

**"Recently done" becomes "Activity"** because the list was never only
done-ness: US-35.1 deliberately includes voluntary releases back to the pool,
which is the opposite of done, and an agent that keeps handing work back is
exactly what the section exists to show.

**Both lists become tables** for the reason the roster did: five hand-backs as
bordered cards, each with a stacked title and sub-line, is three lines of
chrome per row for two facts. Activity gets Work item / Outcome / Kind / When,
with the work item elastic and the rest `whitespace-nowrap`. Performance keeps
its five columns but moves onto the shared `ui/table.tsx` instead of a
hand-rolled `<table>`, so it inherits the same header, borders and overflow
behaviour as everything else.

**The expand panel is tinted to match its row.** At `bg-muted/20` the panel was
close enough to the page background to read as more page; the manager reported
it "blends with UI". Both the expanded row and the panel now carry
`bg-muted/50`, so the pair reads as one block. It is a token, so dark mode
lifts rather than darkens and the grouping survives.

## Acceptance criteria

- **AC1 — the tab exists.** A member's expand panel has three tabs: Details,
  Connect, **History**, in that order.
- **AC2 — both sections moved, neither duplicated.** Details no longer contains
  Recently done or Performance; History contains both, in that order. The data
  each reads is unchanged — the same runs + `run-released` events query, the
  same superadmin-gated `run-analytics` call.
- **AC3 — Activity is the name and a table.** Headed `Activity`, four columns
  (Work item, Outcome, Kind, When), the work item linking to the issue exactly
  as before and truncating rather than wrapping. Empty state unchanged:
  *"Nothing handed back yet."*
- **AC4 — Performance is on the shared table.** Same five columns and the same
  numbers, rendered with `ui/table.tsx`. Still hidden entirely for a
  non-agent, for a non-admin viewer, and for an agent with no runs in the
  window — never an error banner.
- **AC5 — the panel reads as part of its row.** The expanded row and its panel
  share `bg-muted/50`; collapsed rows are untinted. Verified in both light and
  dark.
- **AC6 — compact and full width.** Both tables use the panel's full width, with
  the elastic first column giving up space and the numeric columns
  right-aligned and `tabular-nums`.

## Verification (2026-08-17)

Rendered locally against `build-mill-dev` and looked at, unlike the two stories
before it:

- **AC1, AC3 (empty state), AC5** — confirmed on screen. The three tabs render
  in order; History shows `Activity` and *"Nothing handed back yet."*; the
  expanded row and panel compute to an identical background
  (`oklab(0.969998 … / 0.5)`) while collapsed rows are transparent. Checked in
  dark mode too — the tint lifts and the grouping still reads.
- **AC2, AC4, AC6** — code-verified and type-checked, **not seen populated.**
  No member of the dev workspace has any finished runs (the four principals
  that do are not org members there), so both tables only ever rendered their
  empty state. The populated layout uses the same `ui/table.tsx` primitives as
  the us-112.1 roster, which *was* verified populated across 50 rows — but that
  is an argument, not a screenshot.

**To close AC2/AC4/AC6 in UAT:** open a member on production who has handed
work back — the History tab is where Recently done used to be.

## Out of scope

- **What Details still holds** (About, Machine, Project access) — untouched.
- **The 5-item limit** on the activity list, and the 30-day window on
  Performance. Both are inherited as-is.
- **The superadmin gate** on `run-analytics` (US-62.2).
- **The standalone `/team/[principalId]` route** — `MemberDetail` has exactly
  one call site, the roster's expand panel, so there was no second surface to
  keep in step.
