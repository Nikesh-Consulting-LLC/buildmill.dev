# US-95.2 — Spend is a curve, not a number

**Status:** Testing
**Phase:** 95 — Cost management
**Depends on:** [us-95.1](us-95.1-cost-gets-its-own-room.md) — the section this renders in

## Story

As the manager, the breakdown answers "where did the money go" and nothing
answers "which way is it going". A 30-day total of $180 reads the same
whether spending is winding down or the last week alone was $150 of it — and
the difference is exactly what I open a cost page to learn.

Two additions, both basic: the window drawn as a daily curve, and the
window's total set against the window before it. Every figure is computed
from the same append-only `llm_usage` rows the breakdown reads — no counter
is introduced that could drift (us-91.11 AC4's rule: dollars have one
source).

## Acceptance criteria

- **AC1 — a daily spend series.** `/costs` gains a chart: one value per day
  over the chosen window, following the same window picker as the table.
  Aggregation happens server-side in one day-grouped query — the raw
  `llm_usage` rows never ship to the client (us-87.10's discipline; a
  90-day window over a busy org is tens of thousands of rows).
- **AC2 — the Today window hides the chart.** One day is not a curve.
  For the 7/30/90-day windows the chart renders; for Today it does not,
  and nothing apologises for it.
- **AC3 — the window is compared to the one before it.** The window's total
  spend renders beside the previous equal window's total (last 30 days vs
  the 30 before) with the delta as a signed percentage. When the previous
  window metered nothing, say "nothing to compare against" — never a
  percentage of zero.
- **AC4 — honest gaps.** A day with no metered calls draws as zero — that is
  a fact, not missing data. Unparsed calls in the window (real money the
  meter could not read, US-33.3) and subscription runs (off-meter by design,
  US-52.4) are named beside the chart exactly as the table names them; a
  trend of measured dollars must say when money is off the curve.
- **AC5 — the endpoint checks the gate.** The trend endpoint is new and only
  this section reads it, so unlike the shared breakdown endpoint it verifies
  `view_costs` server-side (us-95.1 AC3's grid), returning a refusal — not
  data — to a member without it.
- **AC6 — the numbers reconcile.** The series' sum equals the breakdown
  table's total for the same window, and a test pins it on a seeded fixture.
  Two dollar figures for the same window that disagree is worse than none.
- **AC7 — it fits a phone and both themes.** The chart is legible in light
  and dark, labels its axis in dollars, and at phone width fits or scrolls
  inside its own container — the page never scrolls horizontally (Phase 92's
  discipline).

## Out of scope

- Forecasting, projections, or "on pace to spend" arithmetic.
- Budget lines, thresholds, or alerts on the chart.
- Per-dimension stacked series (spend per project per day) — the curve is
  the org's one line; slicing it is us-95.4's filters applied to it.
- Hourly grain, custom date ranges, and CSV export.

## Verified (2026-08-14)

- `spend_trend` (db.py) + `GET /llm/orgs/{org}/spend-trend` built; the trend
  SQL was executed verbatim against the live dev database (parses, groups by
  UTC day with the in-window flag).
- Route tests (Essential): 403 with "owners and admins" for a member without
  `view_costs`; 200 for a holder with filters passed through.
- Unit tests pin: zero-filled series (N+1 calendar buckets), the previous
  window as one total with `None` when empty (never a percentage of zero),
  the cutoff-straddling day split by the flag, window clamped like the
  breakdown's, unparsed calls riding the series.
- `test_costs_spend_sql.py` (Full QA) pins series-sum == breakdown-total on
  a seeded fixture — **not run here** (no `DATABASE_URL` on this machine,
  as with us-91.11); it runs on a machine with the credential.
- **Not verified here, for UAT**: the rendered chart with real bars and the
  window-over-window line — the local API cannot start without
  `apps/api/.env`, so the browser showed the section without its data. The
  Today window hiding the chart is code-read only.
