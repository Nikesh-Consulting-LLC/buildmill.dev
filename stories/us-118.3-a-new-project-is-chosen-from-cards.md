# US-118.3 — A new project is chosen from cards

**Status:** Testing
**Phase:** 118 — A template shows its face
**Depends on:** US-118.1 (`TemplateCard`, `TemplateCover`, cover URL, inline
markdown), US-118.2 (org copies carry `category` and a cover the picker can
show), migration 227 (`default_project_org_template()` fills the org default
on insert), 266 (`seed_worker_instructions` seeds `agent_instructions` and
the worker instructions from the chosen template), `project-dialog.tsx`

Design reference: [docs/design/template-cards.html](../docs/design/template-cards.html)
— **Mockup A**, the New project dialog. Open it: the row scrolls, the arrows
step, the chips filter, the arrow keys move the selection.

## Story

As a member creating a project, I want to choose the template from a row of
cards — cover, name, and what it is for — instead of a select of names, so
that I pick the right starting point without opening Settings to find out
which "Web App" is which, and so that ignoring the choice still gives me the
org's default.

## Design

### What exists today

`project-dialog.tsx:63-78` fetches `id, name, is_default` from the org's
available, unarchived templates and renders a Base UI `Select` of
`name` / `name (Default)` (`:182-211`), with helper copy that still says the
template seeds *guidelines* — it seeds `agent_instructions` and the worker
instructions since 265/266. Nothing tells the three templates apart.

### The dialog, widened, template first

Create mode only (`!isEdit`) — Edit project keeps its width and has no
template section:

- `DialogContent className="sm:max-w-3xl"`; the form order becomes
  **Start from a template** → **Name** (autofocus) → **GitHub repository**.
  Templates come first because they answer "what kind of thing is this?";
  Name gets focus because that is what most people came to type.
- The section is a **single horizontal row** of `TemplateCard
  variant="card"`, 210px wide each, `snap-x snap-mandatory` with `snap-start`
  cards, scrollbar hidden. At the dialog's width three cards are in view and
  the **edge of a fourth peeks** — that peek is the "there's more" cue. On a
  phone one card and a peek. Wheel, trackpad, touch and drag all work because
  it is native scroll — no carousel library.
- **Prev / Next** buttons (`Button variant="outline" size="icon"`, round)
  overlay the row's left and right edges, step one screenful, and are hidden
  at the respective end; a soft **fade** at each edge shows while there is
  more that way; **page dots** under the row (one per screenful, hidden when
  everything fits) say where you are.
- The **org's default is preselected** (else the first); the selected card
  has the primary ring and a check on its cover; the choice **never blocks**
  — a person who does not care types a name, picks a repo, and gets what
  they get today.
- **Category chips** (`All` plus one per distinct category, `aria-pressed`
  toggles) appear **only when two or more categories** exist among the
  available templates and narrow the row (scroll resets to the start). A
  **filter box** (name / description substring) appears **only past six
  templates**. Filtering never changes the selection: the line under the row
  always reads *Selected: **{name}** — seeds this project's Agent
  Instructions and worker instructions from the template; editable
  afterward.* — so a selection hidden by a filter is still stated, and the
  stale "guidelines" copy goes.
- The row is a **radio group**: `role="radiogroup"` labelled by the section
  label, each card `role="radio"` / `aria-checked`, roving `tabindex`;
  **←/→ (and ↑/↓)** move the selection *and slide it fully into view*,
  Space/Enter pick, focus ring is the app's. Cover images are decorative
  (`alt=""`); the name is the accessible label. Clicking a partly visible
  card selects it and slides it fully in.
- **Empty org** (no available, unarchived templates): the section is hidden,
  exactly as today; if the member has `manage_project` (the projects page
  passes `canManageTemplates` from `loadOrgCapabilities`) a one-line
  pointer shows instead: *No project templates yet — add one under
  [Settings → Project templates].*
- The fetch becomes `id, name, description, category, image_path,
  updated_at, is_default` (`is_available`, unarchived, ordered `is_default
  desc, sort_order, name`); the insert is unchanged
  (`org_template_id: templateId`).

### The layout gotcha, named so it is not rediscovered

The row lives inside `grid`-laid-out form fields inside a `grid` dialog. A
flex scroller in that chain **widens the dialog to its content instead of
scrolling** unless the chain can shrink: the row's wrapper needs
`grid-cols-[minmax(0,1fr)]` / `min-w-0`, and the scroller `min-w-0`. The
mockup hit exactly this. A padded scroller (`p-[3px] -m-[3px]`) keeps the
focus ring from being clipped by `overflow-x`.

### Pure logic, tested

`apps/web/src/lib/template-picker.ts`: `defaultTemplateId(templates)`,
`showCategoryChips(templates)` (≥ 2 distinct non-empty categories),
`showFilterBox(templates)` (> 6), `filterTemplates(templates, category,
query)`, `categoriesOf(templates)` (distinct, ordered as first seen) — with a
`.test.ts` beside it. The component composes these; the rules are not in
JSX.

### Docs

`interface-catalog.md`'s `/projects` row says the create dialog chooses a
template from a card row.

## Acceptance criteria

1. On `/projects` → **New project**, the dialog is wider (`sm:max-w-3xl`),
   the first section is **Start from a template**, then Name (focused on
   open), then GitHub repository. **Edit project** is unchanged.
2. The section is one horizontal row of cards: 2:1 cover (image or generated),
   name, Default badge, description clamped to three lines. With the dev
   org's three templates the row fits without scrolling and shows no arrows,
   dots or chips.
3. With seven or more templates (seed extra org copies to test): three cards
   are fully in view and a fourth peeks; **Next** steps a screenful and
   **Prev** appears; at the end **Next** hides; the fade shows on the side
   that has more; page dots count the screenfuls and mark the current one;
   the mouse wheel and a trackpad swipe scroll the row and cards snap.
4. The org's default template is preselected on open (the first if none is
   marked); the selected card carries the primary ring and a check on its
   cover; creating without touching the row links `org_template_id` to it —
   the project's Overview then reads *Created from template: X*.
5. With ≥ 2 distinct categories, chips `All · <category>…` show above the
   row; pressing one narrows the row to that category and resets scroll to
   the start; with a single category no chips render. Past six templates a
   filter box appears; typing narrows by name or description; below seven it
   does not render.
6. Filtering does not change the selection: after filtering the selected
   template out of view, the line under the row still reads *Selected:
   **{its name}** — seeds this project's Agent Instructions and worker
   instructions from the template; editable afterward.* The word
   "guidelines" no longer appears in the dialog.
7. Keyboard: Tab reaches the selected card; → moves the selection to the
   next card and slides it fully into view (including from the third card to
   the peeking fourth); ← moves back; Space picks; the focus ring is fully
   visible on the outermost cards, not clipped.
8. Clicking the peeking card selects it and slides it fully into view.
9. At 375px wide the row shows one card and a peek and still scrolls; the
   dialog does not scroll horizontally, and neither does the page at any
   width — the row never widens the dialog.
10. An org with no available templates: no section (as today); a member with
    `manage_project` sees the one-line pointer with a working link to
    `/settings/project-templates`; a member without it sees nothing.
11. `template-picker.test.ts` covers the default choice (marked default;
    first when none; empty), the chip threshold (0, 1, 2 categories; empty
    strings ignored), the filter-box threshold (6 vs 7), and
    `filterTemplates` by category, by query on name and on description, and
    combined. `npm run test:web` and `npm run build` are clean.
12. `interface-catalog.md`'s `/projects` row is updated.

## Out of scope

- **A "start blank" card.** `default_project_org_template()` applies the
  org's default on insert, so "no template" is not a real state today; making
  it one is a different decision.
- **A `/projects/new` page or a two-step wizard.** The escape hatch if a
  catalog outgrows a dialog; the row keeps the dialog's height constant at
  any count, which is what made a page unnecessary now.
- **Change template on a project** — US-118.4 (compact rows; that dialog is
  a narrow vertical list already).
- **Template details on hover / a full-description popover.** The three
  lines plus the settings page are enough; if descriptions grow, this is
  the next thing to add.
- **Remembering the last-used template per member.** The org default is the
  right preselection until someone asks otherwise.
