# US-89.1 — One secret, one home

**Status:** Testing
**Phase:** 89 — The zero-secret workspace
**Depends on:** US-10.3 (zero-secret machines / LLM gateway — the pattern), US-31.9 (per-run MCP config), US-27.9 (token reissue), migration 219 (gitproxy credential fixes)

## Story

As the operator, the slot's worker token lives in exactly one place — the
slot's env file, written by provisioning, readable only by the slot's own
user — and **nothing else on the machine ever contains it**: not a git
remote URL, not a file inside the repo checkout, not a helper script, not
an audit row. Everything that needs the factory authenticates through the
supervisor, which holds the token in memory and injects it at the moment
of use. The machine is trusted (it is Buildmill-managed); the failures
come from *copies* — so the design removes the copies instead of adding
guards around them.

## What broke, and why this fixes it

Two days of evidence (2026-08-12/13):

- The token rode the git remote URL → it sat in `.git/config` and appeared
  verbatim in `runner_command_audit` output.
- The token was written into `.factory-mcp.json` in the working tree, then
  translated into `.grok/config.toml` and `.grok/mcp_call.py` → an agent
  submitted them and the factory committed the token into the project
  repo (rotation required; FACTORY_SCRATCH widened after the fact).
- Agents hand-edited stale tokens into helper scripts when MCP failed.
- The write-then-delete dance left `D`/`M` noise in every git status and
  depends on `finally` blocks running.
- Rotation touches many copies; a missed one is a random breakage later.

Every one of these is a copy. With one home and a broker, each vector is
not guarded — it is *gone*.

## The design

1. **Git: a credential helper, not an embedded URL.** Remotes are clean
   (`https://api.buildmill.dev/git/<org>/<slug>.git`). Provisioning
   installs a machine-wide git credential helper that answers with the
   slot env's token at fetch/push time. `.git/config` holds no secret,
   audit argv holds no secret, and rotation needs no workspace touched —
   the next git call reads the new env.
2. **Factory MCP: a loopback broker in the supervisor.** The supervisor
   listens on `127.0.0.1:<per-slot port>` and forwards `/factory` (and the
   tool-server proxy paths) to the API, injecting `X-Worker-Token` from
   memory. Workspace MCP configs point at loopback and carry, at most, a
   **machine-local session key** minted at agent start — worthless off the
   box, so a committed config is noise, not a leak. (Per-slot isolation on
   shared pools: the loopback key is minted per slot; a sibling slot's
   user cannot use another's broker without it.)
3. **The env file is the only durable home.** Reissue (US-27.9) rewrites
   one file and restarts one service — nothing else exists to chase. The
   `.grok/mcp_call.py`-style helper scripts either disappear or call the
   loopback broker credential-free.
4. **The scratch guard stays, demoted to a belt.** Committing a config
   file becomes harmless; the guard now only keeps noise out of PRs.

## Acceptance criteria

- **AC1 — clean remotes.** After checkout, `git remote -v` and
  `.git/config` contain no token; fetch and push work through the helper;
  `runner_command_audit` rows for git commands contain no `sfw_` material
  (asserted by test against the recorded argv).
- **AC2 — secret-free workspace.** No file under the workspace root ever
  contains the worker token: the per-run/session MCP config carries only
  loopback URLs and the machine-local key. The write-then-delete dance and
  its git-status noise are gone.
- **AC3 — broker equivalence.** Factory MCP calls, proxied tool-server
  calls, and gitproxy operations behave byte-identically through the
  broker — same tools, same refusals, same audit — proven by the existing
  MCP/gitproxy test surfaces pointed at the broker.
- **AC4 — rotation is one file.** Reissue rewrites the env, restarts the
  slot, and every path (git, MCP, gateway mint) works immediately after —
  no workspace edit, no helper edit, no cache flush. The old token is dead
  at the gitproxy within its existing revocation window.
- **AC5 — shared-pool isolation.** On a multi-slot machine, slot A's user
  cannot drive slot B's broker (per-slot key or socket ownership), pinned
  by a test.
- **AC6 — compatibility.** The API changes nothing about token semantics;
  a not-yet-updated machine keeps working exactly as today (the broker is
  runner-side; old bundles keep the old behavior until their next Update).

## Out of scope

- Scheduled/automatic rotation (worth its own story once rotation is
  one-file cheap).
- Per-run short-lived worker tokens (the broker makes them unnecessary for
  the leak problem; revisit only if machines stop being trusted).
- The LLM gateway path — already zero-secret.

## Verification record

Built 2026-08-13 on `us-89-zero-secret-workspace`. No migration, no API
change — runner-side only; reaches machines on their next Update.

**Verified (runner suite 309 passed, incl. 8 new):**
- Git: `clean_url` strips userinfo; a fresh clone rides
  `clone --config credential.helper=…` with a clean URL; an existing
  (pre-89.1) repo gets its remote scrubbed and the helper configured; no
  `worker:`/token material in any recorded argv (`test_gitwork_credentials`).
  The helper reads `FACTORY_WORKER_TOKEN` from the process env at git
  time, so the CLI agent's own `git push` inside a run authenticates the
  same way and rotation needs no workspace touched (AC1/AC4).
- Broker: end-to-end relay against a fake upstream — token injected
  broker-side from the env, path mapped to `/mcp`, JSON relayed back;
  wrong local key → 403 before any forward; unknown path → 404
  (`test_mcp_broker`, AC5's key isolation included).
- Config: with the broker up, `mcpconfig.build` emits
  `http://127.0.0.1:<port>/factory` + the machine-local key and the body
  provably contains no token; without a broker it falls back to the
  legacy shape byte-for-byte (AC2/AC6). One build body feeds every
  consumer (CLI argv, grok toml, ACP session list) so all three are
  covered by construction.

**Not verified (UAT):** a live session/run on the pool after the machine's
next Update — the probe is: open a session, run a factory MCP tool, then
`git -C <workspace> config credential.helper` shows the helper and
`git remote -v` shows a clean URL; `.factory-mcp.json` (if present
mid-run) contains no `sfw_` material.
