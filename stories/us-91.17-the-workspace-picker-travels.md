# US-91.17 — The workspace picker travels, and says when it's switching

**Status:** Completed
**Phase:** 91 — Usability: the dashboard reads like the job
**Depends on:** nothing

## Story

Two things the manager found while testing Phase 91 on a phone.

**There is no way to change workspace on mobile.** `OrgSwitcher` lives in
`AppSidebar`, and the sidebar is `hidden md:flex` — so below `md` it does not
exist. Every page in the app is scoped to the active workspace, which makes
this the one control a phone cannot do without: pick the wrong one and
nothing else on the screen is about the right thing.

**And switching looks like nothing happening.** The switch writes
`principals.active_org_id` and then re-renders every org-scoped surface, which
takes a beat. The only feedback was a spinner on the trigger — inside a
dropdown that has already closed by the time the work starts. So a slow
switch reads as a dead click, and the manager clicks again.

## Acceptance criteria

- **AC1 — the picker is in the mobile drawer.** `MobileNav` renders
  `OrgSwitcher` as the first thing in the drawer, above the nav entries,
  because every entry below it is scoped by that choice. It appears under the
  same condition as on desktop: only when the person belongs to more than one
  workspace.
- **AC2 — one component, not two.** The drawer reuses `OrgSwitcher` rather
  than growing a second implementation that can drift from it.
- **AC3 — switching says so.** While a switch is in flight, an overlay reads
  **"Switching workspace to <name>…"** with a spinner, over the whole
  viewport, so it is visible wherever the click came from.
- **AC4 — it clears when the app has actually switched**, not when the write
  returns. The overlay lifts when the server comes back reporting the new
  `activeOrgId` — clearing on the write's response would drop the curtain a
  second early, onto the old workspace's data.
- **AC5 — a stuck switch is not a locked app.** If the new state never
  arrives, the overlay gives up after 15 seconds and lets the manager try
  again, rather than leaving the app behind a permanent curtain.
- **AC6 — nothing changes for a single-workspace user.** No picker, no
  overlay, no extra query — exactly as today.

## Out of scope

- Changing how the active workspace is stored, or how pages resolve it.
- A workspace picker anywhere other than the sidebar and the drawer.
- Making the switch itself faster; this makes it legible.

## Verified (2026-08-14, localhost against build-mill-dev)

- At 375×812 the drawer opens with **Nikesh Consulting LLC** at the top,
  above Things to Do — the control that did not exist on mobile before.
- Selecting the other workspace showed **"Switching workspace to Nikesh
  Consulting LLC…"** within the first 50ms sample, and it was gone once the
  new workspace's data was on screen.
- The desktop sidebar picker is unchanged and shares the same component.
