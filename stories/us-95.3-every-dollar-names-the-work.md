# US-95.3 — Every dollar names the work that bought it

**Status:** Testing
**Phase:** 95 — Cost management
**Depends on:** [us-95.1](us-95.1-cost-gets-its-own-room.md) — the section this extends

## Story

As the manager, the breakdown groups by project, agent, provider, and model —
the infrastructure's axes. My questions are work-shaped: what do bugs cost me
compared to features? Which epic is eating the budget? What did this one item
cost across everything that touched it?

The attribution chain already exists and nothing walks it: a `llm_usage` row
carries `run_id`, the run carries `issue_id`, and the issue carries `type`
(feature / bug / chore / story) and `epic_id`. Three new dimensions on the
same one-grain breakdown (US-33.3's shape: groupable over a window, not new
reports) — and an honest bucket for the money that cannot be walked to an
item, because a breakdown that silently drops rows claims a completeness it
does not have.

## Acceptance criteria

- **AC1 — three new group-bys.** `/costs` gains **Type**, **Epic**, and
  **Work item** beside the existing four, added to `SPEND_DIMENSIONS` and
  resolved in `spend_breakdown` ([db.py](../apps/api/app/db.py)) by joining
  through the usage row's run to its issue — server-side, one query, same
  200-row cap ordered by cost as today.
- **AC2 — labels read as work, not ids.** Type rows say "Feature", "Bug",
  "Chore", "Story". An epic row says `E4 — <title>` and carries its
  project's name (epic `number` repeats across projects; a bare "E4" from
  two projects would collapse two epics into one row). A work-item row shows
  the item's display id and title.
- **AC3 — the unattributable is a named bucket, never dropped and never
  guessed.** Usage with no `run_id` (session calls), and usage whose run has
  no single work item (a batch run's ledger rows do not say which of its
  `run_items` a given call served), land in one "not attributable to a work
  item" row with the reason in its tooltip. No splitting, no pro-rating —
  a guessed attribution is worse than a named gap.
- **AC4 — every grouping sums to the same total.** Type rows + the
  unattributable bucket = the window's total; likewise Epic and Work item.
  If grouping by type shows less money than grouping by project, rows were
  dropped somewhere. A test pins this on a seeded fixture that includes a
  session call, a batch run, and a normal run.
- **AC5 — the Work item grain agrees with us-91.14.** For an item whose runs
  are all metered, the Work item row's cost reconciles with the
  `issues.cost_usd` rollup the Work Items hub shows. Where they legitimately
  differ — subscription runs are off-meter here but their `runs.cost_usd`
  may be null there; unparsed calls contribute nothing — the difference is
  explainable by those named exclusions, and the test states which. Two
  silently disagreeing dollar figures for the same item is the one outcome
  this story must not produce.
- **AC6 — route tests are Essential.** The new dimensions get route tests
  with faked reads (no network, per the suite split); the reconciliation
  fixture test may be Full QA if it needs Postgres.

## Out of scope

- Filters on these dimensions ("bugs only, by project") — us-95.4.
- Showing cost on the epic's or work item's own pages — us-91.14 covered
  the item surfaces; an epic page cost line is a story for whenever epics
  get a page worth the name.
- Re-attributing batch-run spend by splitting it across the batch's items.
- Any new column on `llm_usage` — attribution is resolved by join at read
  time; the ledger stays append-only and unwidened.

## Verified (2026-08-14)

- The type-dimension query ran verbatim against the **live dev database**
  and answered real money: stories $351.95, unattributable $228.56, chores
  $131.64, bugs $105.72, features $32.48 over 90 days — the work-shaped
  answer this story exists for, including the named bucket.
- Unit tests (Essential) pin: the three dimensions walk run → issue with
  LEFT joins only, the infrastructure dimensions still skip the join, the
  null-key bucket is labelled "Not attributable to a work item" (work dims)
  vs "unattributed" (infra dims), epic labels carry number + title +
  project, item labels use the US-x.y display id with title fallback.
- `test_costs_spend_sql.py` (Full QA) pins AC4 (every grouping sums to the
  same total on the story's exact fixture: normal run, batch run, session
  call) and AC5 (item grain agrees with the `issues.cost_usd` rollup at
  $1.50) — **not run here** (no `DATABASE_URL`); runs on a machine with
  the credential.
- **Found and fixed while building**: the breakdown had ordered rows by
  `order by 4` — which meant cost when written, until US-38.1 inserted the
  two cache columns at positions 4–5 and silently made it "order by cache
  reads". Rows order by cost again (position 6), pinned by a regression
  test.
- **Not verified here, for UAT**: the three group-bys rendered with data in
  the browser (local API cannot start without `apps/api/.env`).
