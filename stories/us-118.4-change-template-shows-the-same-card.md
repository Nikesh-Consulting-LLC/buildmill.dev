# US-118.4 — Change template shows the same card

**Status:** Testing
**Phase:** 118 — A template shows its face
**Depends on:** US-118.1 (`TemplateCard variant="row"`, `TemplateThumb`,
inline markdown), US-114.3 (a project knows its template; the Change
template dialog and its plan banner), `change-template-dialog.tsx`,
`projects/[id]/page.tsx`

Design reference: [docs/design/template-cards.html](../docs/design/template-cards.html)
— Mockup C, right-hand column (the compact rows).

## Story

As a member switching a project's template, I want the Change template
dialog to show each template's cover and one line of what it is for — the
same card I chose from when the project was created — so that the choice
reads the same everywhere and I am not back to telling templates apart by
name and file count.

## Design

### What exists today

`change-template-dialog.tsx:184-213` already renders each org template as a
`<button>` card: name, mono `template_key` (or `custom`), Default badge, and
on the right *current* or `{fileCount} of {total} files`. Its
`OrgTemplateOption` (`:32-39`) carries no description or image. The Overview
tab prints *Created from template: {name}* as a bare muted line
(`page.tsx:514-518`).

### The rows become the shared row card

Each option becomes `TemplateCard variant="row"`: 72px 2:1 thumb (image or
generated), name + key badge + Default, one line of description in inline
markdown, and the existing right-hand `meta` (*current* / `n of N files`).
Behaviour is untouched — the current template is listed but disabled, the
chosen row carries the ring, the amber plan banner and the *Replace all
files* / *Files already match — link template* buttons are exactly as
US-114.3 left them. The dialog stays a vertical list; it is narrow
(`sm:max-w-lg`) and a scrolling `max-h-72` list is right for it — the
carousel is the New project dialog's answer, not this one's.

The fetch adds `description, image_path, updated_at` to what the page
already loads for the switchable templates.

### The Overview line gets the thumb

*Created from template: X* gains a `TemplateThumb` (20px) before the name —
the one visual tie between a project and the card it started from. Nothing
else on the Overview moves.

### Docs

`interface-catalog.md`'s `/projects/[id]?tab=instructions` row (the template
banner, Reset to template, Change template) notes that Change template
shows the template's cover and description.

## Acceptance criteria

1. **Change template** lists each org template as a row: thumb (or generated
   cover), name, key badge (`custom` when none), Default badge, one line of
   description (bold/code rendered, no block structure), and *current* or
   `n of N files` on the right — the same numbers as before.
2. The current template's row is disabled and reads *current*; choosing
   another row shows the ring on it and the plan banner with the same
   overwrite / clear / unchanged counts as before; **Replace all files** and
   **Files already match — link template** behave exactly as US-114.3.
3. A template with no description shows the row with an empty second line
   collapsed — no placeholder text, no layout jump.
4. On the project's **Overview**, *Created from template: X* shows the
   template's thumb before the name; a template with no image shows the
   generated cover at that size.
5. `npm run build` clean; the existing US-114.3 verification steps for the
   dialog still pass by hand (open, choose, banner, apply).
6. `interface-catalog.md`'s Instructions-tab row is updated.

## Out of scope

- **A carousel here.** The dialog is a narrow vertical list by design.
- **Choosing a template from the Instructions tab's banner** or anywhere
  new — this story re-skins the two places that already show a template.
- **Description or cover on the *Reset to template* banner.** The banner
  names the template; the dialog is where one is chosen.
