# US-82.1 — Post-go-live smoke on production

**Status:** Testing
**Phase:** 82 — Smoke, conversion, selection
**Dependencies:** us-81.4

## Story

As a manager, I want a prod-safe subset of suites to run against production
right after a release is confirmed live, so "nothing broke" is observed
within minutes of go-live instead of discovered by users.

## Acceptance criteria

1. When a release is confirmed released (`confirm-released` — the one point
   both prod-deploy paths converge on an observed successful prod deploy),
   the factory launches every active `run_on_prod` suite against the
   project's prod deployment: pinned commit, `trigger='prod-promote'`,
   `release_id` set.
2. The release page gains a **Production smoke** panel mirroring the UAT
   suites panel, plus per-suite re-run.
3. A failed/errored/timed-out prod run notifies through the project's
   notification endpoints and shows a red banner on the release page naming
   the failing run.
4. The banner offers a one-click handoff to the **existing** rollback action
   (rollback run + mark rolled-back). The release stays `released`; a human
   decides. Auto-rollback is explicitly not built — a flaky browser test
   must never revert production.
5. The Suites settings UI labels `run_on_prod` with a prod-safety warning:
   these tests run against live production data and must be read-only /
   non-mutating. The factory cannot verify that; the label puts the burden
   where it lives.

## Out of scope

- Auto-rollback of any kind.
- Scheduled/synthetic monitoring — this runs once per release confirmation,
  not on a timer.
- Verifying prod-safety of specs.

## Outcome

Built 2026-08-11. `confirm-released` launches every `run_on_prod` suite
(`trigger='prod-promote'`, pinned commit, released-status-guarded) after the
flip — fire-and-forget, a smoke verdict can never fail the confirmation. The
release page shows the **Production smoke** panel once released, with re-run;
a non-passing run paints the card red with a banner pointing at the failing
run and at the existing "Mark rolled back" action — the release stays
`released`, the human decides (the handoff is a pointer to the action, not a
wired click-through into its dialog). The suite dialog labels `run_on_prod`
with the prod-safety warning (read-only tests, asserted by the manager, not
verifiable by the factory).

**Verified:** build + Essential green; the trigger's status guard is shared
with (and tested via) the rerun path. **Not verified:** smoke on a real
production release.
