# US-81.1 — A project declares its test suites

**Status:** Testing
**Phase:** 81 — Automated release testing
**Dependencies:** none

## Story

As a manager, I want to declare a project's automated test suites — a name, a
layer, a command, and where the results land — so the factory has a configured
place to run tests from, instead of testing being whatever a person remembers
to do.

## Context

Today the factory has no concept of an automated suite. `test_cases` are
five-field prose rows a human reads and marks; release verification is one
`curl`. This story adds the *declarations only* — the vocabulary the rest of
Phase 81 executes. A suite is org config, like a deployment: the definition
lives in the factory DB, the spec files it runs live in the project's repo so
they pin with the release commit.

## Acceptance criteria

1. New `test_suites` table, org/project-scoped with the standard member RLS
   pattern: `name` (unique per project), `layer` in `api|browser`,
   `run_command` (a `/bin/sh -e` script, the same contract as
   `deployments.script`), `results_path` (JUnit XML, default
   `test-results/junit.xml`, relative to the checkout), `server_id` (nullable —
   null means "run on the target deployment's server"), `run_on_uat` default
   true, `run_on_prod` default false, `blocks_signoff` default **false**,
   `timeout_minutes` default 30, `status` in `active|archived`.
2. `test_cases` gains `execution` in `manual|automated` (default `manual`),
   `suite_id` (nullable FK), `spec_ref` (nullable text — the stable JUnit
   identity: a pytest nodeid, or Playwright's `file::title`), and
   `always_on_uat` (default false — the person-flagged "this always runs on
   UAT" mark).
3. Project settings gains a **Suites** section: list, create, edit, archive.
   Plain CRUD through Supabase RLS from the browser (build-less-API rule);
   no new API endpoints.
4. The `/tests` library shows automated cases with a badge (suite name +
   `spec_ref`) and can filter by execution.
5. Cross-org isolation is verified for the new table (RLS test in the
   `*_sql.py` flavor).
6. Nothing executes. Declaring a suite changes no behavior anywhere else yet.

## Out of scope

- Running anything (us-81.2), triggers (us-81.3), the sign-off gate (us-81.4).
- Authoring automated cases from plans (us-81.5).
- Any module/area taxonomy (Phase 82).
