# US-96.2 — A bug explains itself before the fix

**Status:** New
**Phase:** 96 — The type shapes the path
**Depends on:** us-96.1 (the type branch in `dispatch_kind_for` / `dispatch_issue` lands there)

## Story

As the manager, a bug's first run today produces an "implementation plan" —
files to touch, approach, risks — because that is what the plan
instructions ask every type for. But what I need to approve on a bug is a
diagnosis: **what broke, why, and what the fix will be — in plain
language**, not detailed code. Approving a fix for a cause nobody has named
is how the same bug comes back wearing a different symptom.

A bug's think-first phase becomes a **root cause analysis**. Mechanically it
reuses the plan machinery whole — same `plan` run kind, same
`plan`/`test_plan` artifact kinds, same `planning`/`plan-review`/`planned`
statuses, same claim/lease/submit/send-back paths — because the state
machine stays shared (decided 2026-08-14). What changes is the words the
worker receives and the shape of what comes back: an RCA the manager can
read without being a programmer, whose approval unlocks the fix run.

## Acceptance criteria

- **AC1 — the RCA is the plan artifact.** A bug's think-first run stays
  `kind = 'plan'` end to end; no new `runs.kind`, artifact kind, or
  `issues.status` value. The submitted plan artifact for a bug carries
  exactly these sections: `## What broke`, `## Root cause`, `## Evidence`,
  `## Proposed fix`, `## Blast radius`.
- **AC2 — plain language, pinned in the instructions.** The migration adds
  two instruction kinds to `worker_instructions` with factory defaults in
  `default_worker_instruction`: `bug_rca` — written for a human manager;
  name files and functions when needed, but **no diffs, no patches, no code
  blocks** — the proposed fix is described in words; and `bug_fix` —
  implement the approved RCA's proposed fix, keep the diff minimal, protect
  against regression. Seeding trigger updated, every project backfilled.
- **AC3 — resolution by type.** A bug's `plan`-kind run resolves the
  `bug_rca` text and its `code`-kind run resolves `bug_fix`, at both call
  sites (`get_worker_instruction` at context-serve,
  `seed_issue_instructions` at dispatch). Stories keep `plan`/`code`
  untouched.
- **AC4 — the repro becomes the regression case.** The `bug_rca` default
  demands the companion test plan carry the reproduction steps as at least
  one test case; approving the RCA (`POST /issues/{id}/plan/approve`,
  `approve_plan`) materializes them into `test_cases` exactly as today — a
  bug that reaches its fix run has a regression case attached, through
  machinery this story does not touch.
- **AC5 — the gate reads like an RCA.** On the review surface
  ([plan-review-actions.tsx](../apps/web/src/app/(app)/review/%5BissueId%5D/plan-review-actions.tsx))
  a bug-type issue titles the artifact "Root cause analysis" and the
  approve action "Approve RCA"; send-back keeps its required comment. The
  deeper per-type redesign is us-96.5 — this AC is only the words on the
  gate that must not lie.
- **AC6 — approval unlocks the fix; every recovery path holds.**
  `planned` → dispatch creates the `code`-kind fix run with the approved
  RCA riding the context's existing `plan` slot; a sent-back RCA re-runs
  with the send-back comment; a rejected fix (`needs-fixes`, approved RCA
  surviving) redispatches the fix with the rejection feedback; a failed RCA
  run re-runs the RCA. All four pinned by tests.
- **AC7 — the reference stays true, the migration goes to both projects.**
  [docs/application/lifecycles.md](../docs/application/lifecycles.md) notes
  the type-aware meaning of the plan phase; migration applied to prod and
  dev, types regenerated, embed sweep run.
- **AC8 — tests.** SQL tests pin the instruction resolution mapping and the
  new defaults; an Essential route test pins that a bug dispatch from
  `draft` still creates a `plan`-kind run (the lifecycle is unchanged — only
  the words are).

## Out of scope

- New `runs.kind`, artifact kinds, or status values — deliberately reused.
- Status *labels* per type ("Analyzing", "RCA review") on workbench rows and
  stage trackers — us-96.5.
- Auto-verifying the fix against the repro — test execution stays the
  manual machinery it is.
- The standalone-story instruction split and the Settings editor for the
  grown instruction family — us-96.3.
