# US-91.7 — Reports are Bug Reports, and they live under Activity

**Status:** Completed
**Phase:** 91 — Usability: the dashboard reads like the job
**Depends on:** nothing

## Story

As the manager, **Reports** sits fourth in the sidebar, between Testing and
Release, where it reads like an analytics surface — the place I would go for
charts. It is not: it is what deployed apps have reported about themselves
(us-16.6), which is to say bugs, waiting to be triaged and promoted into work
items.

Two fixes, both naming: call it **Bug Reports**, and move it down beside
**Activity**, the other surface that answers "what has happened out there"
rather than "what am I building". The delivery surfaces at the top —
Things to Do, Work Items, Testing, Release — stay a clean run of the pipeline
in order.

## Acceptance criteria

- **AC1 — the nav entry reads "Bug Reports".** In
  [nav-items.ts](../apps/web/src/components/nav-items.ts), the `/reports`
  entry's label changes. Its icon (`MessageSquareWarning`) is unchanged.
- **AC2 — it sits directly below Activity, as a sibling.** Sidebar order in
  the first group becomes: Things to Do, Work Items, Testing, Release,
  Activity, Bug Reports. It stays a top-level link — **not** a child of
  Activity — so it is still one click away.
- **AC3 — the mobile drawer matches.** Both surfaces render from
  `NAV_ITEMS`; verify the drawer shows the same label in the same position,
  and that the active-route highlight still lands on Bug Reports when the
  page is `/reports`.
- **AC4 — the page agrees with the nav.** The `/reports` page header title
  reads **Bug Reports**, and its description still says what arrives there.
  A nav label and a page title that disagree is how a manager wonders
  whether they clicked the wrong thing.
- **AC5 — the route does not move.** The path stays `/reports`. Every
  existing link into it — the work-item page's origin-report section, the
  superadmin system-issues console, the agent-failures console — keeps
  working untouched.

## Out of scope

- Any change to what the page shows, its triage flow, or the promote dialog.
- Renaming the `reports` table, its API routes, or anything an agent reads.
- Reordering the Configure group, or the admin submenu.

## Verified (2026-08-14, localhost against build-mill-dev)

- Sidebar order is now: Things to Do, Work Items, Testing, Release, Activity,
  **Bug Reports**, then the Configure group.
- The page header at `/reports` reads **Bug Reports**; the route is unchanged,
  so every existing link into it still works.
