# US-119.3 — Costs loads in one round trip

**Status:** Testing
**Phase:** 119 — The API answers while the runners poll
**Depends on:** us-119.1 (the API answers in its own time — without it one
call still waits ~1.3 s, and this story alone takes the page from ~4–10 s to
~2 s, not to sub-second), us-95.1 (the `view_costs` gate), us-95.2 (the
trend), us-95.3/95.4 (dimensions, filters, the URL), us-102.2 (the KPI band
and `/work-summary`), US-52.4 (subscription runs are named, never lumped),
us-91.11 AC4 (one source of dollars), us-104.2 (the endpoint catalog and its
auth-boundary layer)

## Story

As the manager, I want Costs to ask once and show what it has, so that the
page paints in the time one aggregate takes and a filter click narrows the
figures on screen instead of blanking them.

## Design

### What the page does today (`costs-view.tsx:143-203`)

On mount, in this order:

1. projects and workers for the filter menus — two browser → Supabase reads
   (in parallel; fine).
2. `load()`: **`await`** a browser → Supabase count of subscription-billed
   runs, and only then
3. three API calls in a `Promise.all` — `/spend`, `/spend-trend`,
   `/work-summary` — each preceded by its own CORS preflight through the
   Cloudflare tunnel, each doing its own JWT verify, its own PostgREST
   capability RPC and its own connection lease;
4. `setData/setTrend/setSummary` together, after **all three** land — so the
   page shows "Loading spend…" for as long as the slowest call takes
   (`/spend` p95 9.4 s), and
5. every control change repeats 2–4 and drops the table back to the loading
   line meanwhile.

Four network round trips, one of them serial, gated on the maximum — for
figures that are 153 rows in the database.

### The change

1. **One endpoint answers the page.**
   `GET /api/v1/llm/orgs/{org_id}/costs?group_by&days&project_id&worker_id&item_type`
   returns `{ breakdown, trend, summary, subscription_runs }`: `breakdown` is
   exactly `/spend`'s body, `trend` exactly `/spend-trend`'s (`null` when
   `days = 1`, as the page hides the curve then), `summary` exactly
   `/work-summary`'s, and `subscription_runs` the US-52.4 count the page
   used to fetch itself. One `view_costs` check (`_require_view_costs`),
   one `asyncio.to_thread` that runs the three existing `db` functions and
   the count. The three existing endpoints stay — the project card and the
   agent page read `/spend`, and their member-read gate is theirs.
2. **The page fires it immediately** — no serial `await` in front, no
   separate Supabase count. Filter options still load once per org, in
   parallel, as today.
3. **A refetch never blanks, and never paints stale.** On a control change
   the current figures stay on screen, dimmed with an "updating…" hint,
   until the new slice lands; only the very first load shows "Loading
   spend…". Each request carries a sequence number and the previous one is
   aborted (`AbortController`); a response that is not the latest is
   dropped, so a fast click after a slow one can never paint the slow one's
   figures over the fast one's. An error keeps the last good figures and
   shows the message beside them (today it does this for `error` but the
   loading branch still hides the table).
4. Tokens and cost in the KPI band keep reading `breakdown.totals` — one
   source of dollars (us-91.11 AC4) is unchanged by putting the four answers
   in one envelope.

### What this costs

- **A fourth endpoint composing three.** Two ways to get the same numbers.
  Drift is unlikely — `/costs` calls the same `db` functions and returns
  their bodies verbatim — but the auth-boundary catalog and the route tests
  grow by one.
- **Not faster server-side.** The three aggregates run sequentially in one
  thread instead of in parallel across three requests; total server time is
  the same or slightly more. The win is client-side — one preflight, one
  auth check, one lease, no serial count — and it is bounded by 119.1.
- **A second of mismatch.** Between a click and its response, the figures on
  screen belong to the previous slice. The dimming and the "updating…"
  hint are the honesty about that; the sequence check is what stops it
  becoming a wrong answer.
- **Still one browser hop.** First paint waits on the client request; the
  server-side initial fetch that would remove it is out of scope.

## Acceptance criteria

- **AC1 — one endpoint, same figures.** `GET …/costs` returns the four keys
  above; each equals what the corresponding separate read returns for the
  same parameters (`breakdown` ≡ `/spend`, `trend` ≡ `/spend-trend` or
  `null` for `days=1`, `summary` ≡ `/work-summary`, `subscription_runs` ≡
  the org-scoped count of runs with `billing = 'subscription'` created
  inside the window). Gated by `view_costs`: 403 "Costs is visible to owners
  and admins" to a member without it. Pinned by route tests with reads
  faked, including the 403 and the `days=1` null.
- **AC2 — the page asks once per slice.** On mount and on every control
  change the view makes exactly one API request and no Supabase count. Every
  figure the page shows — six tiles, curve, comparison, table, the
  subscription line — comes from that response.
- **AC3 — no blank on refetch.** Changing window, filter or dimension keeps
  the current figures visible (dimmed, "updating…") until the new slice
  lands; the loading line appears only before the first response. An error
  during a refetch keeps the last good figures and shows the message.
- **AC4 — never stale over fresh.** Requests are sequenced and the previous
  in-flight one aborted; a response that is not the latest is dropped.
  Pinned by a web test of the sequencing helper (an older response arriving
  after a newer one does not update state).
- **AC5 — one source of dollars.** The KPI band's *Tokens spent* and *Total
  cost* read `breakdown.totals`, and the table's Total row shows the same
  numbers.
- **AC6 — measured, on prod, the day after release.** p50 of
  `/llm/orgs/{org_id}/costs` under **600 ms** in `api_request_log`, and the
  page's data phase — from mount to figures on screen — is one request in
  the browser's network panel (screenshot in the verification record).
- **AC7 — Essential; the URL contract untouched.** Route tests in the ~30 s
  suite; `costs-url.test.ts` still passes — the parameters and their
  encoding do not change.
- **AC8 — the endpoint catalog knows it.** `scripts/testing/endpoints.json`
  regenerated so the auth-boundary layer (us-104.2) covers `/costs`.

## Out of scope

- **Server-side initial fetch** in `page.tsx` (would remove the preflight
  and the browser → tunnel hop from first paint). Needs the user's token
  forwarded from the server component and a decision about caching; a
  follow-up once this story is measured.
- **A Postgres RPC replacing the API** for spend — US-33.3 put spend in the
  API and the `view_costs` gate lives there; not reopened here.
- **Server-side caching** of a slice — the data is tiny; the cost was never
  computing it.
- **Retiring `/spend`, `/spend-trend`, `/work-summary`** — other surfaces
  and other gates.
- **`Access-Control-Max-Age`** — the preflight cache is per URL, so a filter
  change would preflight anyway; one request per slice makes it moot.
