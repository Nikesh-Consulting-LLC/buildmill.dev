# US-91.10 — SuperAdmin is four menus, not one drawer

**Status:** Completed
**Phase:** 91 — Usability: the dashboard reads like the job
**Depends on:** nothing (touches the same file as [us-91.7](us-91.7-reports-are-bug-reports-and-live-under-activity.md) — sequence them)

## Story

As the platform admin, everything superadmin lives behind one disclosure
labelled **SuperAdmin**. Opening it drops fifteen links into the sidebar in
four inline heading groups (us-62.11 grouped them, which helped, but did not
shorten the list). Every visit costs the same two steps — open the drawer,
then find the row — and while it is open it pushes the rest of the nav off
screen.

Promote the groups. SuperAdmin becomes a section heading, like **Configure**,
with four entries under it: **Machines** as a plain link, and **Accounts**,
**Settings** and **Logs** as their own submenus that open independently. The
nav's existing machinery already does all of this — a `NavEntry` may be a
heading, and a `NavItem` may carry children — so this is a restructuring of
[nav-items.ts](../apps/web/src/components/nav-items.ts), not new navigation
code.

## Acceptance criteria

- **AC1 — the shape.** Under a non-clickable `SuperAdmin` section heading,
  in this order:

  | Entry | Kind | Children |
  |---|---|---|
  | Machines | link → `/admin/machines` | — |
  | Accounts | submenu | Orgs, Users, Roles |
  | Settings | submenu | How agents run, Preset templates, Presets, Prompt templates, Project templates |
  | Logs | submenu | System issues, Agent failures, Usage, Task runs, People, Performance |

- **AC2 — every link survives, and none moves.** All fifteen of today's
  `ADMIN_ITEMS` destinations appear exactly once, at unchanged paths. No page
  is renamed and no route changes; the inline `{ heading }` entries inside
  the old flat list are gone, replaced by the menus themselves.
- **AC3 — `/admin` leaves the nav but not the app.** The SuperAdmin landing
  page stays reachable by URL and by any existing link to it; it simply no
  longer owns a sidebar row.
- **AC4 — each menu opens independently, and remembers nothing it shouldn't.**
  Accounts, Settings and Logs each toggle on their own, using the existing
  per-item disclosure state in
  [app-sidebar.tsx](../apps/web/src/components/app-sidebar.tsx). A menu
  containing the current route starts open, as Settings does today.
- **AC5 — the parent highlights for any child route.** The sidebar's active
  test is `pathname.startsWith(entry.href)`, which worked when the parent
  was `/admin` and prefixed everything. With parents at `/admin/orgs` etc.,
  `/admin/users` would leave Accounts unhighlighted — so the parent must
  read as active when **any** of its children match. Fix it in the sidebar,
  not by inventing parent paths that don't exist.
- **AC6 — the collapsed sidebar still works.** Collapsed, an entry with
  children renders as a bare icon linking to its `href`. Each of the four
  gets a distinct icon and a `title`, and its `href` points at a real page
  (Accounts → `/admin/orgs`, Settings → its first child, Logs →
  `/admin/system-issues`) — never a route that 404s.
- **AC7 — the mobile drawer matches.**
  [mobile-nav.tsx](../apps/web/src/components/mobile-nav.tsx) renders the
  same structure from the same source; verify the four menus and the heading
  there too.
- **AC8 — non-superadmins see nothing new.** The whole block is still
  appended only when `isSuperadmin`. Confirm an ordinary member's sidebar is
  byte-identical to before.

## Out of scope

- Renaming, merging or building any admin page. "Logs" is a menu label over
  existing pages, not a new log viewer — Usage and the three analytics pages
  keep their own titles and content.
- The org-level **Settings** menu (`SETTINGS_ITEMS`), which is a different
  entry for a different audience and keeps its items.
- Nesting deeper than one level, or per-menu icons on the child links.
- Any permission change — what a superadmin can reach is unchanged.

## Verified (2026-08-14, localhost against build-mill-dev)

Switching to the platform-admin workspace, the sidebar renders a **SuperAdmin**
section heading followed by:

| Entry | Children |
|---|---|
| Machines | (link → `/admin/machines`) |
| Accounts | Orgs, Users, Roles |
| Settings | How agents run, Preset templates, Presets, Prompt templates, Project templates |
| Logs | System issues, Agent failures, Usage, Task runs, People, Performance |

All fifteen destinations present at unchanged paths. On `/admin/users`,
**Accounts opens automatically and Users carries the highlight** — the
child-aware active test (AC5) works; the old `startsWith(parent.href)` would
have left it unhighlighted.
