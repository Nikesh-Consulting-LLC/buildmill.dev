# US-112.1 — The Team roster is a table

**Status:** Testing
**Phase:** 112 — The Team roster is a table
**Depends on:** us-109.1 (what the row keeps vs what moved to the expand
panel), US-53.3 (the expand panel itself), us-107.3 (the four capability
icons), US-68.6 (the stacked layout below `sm`, which fixed a real squeeze
bug), US-91.12 (the per-agent effort figures)

## Story

As the manager, I want the roster to be a table with aligned columns, so that I
can compare members down a column instead of hunting the same fact at a
different horizontal position on every row.

## Design

### What is wrong with it

The roster is a list of bordered cards. Inside each, a flex row with
`justify-between` and `flex-wrap`, and a left-hand `flex-col` stacking up to
three lines: the name line, the seat subline, and the effort line
([team-view.tsx:591](../apps/web/src/app/(app)/team/team-view.tsx:591)).

Two costs:

- **Nothing aligns.** Every field's x-position is decided by the width of the
  content to its left, so "Pod-001 slot 9" sits somewhere different on every
  row, and the eye cannot run down a column. The gaps this leaves are large and
  say nothing.
- **Up to three lines per member**, for facts that are each a few characters
  wide. A roster of fifteen agents is forty-odd lines tall for perhaps two
  screens' worth of actual content.

us-109.1 already did the subtractive half of this — the module, token count,
join date and output figures went to the expand panel. What is left is not too
much *content*; it is content in the wrong shape.

### The shape

A real table, reusing `components/ui/table.tsx` (already the pattern on five
admin consoles), one row per member:

| Column | Holds | Align |
|---|---|---|
| **Member** | kind icon, name, `AGENT` / `SUSPENDED` badges | left, flexible — the only elastic column |
| **Does** | the four capability icons, greyed where absent (us-107.3) | left, fixed |
| **Status** | online/offline pill, plus the health pill when not healthy | left, fixed |
| **Seat** | `Pod-001 slot 9`, truncating | left, fixed |
| **Worked** | `4h 52m` | right — a number, read by magnitude |
| **Done** | `6` | right |
| **State** | `Idle` / `Working`, with elapsed when working | left, fixed |
| **Role** | the role select | left, fixed |
| **Actions** | the icon buttons and the expand chevron | right, fixed |

Splitting `4h 52m worked · 6 completed` into two right-aligned numeric columns
is the point of the exercise: as one prose string it cannot be compared down
the list, and comparing agents is what the figures are for. The header supplies
the words "Worked" and "Done" once, so the row does not repeat them fifteen
times.

A person's row leaves Does / Status / Seat / Worked / Done / State empty rather
than showing zeroes — us-109.1's rule, unchanged: `user_activity_sessions`
measures something else and must not be rendered as if it were the same.

### Two things a table must not break

- **The expand panel** (US-53.3) stays. It becomes a second `<tr>` with a
  full-width `colSpan` cell, revealed by the same chevron.
- **Narrow screens.** US-68.6 stacked this layout below `sm` to fix the name
  being the only thing willing to give up width against a cluster of
  never-shrinking buttons. A table would re-create exactly that bug. So the
  table applies at `sm` and up; below it, the existing stacked presentation
  stays as-is. This is a real branch, not a media query on a `<table>`.

## Acceptance criteria

- **AC1 — it is a table with a header.** At `sm` and up the roster renders as
  `components/ui/table.tsx` with the nine columns above and a header row naming
  them. Column positions are identical on every row, so any field can be read
  down the list.
- **AC2 — one line per member.** No member occupies more than one row when
  collapsed. The seat and effort sublines are columns, not stacked lines.
- **AC3 — the numbers are comparable.** `Worked` and `Done` are separate,
  right-aligned columns with the units in the header, not a `·`-joined prose
  string in the cell.
- **AC4 — a person's row is blank where a person has no answer.** No zeroes, no
  em-dashes standing in for measurements that were never taken.
- **AC5 — expanding still works.** The chevron opens the us-109.1 / US-53.3
  panel beneath the member's row, spanning the full table width, with the same
  contents as today. Expanding one member does not disturb another's columns.
- **AC6 — below `sm`, nothing regresses.** The stacked layout US-68.6
  introduced still renders below `sm`, with the name still able to shrink
  against the button cluster. Checked at 375px as well as desktop.
- **AC7 — nothing is lost or invented.** Every fact on today's row appears in
  exactly one column; no new field is added and none is dropped. The status,
  health, suspended and capability renderings are the existing components, not
  re-implementations.
- **AC8 — proven.** `npm run build` and `npm run lint` clean, and the page is
  screenshotted at desktop and 375px against a roster containing at least one
  person and one agent.

## Verification (2026-08-17, branch `phase-111-112-team-and-wizard`)

**Verified:** `npm run build` clean (compile + TypeScript). `npm run lint` 0
errors and the same 103 warnings as before. `npm run test:web` 248 pass.

**How the two shells avoid drifting.** `cellsFor(m)` computes every cell's
contents once; the table and the below-`sm` card both render from it. There is
one source for what a cell contains and two for where it sits, which is the
only split that does not rot.

**Not verified — and for this story that matters more than most.** This is a
layout change and **no one has looked at it.** No `apps/web/.env.local` exists
here and the file is covered by a permission rule, so the page could not be
rendered, screenshotted, or checked at 375px. AC8 asked for exactly those
screenshots and they do not exist. What is proven is that it compiles, that the
types line up, and that no cell content was re-implemented — every piece is the
existing JSX, moved.

**Treat AC1–AC6 as unverified until someone loads /team.** The likely failure
modes, in order: the nine columns overflow on a narrow laptop and the container
scrolls (acceptable, but check); the `max-w-0` Member cell truncates harder
than intended; the expand panel's `colSpan` row picks up hover styling it
should not.

## Out of scope

- **What the expand panel contains** (us-109.1 settled it).
- **Sorting, filtering or column choice.** A sortable roster is a real feature
  and a separate story; this one makes the columns exist.
- **The KPI tiles** — removed 2026-08-17, and not coming back here.
- **The Connect / other tabs** on the Team page.
- **`user_activity_sessions`** and whether a person should ever show effort
  figures (us-91.11 AC6).

## Open question for the manager

**Nine columns is a lot for a narrow laptop.** `Seat` and `State` are the two
most droppable — `Seat` already appears in the expand panel, and `State` is
partly readable from the Status pill plus the orange busy icon. Say the word
and either moves out; the story as written keeps both, because losing a fact
without being asked is how the row got crowded in the first place.
