# US-88.1 — The CLI window looks like a CLI, and its text keeps its shape

**Status:** Testing
**Phase:** 88 — The agent window reads like a terminal
**Depends on:** us-78.10 (an agent's CLI window), us-83.2 (one session engine, two owners)

## Story

As the manager, the one screen where I watch an agent think and type back to
it — the CLI window on an agent — does not read like a command line and, worse,
is hard to read at all.

Two separate faults, and they compound:

**It does not look like a terminal.** The console is a light card with a
grey paragraph per event. The app already has a terminal look — the server
terminal (`servers/[id]/terminal`) is near-black, mono, with a thin chrome bar
— and this window, which is the *agent's* terminal, borrows none of it. Every
event kind (a thought, a tool call, a plan, an error, my own prompt) is a
`<p>` distinguishable only by a subtle colour, so a 40-line session is a wall
with no scannable structure and no way to tell who said what.

**The agent's words arrive mangled.** ACP streams the agent's message and
thought chunks token by token. Each chunk is stripped, run through a clipper
that collapses *all* whitespace (`" ".join(text.split())`), and then the chunks
are rejoined with a space. The result is text no one wrote:

    The user ran ` / doctor ` which is typically a health check command .
    # Doctor report ## Overall : mostly healthy , with two issues

Every newline in the agent's markdown is gone, so a structured report becomes
one unbroken smear; and every punctuation-only token gains a space on both
sides. The chunks are consecutive slices of one string — the only correct
joiner is nothing at all.

The fix belongs together: styling a smear still shows a smear.

## Acceptance criteria

- **AC1 — chunks are rejoined verbatim.** Consecutive `agent_message_chunk` /
  `agent_thought_chunk` slices are concatenated with no inserted separator, and
  the whitespace inside a chunk survives — newlines included. `"Hello"` +
  `" world"` is `"Hello world"`, never `"Hello  world"`; `"command"` + `"."` is
  `"command."`, never `"command ."`.
- **AC2 — a multi-line answer stays multi-line.** An agent answer containing
  `\n` reaches `run_trace` with those newlines intact. The whitespace-collapsing
  clipper stays exactly as it is for one-line progress notes (the stdout
  scrapers in `progress.py` depend on it); the streamed-text path gets its own
  clipper that only clips.
- **AC3 — the console is a terminal.** The CLI window renders on the same dark
  surface as the server terminal (`#0a0a0a`, `border-white/10`, mono), not a
  light card, and it does not change with the app's light/dark theme — a
  terminal is a terminal.
- **AC4 — every line says what kind of line it is.** Each event carries a
  gutter glyph and an ANSI-ish colour that identify it at a glance without
  reading it: the agent's speech, its thinking, a tool call, a plan/decision, an
  error, a progress note, and the manager's own typed line — seven visibly
  distinct kinds. Wrapped lines hang-indent past the gutter so the glyph column
  stays a column.
- **AC5 — the manager's line is not the agent's.** What the manager types is
  echoed as a prompt line (`❯`), visually separate from anything the agent said.
  It is the one line the console renders that did not come from the server, and
  it must not read as if the agent said it.
- **AC6 — the prompt is a prompt.** The input is a bare shell prompt on the
  terminal surface — glyph, transparent field, mono caret — not a bordered form
  control, and Send/Stop are terminal chrome. Disabled state still says why
  (read-only run).
- **AC7 — status is legible at a glance.** The chrome bar names the agent and
  shows connecting / attached-and-steerable / attached-read-only / disconnected
  with a status dot, in that mono chrome.
- **AC8 — scrollback is usable.** The console follows the tail only while the
  view is already at the bottom; scrolling up to read while the agent streams
  no longer yanks the view back down.
- **AC9 — nothing else regresses.** The run page's trace card and the server
  terminal are untouched; the runner test suite passes and `npm run build` is
  clean.
- **AC10 — markdown is rendered, the way a terminal renders it.** _(added
  2026-08-13, manager's review of the first build: "doesn't look like it
  respects markdown".)_ Content the agent **wrote** — its speech and its
  thinking — renders as markdown: headings bold, `**strong**` strong, tables as
  tables, fenced code framed, lists bulleted, backticked spans tinted. Not as
  web prose: the console's own 12px mono scale and thin rules, fixed to the
  terminal palette, no theme-following tokens, and **no image is fetched** —
  a console streaming untrusted agent output does not make a network request
  because a line of that output asked it to. Lines the *runner* composed (tool
  calls, plan counters, progress notes, the manager's own typed line) stay raw,
  because an asterisk in a file path is an asterisk. The parser is the app's
  (`react-markdown` + `remark-gfm`), so what the console understands and what
  the run page understands cannot diverge.
- **AC11 — a block arrives whole.** _(added with AC10 — it is what makes AC10
  possible.)_ The coalescer cuts a row at a line ending whenever one is
  available, and its ceiling is a block (4000 chars) rather than a line (400).
  Half a table row is not half a table, it is no table at all — and the old
  ceiling cut mid-word besides. Nothing is dropped at the boundary: the
  remainder carries into the next row instead of being clipped away, so an
  agent that streams nothing and sends one large answer is split, never
  truncated.

- **AC12 — the window is the screen.** _(added 2026-08-13, manager's second
  review.)_ On the agent's own CLI page, the console fills the height it is
  given from first paint — no heading, no explanatory paragraph, and no
  starting-small-then-growing as output arrives. What those two lines said
  moves into the chrome bar, which already had room: `live session`,
  `working now`, `last session · read only`, `no session`. The console keeps
  its bounded size everywhere else (on the run page it is one card among
  many and must not eat the page), and at any viewport the prompt stays on
  screen with the transcript scrolling inside the frame — the page itself
  never scrolls.

- **AC13 — the working-out folds, and says it is still working.** _(added
  2026-08-13, manager's third review: "all the thinking items clog the view …
  when it's working show a thinking animation and keep all the thinking inner
  messages collapsed".)_ Consecutive rows of the agent *working* — thinking,
  tool calls, permission notices, progress — collapse into a single grey line,
  collapsed by default, titled by the **newest** row in the fold so it reads as
  a live status rather than a stale one, and expandable in place. Runs of one
  fold too: a lone thought is a paragraph that wraps to four lines between two
  sentences of the answer. What is *addressed to the manager* never folds — the
  agent's speech, an error, and the manager's own line. While the fold is the
  tail of an attached session, its star turns; once the agent speaks, the answer
  is the tail and the fold above it is history. A fold the manager opens stays
  open as it grows.

## Out of scope

- xterm. This is a stream of typed ACP events, not a PTY — the decision in
  US-78.8 stands.
- Merging rows the coalescer already split. A long live answer still arrives as
  several markdown blocks; each is whole, and that reads as streaming.
- Multi-line input (Shift+Enter). One turn, one line, as today.
- The Start session / Close session panels around the console.

**Not verified (UAT):**

- **Not seen against a live agent.** The trace was a stub. AC1, AC2 and AC11 have
  never been observed end-to-end from a real ACP stream — and they cannot be
  from a deploy alone: `events.py` runs on the **operator's own machine**, so
  the mangled text keeps arriving until that runner is restarted. The web half
  ships with the release; the text half ships with the restart. **Markdown
  rendering depends on it too**: nothing can be made of `# Doctor report ##
  Overall :` on one line, so AC10 will look like it did nothing until the
  runner restarts.
- AC8's scroll-pinning was implemented and reviewed but not exercised in the
  browser — the harness content never grew tall enough to scroll.
