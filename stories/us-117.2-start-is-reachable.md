# US-117.2 — Start is reachable

**Status:** Testing
**Phase:** 117 — A transient fault reads as transient
**Depends on:** us-116.5 (the Start/Stop control this fixes), us-116.4 (the
nine-word status vocabulary), us-112.1 (the roster table the control sits in)

## Story

As the manager, I want Start offered whenever an agent is stopped, so that the
agents most likely to need starting are not the ones the button refuses to
offer it for.

## Design

### The bug

`team-view.tsx` decided which half of the toggle to render with:

```ts
const agentStopped = agentState === "stopped";
```

`agentState` is one of **nine** words (`offline`, `revoked`, `working`,
`stopped`, `no-roles`, `no-model`, `no-grants`, `queue-held`, `ready`). Every
one that is not exactly `stopped` rendered **Stop** — so an agent that was
paused *and* offline, or paused *and* missing a model, roles or grants, showed
a Stop button and had no way to be started from the roster at all.

That is precisely the set most likely to need starting.

It also inherited `stateFor`'s optimistic default:

```ts
if (!status) return "ready";
```

Before the status poll answers, every live agent reads `ready` — so a stopped
agent showed **Stop** on load and only flipped to Start once the poll landed.
If that request was slow or failed, it never flipped. On the night of
2026-08-17 those requests *were* failing (us-117.1), which is the likeliest
reason the manager saw no Start control at all.

**Found on prod, 2026-08-18.** A paused `Architect` held the only queued `plan`
run in Sandy's Workspace — the only agent in that org carrying the `plan` role,
with Programmer `code`-only and DevOps `test/release/deploy`. The run sat
unclaimed and the manager reported the Team page had no option to start any
agent.

### The fix: read intent, not status

**Status** is what the agent is doing. **Intent** is what the manager last
asked for. Only the second has two answers, and it is the one a Start/Stop
toggle is about.

`agent_slots.desired_state` (`enabled` / `paused`) now drives it, carried to
the roster alongside the seat it already loads. It is known from the first
render, needs no poll, and is independent of presence, model, roles and grants.

The rule lives in `lib/idle-reasons.ts` as `showsStart()` and the component
imports it, rather than restating the expression in JSX — the test then guards
the shipped function instead of a copy of it. (us-117.1 was a lesson in what a
test asserting its own fake is worth: the pool's reset test passed for months
while every reset failed in production.)

## Acceptance criteria

- **AC1 — Start is offered whenever the agent is stopped.** The toggle renders
  Start iff `desired_state === "paused"`, in every one of the nine states.
  Pinned by a test that loops `AGENT_STATES`.
- **AC2 — Stop is offered otherwise**, including while the status is unknown —
  an absent intent is not "stopped".
- **AC3 — no dependence on the status poll.** The control renders correctly on
  first paint, before any `agent_status` call answers.
- **AC4 — the rule is shared, not restated.** `showsStart` is exported from
  `lib/idle-reasons.ts`, imported by the roster, and the test imports the same
  function.
- **AC5 — nothing else moves.** `stateFor`, the State column, the status
  vocabulary and the start/stop API calls are untouched.

## Verification (2026-08-18)

`npm run test:web` 285 pass (+4). `npm run build` clean. `npm run lint`
0 errors.

**Not verified in a browser.** The prod session is not available to me and the
dev workspace's agents have no `agent_slots` rows in the paused state, so the
rendered toggle was not re-checked on screen. The logic is pure and pinned; the
render is one boolean feeding an existing button.

**The prod symptom is separately resolved:** Architect's pause was cleared
directly (`runner_config.paused = false`, slot `desired_state = enabled`) and
it claimed the queued run `a0e72e43` at 02:17:44 UTC — so the queue side is
confirmed working end to end.

## Out of scope

- **`stateFor`'s optimistic "ready" default.** Left as-is: it is a
  no-flicker choice for a *display* cell, self-correcting on the next poll, and
  after this story it no longer gates any action. Changing the vocabulary's
  default would ripple through four surfaces for a transient label.
- **The nine-state vocabulary itself** (us-116.4).
- **Whether Stop should be disabled for an offline agent** — arguable, and a
  separate judgement about what stopping an absent process means.
- **The standing uncleared `runner-fault` incident** on Architect from
  2026-08-17 23:43 (`submit refused (409)`), which may still colour its health.
